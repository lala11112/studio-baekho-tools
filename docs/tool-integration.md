# 도구 통합 안내

이 문서는 개발 중인 **타격감 찾기 자동화**, **모델링 자동화**를 스튜디오 백호툴에 연결할 때 맞출 사용자 경험과 인계 항목을 정리합니다.
공통 앱은 탐색, 작업 상태, 결과 보관을 맡고 각 도구는 기존 화면과 내부 작업 흐름을 유지합니다.
현재 구현이나 지원 여부를 보증하는 문서가 아닙니다. 실제 동작은 도구별 인계 내용과 확인 근거로 판단합니다.

[프로젝트 안내](../README.md) · [UX 원칙](ux-principles.md) · [도구 인계 템플릿](templates/tool-handoff.md)

## 1. 통합의 기준

- 사용자가 도구를 찾고, 작업하고, 결과를 다시 여는 과정을 편하게 만듭니다.
- 기존 도구에 익숙한 사용자가 설정과 작업 순서를 다시 배우지 않게 합니다.
- 공통 메뉴와 작업 문맥은 일관되게 제공하되 도구 내부 화면은 기능에 맞게 유지합니다.
- 고정 단계 마법사나 동일한 패널 구성으로 모든 도구를 다시 설계할 필요는 없습니다.
- 연결 방식, 프레임워크, 실행 API, 저장 형식은 조사 후 결정합니다. 이 문서는 이를 확정하지 않습니다.

## 2. 공통 앱과 도구의 역할

| 영역 | 공통 앱의 책임 | 도구의 책임 |
| --- | --- | --- |
| 탐색 | 전역 메뉴, 도구 진입, 돌아가기 | 내부 탭과 세부 작업 이동 |
| 작업 문맥 | 현재 프로젝트와 도구, 다시 열 위치 표시 | 필요한 입력·설정과 도구 내부 문맥 관리 |
| 진행 상태 | 실행 목록과 눈에 보이는 상태 표시 | 실제 실행 상태와 가능한 제어 범위 제공 |
| 결과 | 결과 목록, 보관 위치, 다시 열 진입점 | 결과의 의미, 미리보기·편집·내보내기 방식 제공 |
| 이어서 작업 | 이전 작업과 초안으로 돌아갈 경로 제공 | 복구 가능한 입력·설정·작업 상태의 범위 설명 |

여기서 역할은 책임 범위입니다. 특정 팀원에게 담당을 배정한 내용은 아닙니다.

## 3. 공통 메뉴와 이동

전역 메뉴는 **홈 / 도구 / 실행 / 결과 / 설정**을 사용합니다.

| 메뉴 | 사용자가 하려는 일 |
| --- | --- |
| 홈 | 최근 작업과 결과를 보고 이어서 작업하기 |
| 도구 | 필요한 도구를 찾고 작업공간 열기 |
| 실행 | 진행 중이거나 끝난 실행의 상태와 다음 행동 확인하기 |
| 결과 | 결과를 찾아 다시 열고 검토·보관하기 |
| 설정 | 공통 환경과 연결 상태 확인하기 |

큰 흐름은 **도구 선택 → 도구 작업공간 → 결과 확인·보관 → 이어서 작업**입니다.
이는 사용자가 길을 잃지 않게 하는 이동 구조이며, 도구 내부 작업을 네 단계로 고정하는 요구가 아닙니다.
작업공간에서는 현재 프로젝트와 도구를 알아볼 수 있어야 하며, 돌아갈 위치가 명확해야 합니다.
실행 목록에서 작업을 열거나 결과에서 원래 작업으로 돌아올 때 관련 문맥도 함께 복원합니다.

## 4. 기존 도구를 연결하는 순서

1. 현재 실행 방법, 화면, 입력·출력, 저장 위치와 제약을 인계 템플릿에 기록합니다.
2. 기존 UI에서 유지할 부분과 공통 앱이 제공할 탐색·상태·결과 연결점을 정합니다.
3. 도구 진입과 돌아가기, 작업·결과 다시 열기부터 연결합니다.
4. 실제 지원되는 상태 표시와 제어 기능을 연결하고 확인 근거를 남깁니다.
5. 부족한 기능은 사용자 영향이 작은 개선 항목으로 나누어 추적합니다.

독립 실행 중인 도구는 전환 기간에 기존 화면으로 여는 링크를 사용할 수 있습니다.
가능하다면 프로젝트·작업 문맥을 전달하는 딥링크와 공통 앱으로 돌아오는 경로를 함께 제공합니다.
문맥 전달이나 복귀가 아직 안 되면 사용자가 무엇을 다시 선택해야 하는지 먼저 안내합니다.
최종 방향은 공통 앱 안에서 탐색·상태·결과 보관을 이어 사용하는 것입니다. 외부 링크 연결은 전환 단계입니다.
도구별 통합 방식은 제약을 보고 정하며, iframe이나 특정 화면 삽입 방식을 필수로 요구하지 않습니다.

## 5. 인계할 개념 정보

아래 항목은 화면과 책임을 맞추기 위한 개념 수준의 정보입니다.
실행 가능한 스키마나 API 명세가 아니며, 실제 이름·표현·전달 방식은 통합 과정에서 합의합니다.

### 도구 목록에 필요한 정보

| 항목 | 필요한 이유 |
| --- | --- |
| 도구 식별 정보·표시 이름·설명 | 사용자가 같은 도구를 일관되게 찾기 |
| 진입 위치·현재 실행 방법 | 기존 작업공간을 정확히 열기 |
| 필요한 프로젝트 문맥·입력 | 시작 전에 준비할 내용을 알기 |
| 이용 조건·의존 항목 | 연결·권한·설치 문제를 설명하기 |
| 기능별 지원 상태·확인 근거 | 가능한 행동과 제약을 사실대로 표시하기 |
| 인계 책임 역할·확인 시점 | 변경 사항을 확인할 경로 남기기 |

### 작업 화면에 필요한 정보

| 항목 | 필요한 이유 |
| --- | --- |
| 작업 식별 정보·이름·도구·프로젝트 | 어느 작업의 상태인지 구분하기 |
| 입력·설정·초안의 보존 범위 | 다시 열었을 때 복원되는 내용을 알기 |
| 실행 상태·상태 확인 시점 | 현재 진행 상황과 정보의 신선도를 알기 |
| 진행 설명·중단 또는 실패 이유 | 기다릴지 수정할지 판단하기 |
| 가능한 행동·제약 | 실행·취소·재시도 등의 사용 가능 여부 설명하기 |
| 다시 열 위치·연결된 결과 | 다음 방문에서 이어서 작업하기 |

### 결과 화면에 필요한 정보

| 항목 | 필요한 이유 |
| --- | --- |
| 결과 식별 정보·이름·생성 작업 | 결과의 출처를 알기 |
| 생성 시점·버전 구분 정보 | 여러 결과를 혼동하지 않기 |
| 결과 위치·다시 열 참조·접근 조건 | 다음 방문에도 같은 결과를 찾기 |
| 미리보기·원본 열기 등 지원 행동 | 해당 결과에 맞는 확인 방법 제공하기 |
| 검토 상태·보관 상태 | 검토 여부와 저장 여부를 별도로 알기 |
| 적용 대상·적용 가능 여부 | 어디에 반영되는지 알고 실행하기 |

결과 다시 열기에는 일시적인 화면 주소만 의존하지 않는 안정적인 참조가 필요합니다.
결과가 이동·삭제되었거나 접근할 수 없으면 이유와 복구 또는 위치 재지정 방법을 표시합니다.
저장 방식과 파일 형식은 도구별 사실을 기록하며 공통 형식으로 단정하지 않습니다.

## 6. 상태와 버튼의 의미

실행 상태와 검토 상태는 분리합니다. **실행 완료**는 처리가 끝났다는 뜻이며, 결과가 검토되거나 채택되었다는 뜻은 아닙니다.
예를 들어 실행은 완료되어도 결과는 검토 전일 수 있습니다. 검토·보관·적용 여부를 실행 성공 하나로 묶지 않습니다.
실행 상태의 세부 단계는 실제 도구 동작에 맞추고, 진행률을 알 수 없으면 수치를 만들어 표시하지 않습니다.

| 행동 | 공통 의미와 도구가 알려줄 내용 |
| --- | --- |
| 실행 | 현재 입력과 설정으로 처리를 시작합니다. 실행 조건과 필요한 준비를 보여줍니다. |
| 취소 | 진행 중인 처리를 중단하도록 요청합니다. 실제 중단 가능 여부와 남는 결과·초안을 설명합니다. |
| 재시도 | 실패·중단한 처리를 다시 시작합니다. 처음부터인지, 이어서인지와 재사용 입력을 설명합니다. |
| 보관 | 결과를 나중에 찾아 열 수 있게 저장·등록합니다. 위치와 보존 범위를 보여줍니다. |
| 적용 | 선택한 결과를 지정한 대상에 반영합니다. 대상과 변경 내용을 실행 전에 보여줍니다. |

취소 요청만 접수된 상태를 취소 완료로 표시하지 않습니다.
결과 보관만으로 적용한 것으로 처리하지 않으며, 적용을 지원하지 않는 도구에는 그 이유를 표시합니다.
접근 불가·조건 미충족·미지원 기능은 사용할 수 있는 것처럼 보이지 않게 하고, 비활성 이유와 가능한 다음 행동을 가까이 표시합니다.

## 7. 화면을 떠나도 이어서 작업하기

목표는 이동 후에도 작업 상태를 확인하고 입력과 결과를 잃지 않는 경험입니다.
다만 모든 도구가 화면 밖이나 앱 종료 후에 실행을 계속할 수 있다고 가정하지 않습니다.

- 도구별로 화면 이동, 도구 화면 닫기, 앱 종료 시 실행 지속 여부를 각각 기록합니다.
- 이동하면 실행이 멈추거나 입력을 잃는 경우, 이동 전에 영향과 선택 가능한 행동을 안내합니다.
- 실행 지속이 어려우면 복원 가능한 입력·설정의 초안 보존을 우선 마련하고, 복원하지 못하는 항목도 알립니다.
- 실행 이어받기와 저장된 입력으로 새 실행 시작하기를 구분합니다.
- 저장 실패나 복원 불가를 숨기지 않으며, 실제 보존된 시점과 범위를 표시합니다.
- 부족한 기능은 영향·현재 대안·개선 범위·확인 조건을 적어 작은 개선 항목으로 남깁니다.

## 8. 지원 상태와 확인 기준

기능별 지원 상태는 다음 네 값만 사용합니다. 실제 시험 결과와는 별도 항목입니다.

| 값 | 의미 |
| --- | --- |
| `supported` | 현재 제공하는 기능이며 확인 근거를 함께 기록함 |
| `planned` | 구현 예정으로 합의했으며 현재 사용 가능하다는 뜻은 아님 |
| `unsupported` | 현재 지원하지 않으며 제약과 대안을 설명함 |
| `unconfirmed` | 조사·검증 전이어서 지원 여부를 판단할 수 없음 |

실행·취소·재시도, 초안 보존·복원, 이동 후 실행 지속, 상태 조회, 결과 다시 열기, 보관·적용을 기능별로 기록합니다.
`supported`라고 적을 때는 구현 위치나 담당 역할의 확인 등 근거를 남깁니다.
“실행해 확인함” 또는 “테스트 통과”는 재현 단계, 환경, 날짜, 관찰 결과가 있을 때만 기록합니다.
문서 검토나 화면 목업만 확인한 경우에는 그 범위를 명시하며 실제 실행 검증으로 취급하지 않습니다.

인계 전에는 [템플릿](templates/tool-handoff.md)을 채우고 진입·돌아가기, 문맥 보존, 상태 표시, 결과 다시 열기에서 확인된 범위와 미확인 범위를 함께 검토합니다.
