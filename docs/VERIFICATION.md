## 0.6.3 — 실제 Google 버튼의 인증 경로 누락 수정

- **증상·확정 원인:** 0.6.2에서 Google 버튼이 로딩 상태로 멈췄습니다. 사용자가 `BLOCKED_NAVIGATION · chatgpt.com /auth/[redacted]` 진단을 전달했고, 별도 새 Electron 프로필의 실제 ChatGPT 공개 화면에서도 같은 오류를 재현했습니다. 실제 Google 링크는 `/auth/login_with`로 이동하는데 기존 허용 목록에 이 경로가 빠져 있었습니다. 0.6.2의 모의 팝업 검사만으로는 실제 버튼 경로 누락을 발견하지 못했습니다.
- **수정 범위:** 정확한 `/auth/login_with`만 사람의 인증 이동에 허용하고 공개 경로명 진단에 추가했습니다. 하위·유사 경로와 잘못된 호스트·프로토콜·사용자 정보·포트는 차단하며, 작업자의 `isChatGptUrl`은 넓히지 않았습니다. 추적하는 창의 실제 로그인 시작 요청 결과만 관찰해 HTTP/네트워크 실패를 표시합니다. 세션 조회의 정상적인 미로그인 401과 다른 창의 요청은 제외하며 요청·본문·헤더·쿼리·토큰을 수집하거나 재전송하지 않습니다.
- **실제 웹 재검사:** 수정 후 `/auth/login_with` 문서 HTTP 200과 이동 통과를 확인했습니다. 이후 같은 격리 프로필에서 ChatGPT 페이지가 보낸 로그인 요청 `/api/auth/signin/[redacted]`는 HTTP 403을 반환했습니다. 따라서 앱의 경로 차단은 해결했지만 Google 계정 입력 화면 도착이나 실제 로그인 완료는 확인하지 못했습니다. 이 403의 원인과 사용자 기존 세션에서의 재현 여부는 미확정이며, Google의 `disallowed_useragent`라고 단정하지 않습니다. 계정 입력·쿠키 복사·사용자 에이전트 변경·이미지 생성·유료 요청 0회. `artifacts/chatgpt-login-route-live.json`에 제한된 증거를 기록했습니다.
- **주요 파일:** `electron/chatgpt-policy.ts`, `electron/chatgpt-browser.ts`, `tests/chatgpt-policy.test.ts`, `scripts/chatgpt-auth-smoke.mjs`. 별도 실행 파일은 `release/0.6.3/win-unpacked/Partsmith.exe`이며 기존 사용자 앱·프로젝트·로그인 저장소를 수정하거나 재시작하지 않습니다.
- **검사·패키지:** 정책 **12/12**, 오프라인 실제 Electron 인증 **13개**와 기존 원본 다운로드·중복 제출 **9개** 통과. 새 검사는 정확한 경로의 같은 창 이동·리디렉션, 로그인 요청 HTTP 403/네트워크 실패, 관련 없는 세션 401/다른 창 제외, 정상적인 취소 요청 제외를 확인했습니다. 실제 HTTP 실패로 생성 요청을 재시도하지 않습니다. TypeScript·Vite·Electron 빌드와 최종 0.6.3 EXE의 버전·SQLite·미로그인 사전 차단·재연결 버튼·Codex 연결 조회 통과. 새 이미지·유료 요청은 0회이며 기존 큰 번들 경고는 유지됩니다. 실제 계정 로그인 완료와 사용자 환경의 후속 403 여부는 확인 대기입니다.

## 0.6.2 — ChatGPT Google 인증 팝업·진단·재연결

- **증상·확인한 결함:** 사용자는 Google 로그인 버튼을 눌러도 창이 나타나지 않는다고 보고했습니다. 기존 인증 팝업의 추가 창 열기 처리가 항상 `deny`였고, 최초 페이지 로딩 실패 후에는 기존 창을 다시 보여주기만 했습니다. 두 코드 결함을 수정했지만 사용자 환경의 실제 차단 원인과 로그인 성공은 아직 확인하지 않았습니다.
- **변경:** 메인·인증·추가 인증 창에 같은 주소 검사와 세션을 적용합니다. 임시 `about:blank`를 허용하되 이후 이동을 검사하고 빈 창/로딩 대기를 30초로 제한합니다. 차단·로딩 실패·렌더러 종료를 진단하며 호스트·공개 경로·오류 코드만 표시합니다. 쿼리·fragment·인증 값과 알 수 없는 경로 구간은 남기지 않습니다. 실제 `disallowed_useragent` URL/페이지가 확인되면 내장 방식 미지원으로 표시합니다.
- **화면·보존:** 로딩·로그인 대기·연결 준비됨·실패와 명시적인 다시 연결을 추가했습니다. 인증 중 상태를 제한된 간격으로 조회하고 완료/창 닫기/10분 경과 후 중단합니다. 상태 확인은 작업자의 화면 컨트롤 ID를 바꾸지 않습니다. 재연결 중 이전 상태 조회가 늦게 도착해 준비됨을 표시하는 경합을 막았습니다. 작업자·다운로드가 실행 중이면 재연결을 거부하며, 기존 제출 기록과 대화는 보존합니다. 로그인 후 생성·복구·다음 단계는 자동 실행하지 않습니다.
- **주요 파일:** `electron/chatgpt-browser.ts`, `electron/chatgpt-policy.ts`, `electron/main.ts`, `shared/types.ts`, `src/AssetWorkbench.tsx`, `src/workbench.css`, `tests/chatgpt-policy.test.ts`, 새 `scripts/chatgpt-auth-smoke.mjs`와 관련 회귀 스크립트.
- **검사:** 기존 전체 단위·회귀 **222/222**, 추가 인증 정책을 포함한 해당 파일 **10/10**(기존 7개 + 신규 3개) 통과. 최종 TypeScript·Vite·Electron 빌드 통과. 기존 큰 번들 경고는 남아 있습니다. 실제 Electron의 격리된 로컬 페이지로 인증 **9개**, 원본 다운로드·중복 제출 방지 **9개** 통과. HTTPS 인증 페이지는 시험 세션에서 가로채 제공했으며 실제 Google 인증 서버나 계정을 사용하지 않았습니다. 테스트 자체의 팝업 반환값 직렬화와 HTTP keepalive 종료 처리를 수정한 뒤 통과했습니다.
- **인증 검사 범위:** Google/추가 팝업, 부모·자식 세션 일치, 임시 빈 창 이동, 부모로 복귀, 차단 주소 진단, Google 거부 문구, 빈 창 시간 초과, 첫 로딩 실패 후 재연결, 활성 작업 중 재연결 거부를 확인했습니다. 상태 조회 후에도 기존 컨트롤 ID로 작업할 수 있고 원본 바이트·해시·한 번 제출 기록이 유지됩니다. 보고서: `artifacts/chatgpt-auth-smoke.json`, `artifacts/chatgpt-browser-smoke.json`.

- **남은 확인:** 사용자가 새 앱에서 직접 Google 로그인을 마치고 준비됨으로 바뀌는지 확인해야 합니다. 모의 검사만으로 로그인 성공을 선언하지 않습니다. Google의 내장 브라우저 거부는 위장·쿠키 복사로 우회하지 않으며 외부 브라우저 연결은 별도 변경입니다. 새 이미지 생성·Tripo 유료 요청 0회, 실제 제작 종단 품질은 미검증입니다.

## 0.6.1 — 생성 개수·선택형 분리·내부 도구 권한 오류 수정

- **요청·동작:** 컨셉 이미지, 분리 후보 세트, 신규 3D 모델 개수를 1–16 범위에서 설정합니다. 앱의 요청 한도이며 서비스의 지원 개수로 간주하지 않습니다. 새 프로젝트는 선택한 전체 이미지로 바로 모델링합니다. 파츠 분리를 선택하면 정면만 분리하거나 정면을 기준으로 후면·좌·우를 추가합니다. 결과 선택·채택은 계속 사용자가 합니다. 분리 세트 수 × 세 파츠 × 선택 방향 수를 표시하며, 동작 참조는 키포즈 개수로 조절합니다.
- **후속 단계·보존:** 전체 모델과 파츠 모델의 입력·의존 관계를 분리해 UV·텍스처·Astra 조립까지 연결했습니다. 조립은 채택한 텍스처의 전체/파츠 경로를 고정합니다. N개 후보에서 선택한 기준 결과로만 수정하며 파츠·방향·개수·원본·이전 버전을 보존합니다. 분리 후보 세트마다 제출/체크포인트 ID를 구분하고 복구 시 재전송하지 않습니다. 기존 모델 리롤은 Mesh Edit 결과 1개로 유지합니다.
- **Tripo 생성:** 사용자가 고른 개수를 실제 Studio 기본 생성 개수 UI에서 확인하고 한 번의 승인된 제출로 요청합니다. 없는 옵션을 임의로 줄이거나 여러 Generate 호출로 대체하지 않습니다. 후보별 실제 다운로드·중복·파일 검사는 유지합니다. Studio 관찰에는 실제 선택 상태와 일반 입력값도 포함합니다. 실제 계정의 개수·비용·결과는 이번에 유료 생성으로 검증하지 않았습니다.
- **오류 원인·수정:** `approval_policy="never"`인 비대화형 Codex 작업자에게 내부 MCP 도구별 실행 승인이 전달되지 않아 Studio 상태·다운로드 조회까지 차단됐습니다. 앱 소유 Studio/ChatGPT 도구 목록에만 자식 실행 인자 `approval_mode="approve"`를 지정합니다. 전역 승인 정책·workspace-write·사용자 MCP 설정을 바꾸지 않고, 호스트의 예산·인증·경로·중복 제출 방지를 유지합니다. 실제 MCP 승인 거부가 발생하면 작업자를 즉시 중단해 로그를 거듭 읽는 복구를 막습니다. 제출 불명확 기록을 오류 문구만 보고 해제하지 않으며, 외부 사이트 미제출 확인 버튼은 사용자 확인 후에만 동작하고 실제 제출 영수증이 있으면 거부합니다.
- **주요 파일:** `shared/workbench.ts`, `engine/workbench.ts`, `engine/workbench-executor.ts`, `src/AssetWorkbench.tsx`, `src/workbench.css`, `engine/codex-worker.ts`, `electron/studio-browser.ts`, `electron/chatgpt-browser.ts`, 새 `electron/worker-tool-policy.ts`, 회귀 검사와 `scripts/worker-permissions-smoke.ts`.

2026-10-08 사용자가 `HTTP 401 / code 2`를 보고했습니다. 초기 앱은 중국용 `https://openapi.tripo3d.com/v3`를 고정 사용했습니다. 공식 [국제 API 소개](https://developers.tripo3d.ai/en/docs/introduction)의 국제 주소는 `https://openapi.tripo3d.ai/v3`입니다. 0.1.1에서 국제 주소를 기본으로 수정하고 연결 지역 선택, 지역 불일치 오류 안내, 구버전 설정 보존 마이그레이션을 추가했습니다. 지역별 호스트·자동 재시도 없음·설정 이관을 포함해 엔진 테스트 10/10이 통과했습니다. 새 실행 파일은 `release/0.1.1/win-unpacked/Partsmith.exe`이며, 실행 중인 기존 앱 파일을 덮어쓰지 않고 별도로 패키징했습니다.

공식 [오류 표](https://developers.tripo3d.ai/en/docs/error-handling)에 따르면 HTTP 401은 인증 문제이며, 크레딧 부족은 `2010`입니다. `code 2`는 공개 v3 표에 없어 개별 의미를 추정하지 않았습니다. 수정 후 기존 DPAPI 저장 키를 앱 프로세스 안에서만 사용해 국제 서버 `GET /v3/account/balance` 인증 성공을 실제 확인했습니다. 당시 응답 잔액과 예약 크레딧은 모두 0이었습니다. 키는 출력하거나 다른 파일로 복사하지 않았으며 유료 요청을 보내지 않았습니다.

**실제 Tripo 인증·잔액 조회: 성공. 실제 유료 생성: 미검증.** 키를 채팅으로 받거나 코드에 넣지 않았습니다. 계정별 지원 모델, 가격, 이미지 생성·수정, 파츠 3D 생성, 자동 리깅·리타게팅의 성공 여부는 API 크레딧 충전과 사용자 비용 승인 후 별도로 검증해야 합니다. 현재 목록은 공식 endpoint 문서 기반이며 계정 사용 가능 여부를 보증하지 않습니다. 예상 비용을 확인할 수 없으면 숫자를 만들지 않고 별도 승인을 받습니다.

- 0.2.0에서 Tripo 원격 분할·보완·리토폴로지·텍스처·UV 패킹 요청 경로를 추가했습니다. 실제 계정의 유료 처리 성공·품질은 미검증입니다. 기존 수동 crop·마스크는 별도 기능입니다.
- Blender 조립은 상대 배치와 목표 키 정규화입니다. 로컬 표면 용접·리토폴로지·UV 재생성은 구현하지 않습니다. 메시 변경 뒤 텍스처 처리는 사용자가 별도 Tripo 요청으로 승인합니다.
- Tripo의 기본 동작은 각각 별도 결과 후보입니다. 서로 다른 리타게팅 결과를 하나의 다중 클립 캐릭터에 자동 병합하는 기능은 없습니다. Blender에서 수동으로 병합한 GLB를 가져올 수 있습니다.
- 실제 복잡한 캐릭터의 헤어 연결·관절 웨이트·접합부·PBR 맵 정확성은 육안 검수해야 합니다. 로컬 데모 재질은 색상 중심이며 실제 API 텍스처 세트를 검증하지 않았습니다.
- 원격 취소 API를 확인하지 못해 앱의 중지는 추적 중지로 표시합니다. 모호한 제출은 기존 작업 ID를 확인해 연결하며 자동으로 재과금하지 않습니다.
- Unity가 닫혀 있거나 컴파일 중이면 요청이 대기합니다. 미저장 씬이 있으면 자동 Play Mode 검사를 건너뜁니다.
- 코드 서명·자동 업데이트·설치 프로그램은 포함하지 않습니다. npm audit에 moderate 개발 의존성 항목이 남아 있으며 제품 배포 전 재검토가 필요합니다.
