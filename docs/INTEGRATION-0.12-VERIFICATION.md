검증일: 2026-10-22, Windows 로컬 환경.

## 충돌과 연결 보완

- 최신 3D의 제작 시작·이어하기·설정 복귀 흐름을 유지하면서 `AppProps`, 공통 메뉴 탐색과 embedded toolbar를 다시 적용했다. `electron/main.ts`에는 최신 미리보기·외부 리그·Unity 대상 검증과 기존 통합 호스트를 함께 유지했다.
- 통합 앱의 appId, productName과 저장 경로를 유지하고 통합 버전을 0.12.0으로 갱신했다. lockfile은 통합 의존성을 기준으로 재생성했다.
- 지도 창은 같은 공유 `window-service`를 standalone/integrated 경로에서 사용한다. 새 Unity·컨셉 핸들러를 공유 서비스에 반영하고 integrated preload는 `map-forge:`로 분리했다. 모든 핸들러는 기존 창·메인 프레임 검증을 거친다.
- 새 Unity 서비스의 설정·원장은 `<격리 프로필>/map-forge/unity`에 둔다. 창 재열기는 새 서비스 인스턴스를 만들며, 창·앱 종료에서는 transport 정리를 수행한다. 호스트는 지도 서비스의 비동기 종료도 기다린다.
- Unity importer와 벽 프리팹 안내를 asar 밖 `resources/map-forge/unity-importer`에 포함했다. 개발·패키지 경로를 각각 검증했다.
- MCP SDK 1.32.1은 기존 루트 Zod 4.6.5와 함께 번들된다. SDK의 peer 범위는 Zod 3.25 또는 4를 허용한다. esbuild metafile에서 SDK/Zod 입력 131개와 외부 패키지 누락 0개를 확인했다. 기존 루트 Zod API를 다른 major로 바꾸지 않았다.
- 기존 UI 회귀 검사에서 접힌 목록·상세 설정, 주/보조 실행 버튼, 사용/다음 설정 문구와 입력 소유권 조건을 반영했다. 검사는 실제 disclosure를 열고 상호작용하며 force click을 사용하지 않는다. 원본·채택 상태 보존, 승인 전 실행 금지, 중복 방향과 다른 파트 차단 검증은 유지했다.
- Windows CI에 지도 테스트와 빌드 후 통합 화면·MCP transport 검사를 추가했다. 루트 테스트는 기존 열린 핸들의 영향을 피하도록 Node의 test-force-exit를 사용하며 테스트 자체를 제외하지 않는다.

## 설계 검토와 한계

핵심 통합 결정만 2,692자 텍스트로 기존 Claude 구독 브리지에 검토받았다. 응답 메타데이터의 모델은 `claude-opus-5-5`, 요청 CLI effort는 `max`다. 일반 headless 응답은 서버에 실제 적용된 effort를 별도로 증명하지 않는다. Codex가 저장소 조사·충돌 해결·수정·모든 검사를 수행했다. 세션/IPC 격리, 공유 서비스 수명, 패키지 경로, 의존성 번들과 소스 차이 확인을 반영했다.

실제 Blender 제작·리깅, Unity Editor C# 컴파일·게임 씬·Play Mode, 유료 AI/Tripo/fal 생성과 음악 품질은 이번 통합 검증에서 실행하지 않았다. 폴더 패키지는 서명된 설치 프로그램이 아니며 전체 `win-unpacked` 폴더가 필요하다.

저장소가 지정한 Notion 개발 기록 페이지를 현재 연결로 읽었으나 `404/object_not_found`였다. Notion에는 게시하지 못했다. 이 문서를 미게시 개발 기록으로 보존한다. 기존 인증과 다른 설정은 변경하지 않았다.
