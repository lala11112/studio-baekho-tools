# 새 오브젝트 추가와 원본 메시 검사 — preview.12

2026-10-13. 이번 변경은 기존 `새 오브젝트 추가 → 대상별 이미지 설정` 흐름의 가독성과 모델 검사 개선이다. 이미지 단계에 모든 대상 분류를 다시 펼치거나 제작 엔진을 교체하지 않는다.

## 사용 흐름

1. 왼쪽 목록 상단의 **＋ 새 오브젝트**를 누른다. 빈 프로젝트 중앙 버튼도 같은 창을 연다.
2. 넓은 중앙 창에서 **분류 → 세부 대상 → 이름**을 선택한다. 이미지 생성은 이 단계에서 실행하지 않는다.
3. **오브젝트 만들기**를 누르면 새 대상의 이미지 단계로 이동한다. 기존 대상의 결과는 남는다.
4. 모델 단계에서 **제작 도구·모델 / 쿼드·삼각형 / 목표 면 수**를 설정한다. 숫자 입력과 100면 간격 슬라이더가 같은 값을 사용한다.
5. 모델 미리보기의 **메시 선 ON → 원본 면 선**으로 실제 원본 면 경계를 확인한다. **게임용 삼각형 선**은 면 내부의 삼각분할까지 보여준다.

생성창은 최대 960px이며 하단 취소·만들기 버튼은 고정된다. 취소하면 기존 단계와 미저장 설정, 같은 프로젝트의 생성 초안을 유지한다. 생성 중에는 입력과 중복 제출을 막고 실패하면 입력과 오류를 창 안에 남긴다. 키보드 포커스를 창 안에 유지하고 취소 시 진입 버튼으로 돌려준다.

## 모델 설정 계약

| 모델 | 쿼드 | 삼각형 | 새 대상·파츠 기본 |
|---|---|---|---|
| Smart Mesh P2.0 | 1,000–25,000면 | 1,000–50,000면 | 5,000면·쿼드 |
| Smart Mesh P1.0 | 지원하지 않음 | 1,000–20,000면 | 5,000면·삼각형 |

다른 제작 경로에도 해당 경로의 입력 한도를 적용한다. Blender 프리셋의 면 수는 상한이며, Astra의 수치와 토폴로지는 제작 목표다. 입력 한도나 선택 버튼이 정확한 결과 달성을 보장하지 않는다.

저장된 기존 수치는 화면을 여는 것만으로 변경하지 않는다. 모델이나 토폴로지를 직접 바꿔 한도를 넘으면 조정값을 알린다. 선택 해제는 저장되며, 미선택·유효하지 않은 설정은 실제 작업 준비 전에 차단된다. UI와 준비·비용 요청은 같은 검증 함수를 쓴다. 과거 결과의 제작 모델·목표·토폴로지는 해당 결과의 생성 기록에서 읽는다.

## 원본 면 선의 근거와 한계

- 원본 `.blend` 또는 FBX를 읽기 전용으로 다루고 로컬 검사 사본만 만든다. 제작 버전이나 채택 기록을 추가하지 않는다.
- Blender 내보내기에 원본 정점·면 ID를 실어 UV 경계와 재질 분할을 넘어 실제 원본 변을 대응시킨다. 삼각형 두 개를 임의로 사각형처럼 합치지 않는다.
- 원본·기존 미리보기·등록 텍스처·검사 GLB·대응표·변환 코드 해시를 연결한다. 캐시 재사용과 파일 제공에서도 해시를 다시 검사한다.
- 대응된 변의 위치는 표시 중인 메시의 모프와 스킨 변형을 적용해 갱신한다.
- 대응이나 지원 여부를 검증하지 못하면 이유를 표시하고 게임용 삼각형 보기로 남긴다. 지원하지 않는 변형자나 등록되지 않은 외부 자료를 조용히 생략하지 않는다.
- 원본 면 보기는 재토폴로지 기능이 아니다. 기존 토끼의 원본은 5,387면(사각형 4,579개·삼각형 808개), 게임용 9,966삼각형으로 확인된 혼합 메시다.

검사 사본은 프로젝트의 `graphics/inspection/native-topology`에 저장하고 저장 공간 현황에서 원본과 구분한다. 창 열기·선택·검사·크기 표시에는 GPT나 유료 서비스 요청이 없다.

## 검증 기록

- 실제 Electron 검사: 생성·취소·오류·중복 클릭·초안·포커스·기존 설정과 기록 보존.
- 면 수 검사: 신규 기본값, 저장값 보존, 해제 후 실행 차단, 모델별 한도, 파츠별 적용과 실제 준비·견적 경계.
- 실제 Blender 검사: 사각면, 혼합 면, UV·재질 경계, 리그·모프·애니메이션, 해시 변조 거부, FBX 원본 폴더 보존.
- 전체 회귀 실행은 649개 중 638개 통과·10개 생략·새 슬라이더 폭 검사 1개 실패였다. range 기본 여백 2px를 제거한 뒤 해당 UI 검사를 재실행해 통과했다.
- 별도 배포본에서 1920·1280·960·800px × 100·125·150%의 12가지 창/배율 조합을 통과했다. 생성창과 하단 버튼의 경계, 문서 가로 넘침, 새 건물 생성, 설정 저장, 재시작 보존을 확인했다. 이는 앱 배율 검사이며 Windows 디스플레이 배율을 12번 변경한 검사는 아니다. 실제 사용자 환경의 Windows 150%에서도 확인했다.
- 실제 토끼 원본에서 긴 Windows 경로의 `WinError 206`을 발견해 짧은 Temp 작업 공간으로 수정했다. 260자 초과 입력·400자 초과 캐시 경로 검사 및 같은 토끼 변환을 통과했다.
- 최종 preview.12를 실제 앱으로 열어 생성창 960px, 토끼 원본 면 선과 28개 뼈대 동시 표시를 확인했다. 기존 작업 공간과 13개 버전·42개 등록 파일 SHA가 그대로이며 새 제작 작업·유료 제출은 0회, 화면 오류는 0개다.
- 배포본·실제 앱 확인 결과: `artifacts/runtime/graphics-preview12-package.json`, `graphics-preview12-live.json`. 새 검사 사본은 로컬 캐시에만 추가됐다.

새 유료 생성과 제작용 GPT 작업은 실행하지 않는다. 배포본 폴더 전체를 유지하며 기존 제작 파일·채택·비용 장부는 보존한다.
