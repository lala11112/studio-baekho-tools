# Unity PC 개정 계약과 구현 상태

2026-10-13 · 0.7.0-preview.2 · 기존 00–03 초안을 보완하는 승인된 개정. 제품 전체 완료 보고가 아니다.

## API 전환 추가 구현 및 실제 검증

- 개발 한도: Tripo 최대 300크레딧, fal 추가 사용 없음. 실제 API 잔액 1,000 → 860, 사용 140(모델 100 + Smart UV 20 + HD 텍스처 20). 각 유료 단계는 실제 앱의 비용 카드로 승인했고 반복 제출하지 않았다.
- 이전에 실제 네이티브로 생성한 대검 PNG를 별도 검증 오브젝트에 가져왔다. 이미지 재생성 없이 앱 버튼 M01 → T01 → T03 → X04 → X05를 완료했다. 네이티브 FBX와 텍스처, 편집 가능한 .blend, Unity 프리팹을 보존한다.
- 최종 대검에는 6,438정점, 9,628삼각형, UV 1개와 4096×4096 텍스처 3개가 있다. 5,000쿼드 목표가 모든 후처리에서도 5,000폴리곤으로 유지된다고 표시하지 않는다.
- 실제 Unity 6000.3.21f1 URP 프로젝트에 가져왔다. 기존 파일 250개와 씬 8개의 해시, 씬 설정이 유지됐다. Play Mode는 실행하지 않았다.
- 같은 대검으로 앱 M05 → 실제 gpt-6-astra → Blender 보정을 완료했다. 칼날 146정점의 폭을 5% 넓혔고 정점 수·토폴로지·UV·재질·4096 원본 맵을 유지했다. 수정본은 별도 버전이며 원본을 덮어쓰지 않았다.
- M05 실제 기록은 입력 543,732 / 캐시 입력 487,936 / 출력 4,698토큰이다. 이 수치는 앱 작업자만의 네이티브 기록이며 개발 대화의 사용량, 계정 잔여율 또는 비용 절감률로 환산하지 않는다. API 제출·대기·다운로드·로컬 출력·Unity 전달에는 GPT 요청이 없었다.
- 프로젝트 한도는 취소·제출 불명확 작업의 승인액도 보수적으로 합산한다. 비용 대기·취소·재시작은 작업자를 자동 실행하지 않는다. 복구는 원래 원격 ID/실행 기록을 요구하고 첫 제출을 대신 실행하지 않는다.
- 새 연결: I05 색/스타일 변형, I06 참조 장비, I07 선택 방향별 독립 이미지. N01은 채택 모델/리그에서 2048px 측면 두 장을 로컬 렌더하고 N02는 채택 측면 PNG로 Runway 720p 영상을 만든다. R01–R03과 N04–N06은 Astra 어댑터로 연결하고 뼈·웨이트·변형·클립을 실제 Blender에서 검사한다.
- N06은 원래 애니메이션과 영상 참조를 보존한다. 나중에 채택한 다른 리그/영상을 몰래 섞지 않는다. 외부 .blend 동작은 정확한 Action 이름의 슬롯으로 가져온다. 입력 Action이 없으면 GPT 실행 전에 멈춘다.
- 별도 리그와 여러 클립은 바인드/뼈/회전 방식/FPS가 일치할 때 로컬 합성 후 Unity로 전달한다. 원본을 바꾸지 않으며 제약·드라이버나 미지원 별도 재질 버전은 이유를 표시한다.
- 실제 검사에서 Blender 5 GLB 원본 유지 옵션이 외부 URI와 작은 대체 이미지를 내보내는 문제를 확인했다. 자가 포함 GLB로 출력하고, 동일 채널 이미지에는 packed 원본 바이트를 유지하며 필요한 ORM 합성만 수행한다. 이전 결과는 그대로 보존하고 새 로컬 X04 버전으로 수정했다.
- Unity에서는 금속 맵 누락·일반 이미지로 처리된 노멀 맵·잘못된 기본 색 계수를 수정했다. Blender 노드 근거로 역할 명세를 고정하고 원본 4K 맵 3개를 보존한 채 Unity용 금속 R/매끄러움 A 이미지를 별도로 만든다. 실제 대검의 16,777,216픽셀 대조 불일치 0, 실제 URP 재질 GUID/키워드/색 계수/노멀 importer/선형 맵/4096 해상도 검사 통과. 임의 노드 그래프는 정확히 변환한 것처럼 표시하지 않는다.
- 수정본의 실제 Unity 재전달에서 Generated 프리팹 GUID와 기존 250파일·8씬을 유지했다. 최초 갱신 전 User 프리팹 바이트는 별도 스냅샷이 없어 미측정이다. 이후 동일 입력을 앱에서 다시 전달한 검사에서는 같은 전달 ID를 재사용했고 Generated/User 23파일과 GUID 불변, 추가 staging/receipt/API/GPT 요청 0을 확인했다. Play Mode와 Unity 렌더의 시각적 일치 검사는 하지 않았다.
- API 성공부터 앱 등록 사이에 파일이 변경되면 원본 해시를 새 해시로 바꿔 등록하지 않도록 수정했다. 고정 요청·원격 ID·원본/미리보기 체크포인트를 등록 직전에 검사하고 후보 묶음 전체를 보류한다. 이미 등록한 결과와 원격 작업은 유지한다.
- 최종 전체 검사 443통과·6제외, 이후 해시 등록 경계 관련 68개 회귀 검사와 뷰어 검사 통과. 실제 Blender GLB/재질 검사와 실제 앱/API/Unity 검증은 별도 증거다. TypeScript·별도 0.7.0-preview.2 패키지와 실제 배포본 2회 재시작 통과, 추가 유료/GPT 요청 0. 원본 좌표를 바꾸지 않고 미리보기 카메라·바닥·금속 조명도 정리했다.

현재 실행 경로는 27개(로컬 7개 + 서비스/AI 20개), 미구현은 89개다. 서비스/AI 중 실제 앱 생산을 확인한 종류는 I01·M01·M05·T01·T03이며 나머지 연결은 단위/합성/Blender 검사와 실제 서비스 검증을 구분한다. 이번에 유료 Runway 생성이나 실제 캐릭터 리깅·동작 작성을 새로 실행하지 않았다.

증거: `artifacts/runtime/graphics-api-live.json`, `graphics-api-assets.json`, `graphics-api-unity-verify.json`, `graphics-api-unity-materials-verify.json`, `graphics-api-unity-reuse-verify.json`, `graphics-unity-materials-check.json`, `graphics-glb-preservation.json`, `graphics-api-package-check.json`, `graphics-api-full-tests.log`. 실제 대검 검증 스크립트는 `scripts/graphics-api-live.ts`이며 기존 승인 ID를 가진 단계는 읽기 확인만 한다. 같은 유료 작업을 재실행하지 않는다.

아래 표와 기록은 preview.1 시점의 기준선으로 보존한다. 위 추가 구현·실제 검증이 최신이다.

## 최우선 계약

- Windows 앱에서 Unity PC 게임 그래픽을 만든다. 첫 대상은 Unity 6000.3.21f1 / URP다. 다른 엔진은 범위 밖이다.
- 오브젝트 → 자료/역할 → 필요한 작업 → 고정 요청과 비용 → 실행 → 검토/채택. 채택과 다음 실행은 별개다.
- 116개 작업의 의미를 유지한다. 목록 존재, 구현, 실제 검증을 구분한다.
- 일상 작업에 브라우저 수동 조작이나 개발자 채팅이 필요하면 연결이 미완성이다. 새 작업 공간은 브라우저 제작 경로를 호출하지 않는다.
- 수동 편집은 선택 사항이다. 정해진 로컬 처리는 코드로, 복잡한 판단/제작은 필요한 Codex/Astra 실행으로 처리한다.
- 모델·추론 강도·참조 해상도·검수 범위를 낮춰 사용량을 줄이지 않는다.

## 데이터와 비용

`GraphicsObject`는 대상, 설정, 참고 역할, 역할+슬롯별 채택 버전을 가진다. `AssetVersion`은 원본 파일 경로/해시/크기/출처와 상위 버전을 보존한다. 채택은 파일을 수정하거나 작업을 실행하지 않는다. 애니메이션은 클립 슬롯별로 채택하며 다른 슬롯을 지우지 않는다.

`GraphicsTask`는 입력 버전/설정/지시/대상을 고정한다. Unity 전달은 `UnityTargetProfile`도 고정한다. 비용 대기는 SQLite와 프로젝트 JSON에 저장한다. 대기 중 작업자는 실행하지 않는다. 만료된 API 견적은 견적만 갱신하고 다시 확인받는다. 실제 제출 장부는 기존 `Engine`의 일회용 `Quote`/`Job`을 재사용한다.

Tripo API 요금은 Studio 구독과 별도다. 2026-10-12 공식 공개 요율을 **예상 비용**으로 표시하며 계정별 실시간 견적으로 표현하지 않는다. P2 무텍스처는 요청 1개당 100 API 크레딧이므로 2개는 200이다. Smart UV는 `/mesh/uv`의 별도 20크레딧 작업이며 `/models/convert`의 UV 패킹과 다르다. 실제 제출은 앱 비용 승인 후 수행한다.

## 이번 실제 검증

- 새 작업 공간의 I01 버튼으로 실제 대검 원본 1장을 생성했다. 브라우저와 외부 유료 API를 호출하지 않았다. 1024×1536 PNG, 1,008,066바이트, SHA256 `a62b91782114480f457662d1fb4527a3f4b58adc44bf90ab6ad236940376b4d8`. 결과는 미채택이다. 칼끝과 손잡이는 보이지만 위아래 여백이 좁다는 경고를 유지했다.
- 최초 등록은 CLI JSONL에 이미지 완료 이벤트가 누락되어 멈췄다. 저장된 `thread/read`만 조회해 thread ID·작업 폴더·native savedPath·응답 바이트 SHA를 확인하는 호스트 복구를 추가했다. 실제 앱 복구 버튼으로 같은 파일을 등록했고 추가 생성은 0회다. base64는 로그나 증거 JSON에 저장하지 않았다.
- 해당 생성 실행의 실제 입력 151,482, 캐시 입력 115,712, 비캐시 입력 35,770, 출력 1,041토큰이다. 복구의 모델 호출은 0회다. 계정 잔여 퍼센트나 이미지 전체 원가, 동일 품질 전후 절감률로 환산하지 않는다. 실패 후에도 기록된 사용량은 앱 집계에 포함한다.
- 실제 앱에서 합성 모델 가져오기·채택·X04 로컬 내보내기·재시작 보존을 확인했다. X05 버튼으로 별도 Unity URP 프로젝트에 가져온 뒤 앱 결과 수집·재시작·동일 입력 재전달을 확인했다. 원본·GUID·사용자 프리팹 해시가 유지됐고 동일 전달 기록 1개를 재사용했다. 이 검증의 GPT·유료 제출·Play Mode는 모두 0회다. 실제 대검 모델 완주는 아니다.
- 연결 진단은 Codex 네이티브 지원/로그인, Tripo API 인증(잔액 0), Runway 인증(잔액 853), Blender 5.0.0, Unity 6000.3.21f1 URP를 읽기 전용으로 확인했다. 계정 잔액은 당시 값이다. Tripo는 API 잔액 부족·미확인 시 업로드/견적 소비 전에 멈춘다. Studio 잔액으로 대신 결제하지 않는다.
- 자동 검사 360통과·2제외, TypeScript와 빌드 통과. 별도 0.7.0-preview.1 패키지에서 실제 원본 표시·확대·재시작 보존 확인, 추가 모델 호출·유료 제출 0회. 실제 제작·단위 테스트·합성 Unity 검증을 구분한다.
- 실제 승인 대기 1,800,129ms(30분 0.129초) 동안 중간 재시작을 거쳐 동일 요청·원본·채택 보존, 네이티브 승인·GPT 작업자·유료 제출 0회. 이후 명시적 X04 로컬 실행과 최종 재시작도 통과했다. 시계만 바꾼 검사가 아닌 실제 벽시계 검사이며 `graphics-app-check.json`에 기록했다.

검증 경로: `scripts/graphics-native-live.ts`, `scripts/graphics-app-check.ts`, `scripts/graphics-unity-app-check.ts`, `scripts/graphics-connections-check.ts`, `scripts/graphics-package-check.ts`. 상세 실행 증거는 각 이름의 `artifacts/runtime/*.json`에 저장된다.

## Unity 전달과 재사용

- `Assets/PartsmithGraphics/<objectId>/Generated`는 앱 관리 결과, `User`는 사용자 스크립트/설정 영역이다.
- `.meta`/GUID를 유지하고 같은 전달 요청을 재사용한다. 구조 변경이나 관리 파일의 외부 수정은 덮어쓰기 전에 충돌로 멈춘다.
- 기본은 가져오기와 파일 유지이며 자동 Play Mode는 없다. 기본 전달은 GPT 요청 0회다.
- 원본을 최적화 값으로 덮어쓰지 않는다. 현재 임의 해상도 축소/압축은 하지 않으며, 선택형 LOD/플랫폼 압축과 성능 측정은 별도 미구현이다.
- 대기 확인은 고정한 설정 파일만 비교한다. 매번 전체 Assets를 읽지 않고, 완료 시 프로필/GUID를 검증한다.

## 검증 표기

1. 단위/경계 검사는 중복 제출·고정 입력·실패 보존·견적·취소를 검사한다. 실제 서비스 품질 증거가 아니다.
2. 별도 Unity 합성 모델 검사는 실제 가져오기 증거지만, 실제 무기 완주나 사족 리그 변형을 대신하지 않는다.
3. 앱 버튼 검사는 실제 main/preload/store 연결을 사용한다. 모의 onAction 화면 검사와 구분한다.
4. 31분 시계 이동 검사와 실제 30분 승인 대기/재시작 검사는 구분한다. 후자는 시간 측정 증거가 있어야 통과다.
5. 최근 최대 10개 작업 사용량은 캐시/비캐시/출력을 분리하며 누락을 0으로 보지 않는다. 동일 품질 전후 측정 전에는 절감률을 발표하지 않는다.

## 저장 공간 조사

저장소 35.26 GiB 중 release 24.31 GiB(52개 배포 폴더), artifacts 10.17 GiB(검증용 프로젝트·프로필 사본), node_modules 0.73 GiB였다. 조사에서 파일은 삭제하지 않았다. 같은 검증 출력은 재사용하며, 정리는 현재 실행 경로·복구본·제작 원본을 확인한 뒤 별도로 처리한다.
