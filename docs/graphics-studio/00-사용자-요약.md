# Partsmith 자동 그래픽 제작 툴 사용자 요약

검토용 초안 1.0 · 2026년 10월 12일

> **개정:** Unity PC 전용으로 확정했습니다. [개정 계약과 구현 현황](04-Unity-PC-개정-구현현황.md)을 우선 적용합니다. 116개 작업 전체가 완성된 상태는 아닙니다.

## 만들려는 앱

**사용자가 만들 대상과 작업을 선택하면, 앱이 실제 제작과 수정을 수행하고 결과를 보여주는 게임 그래픽 자동 제작 툴입니다.** 사용자는 작업 선택, 취향과 요구 전달, 비용 확인, 결과 채택을 담당합니다. 메시를 직접 고치거나 뼈를 배치하거나 키프레임을 찍는 일이 필수 과정이 되어서는 안 됩니다.

기획서를 먼저 써야 하는 앱이 아닙니다. 빈 오브젝트, 참고 이미지, 기존 모델, 텍스처, 리그, 애니메이션 중 필요한 것에서 시작합니다. 문서는 참고 자료로 넣을 수 있습니다.

전체 앱을 바꿀 수 있지만 기존 결과와 기록은 보존합니다. 이 문서는 구현 완료 보고가 아닌, 사용자가 검사하고 고칠 수 있는 제품 설계입니다.

## 내가 하는 일과 앱이 하는 일

| 내가 하는 일 | 앱이 알아서 하는 일 |
|---|---|
| 캐릭터·대검·배경·아이콘처럼 대상을 고름 | 대상에 맞는 작업과 필요한 입력을 제시 |
| 원하는 작업을 켜고 설정함 | 설정을 검사하고 필요한 처리 순서를 구성 |
| 목록에 없으면 자연어로 설명 | 실행할 작업으로 해석하고 지원 여부·범위·비용을 표시 |
| 생성 비용을 확인하고 실행 | 업로드·생성·저장·변환·미리보기·기술 검사 |
| 결과를 보고 채택·보류·수정 지시 | 원본을 보존하면서 지정한 부분의 새 버전 제작 |
| 다음 작업을 선택하거나 실행 | 채택한 정확한 결과를 이어서 사용 |

‘단계별 확인’은 작업을 사용자가 대신 한다는 뜻이 아닙니다. **한 작업 안의 처리와 복구는 앱이 하고, 새 결과를 다음 작업에 사용할지는 사용자가 결정합니다.** 후보 수만큼 매번 업로드하거나 Blender를 열어 정리할 필요가 없어야 합니다.

## 화면은 이렇게 구성

- **왼쪽: 만들고 있는 대상들.** 캐릭터 A, 대검 A, 나무 세트, 체력바 등을 오브젝트 단위로 관리합니다.
- **가운데: 실제 결과.** 이미지, 돌려보는 3D 모델, 영상, 애니메이션, UI·이펙트 미리보기를 표시합니다.
- **오른쪽: 작업 선택.** 해당 대상에서 가능한 작업을 켜고 개수·해상도·면 수·동작 등을 정합니다.
- **아래: 추가 지시와 결과 기록.** “검날만 짧게”, “의상은 유지”, “점프 착지를 부드럽게” 같은 지시와 이전 버전을 관리합니다.
- **실행 전: 이번 작업 확인.** 사용할 원본, 만들 결과, 필요한 연결, 추가 비용, GPT 사용량 정보를 보여줍니다.

처음부터 모든 토글을 펼치지 않습니다. 대상에 맞는 기본 작업을 먼저 보여주고 ‘전체 작업’에서 나머지를 찾습니다. 프리셋은 시작 설정이며 수정할 수 있습니다.

## 어떤 작업을 선택할 수 있나

| 분야 | 예시 |
|---|---|
| 디자인·참고 이미지 | 새 이미지, 캐릭터에 맞는 장비, 부분 수정, 색상·스타일 변형, 필요한 방향 |
| 2D 게임 그래픽 | 스프라이트, 아이콘, 초상화, 타일, 배경, 패럴랙스, 시트·아틀라스 |
| UI 그래픽 | 버튼, 패널, 상태별 이미지, 게이지, 9슬라이스, Unity UI 구성 |
| 3D 모델 | 캐릭터, 무기, 소품, 건물, 모듈, 파츠 분리·조립, 형태 수정 |
| 재질·표면 | UV, 텍스처, 색상 수정, PBR 맵, 데칼, 베이크 |
| 리깅 | 사람·동물 뼈대, 스키닝, 귀·꼬리·옷·머리카락, 손잡이·장착점 |
| 애니메이션 | 동작 참고 영상, 대기·이동·공격·점프, 기존 동작 수정, 루프·접지 |
| 이펙트 | 플립북, 트레일, 충격파, 파티클, 셰이더, Unity 효과 프리팹 |
| 게임용 준비 | 크기·원점, 충돌체, LOD, 재질 연결, 내보내기, Unity 가져오기·검사 |

세부 작업은 [전체 작업 선택표](02-전체-작업-선택표.md)에 있습니다. 모든 항목이 지금 작동한다는 뜻은 아닙니다. 연결 검증이 끝난 작업만 실제 실행을 허용합니다.

## 대검 하나를 만드는 예

1. 캐릭터 이미지를 ‘디자인 참고’로 놓고 **새 오브젝트: 대검**을 추가합니다.
2. ‘참조 기반 디자인’, ‘3D 모델’, ‘텍스처’, ‘Unity 가져오기’를 선택합니다. 리깅·애니메이션·조립은 선택하지 않습니다.
3. “이 캐릭터가 양손으로 쓰는 검. 검정과 빨강. 손잡이는 길게”라고 적습니다.
4. 앱이 대검 이미지를 만들고 보여줍니다. 사용자는 채택하거나 수정 지시만 합니다.
5. 채택 후 모델 작업을 실행하면 앱이 모델 생성부터 다운로드·미리보기까지 처리합니다.
6. 모델을 채택하고 표면 작업을 실행합니다. UV가 필요하면 앱이 설명하고 선택된 표면 작업 안에서 처리합니다.
7. 완성 결과를 채택하고 Unity로 보냅니다. 기본은 가져오기와 파일 유지이며, 실제 재생 검사는 따로 선택합니다.

처음부터 모델을 가지고 있다면 1~5를 하지 않고 그 모델에 텍스처 작업부터 시작할 수 있습니다.

## 수정도 앱이 수행

| 지시 | 앱의 처리 |
|---|---|
| “칼날만 20% 짧게” | 대상과 수치를 확인하고 가능하면 로컬 변형. 전체 AI 재생성부터 하지 않음 |
| “이 캐릭터 색감에 맞는 방패” | 캐릭터는 참고로 유지하고 방패라는 새 대상을 생성 |
| “꼬리도 움직이게” | 기존 리그에서 꼬리 뼈·웨이트를 보완하고 변형 확인 |
| “점프 착지만 부드럽게” | 기존 애니메이션과 채택한 동작 참조를 계속 사용하여 착지 구간 수정 |
| “이펙트를 가볍게” | 입자 수·오버드로 등 원인과 외형 영향 설명 후 선택한 최적화 적용 |

목록에 없는 지시를 받으면 실행 범위를 먼저 보여줍니다. 지원되지 않는 작업을 했다고 꾸미거나, 캐릭터 참고를 무시하고 텍스트만으로 생성하지 않습니다.

## 웹 화면 없이 연결

일상 제작에서 Chrome이나 웹사이트 버튼을 조작하지 않는 구성을 목표로 합니다. 최초 계정 연결·결제는 외부 인증 화면이 필요할 수 있습니다.

- 이미지: Codex 내장 이미지 도구의 **앱 작업자 연결을 먼저 검증**합니다.
- 모델·UV·텍스처: Tripo 공식 API. P2 Preview·Smart UV는 문서 지원이 확인됐으나 새 앱에서 실제 계정·결과 검증이 필요합니다.
- 보정·리깅·3D 동작: Codex Astra가 로컬 Blender를 사용합니다.
- 동작 영상: Runway 공식 연결을 사용합니다.
- Unity 전달: 일반 코드와 Unity 연결을 우선 사용합니다.

Tripo Studio 구독과 API 비용은 별도입니다. 지원되지 않는 옵션을 웹으로 몰래 우회하거나 품질이 낮은 모델로 바꾸지 않습니다.

## GPT 사용량이 많이 들면

**모델·추론 강도·결과 해상도를 낮추는 최적화는 하지 않습니다.** 사용량은 작업별로 기록하고 다음부터 확인합니다.

1. 같은 설명이나 파일을 반복해서 보내고 있는가?
2. 기다리기·다운로드·파일 검사에 GPT를 부르고 있는가?
3. 이미 완성된 결과를 다시 만들고 있는가?
4. 실패 원인이 같은데 같은 호출을 반복하는가?
5. 단순 수치 수정까지 AI에게 다시 계획시키고 있는가?

일반 코드로 가능한 처리는 앱으로 옮기고, 변경된 부분과 필요한 원본만 AI에 전달합니다. 화면에 기록된 사용량과 실제로 알 수 없는 계정 잔여량은 구분합니다. ‘몇 % 절약’은 비교 측정한 뒤에만 표시합니다.

## 검토할 사항

아래 번호로 ‘유지 / 수정 / 제외’를 알려주면 됩니다. 처음부터 세부 표 전체를 검토할 필요는 없습니다.

1. **작업 중심:** 오브젝트를 선택하고 작업을 켜는 화면이 맞는가?
2. **자동화 범위:** 제작·편집·검사를 앱이 수행하고 사용자는 결과를 선택하는가?
3. **결과 확인:** 작업 완료마다 채택·수정하고 다음 작업은 직접 실행하는가?
4. **기능 범위:** 작업 선택표에 빠진 게임 그래픽 작업이 있는가?
5. **수정 방식:** 기본은 자연어 수정이고 직접 편집은 선택 사항인가?
6. **연결 방식:** 웹 조작 없이 공식 연결을 쓰며, API 별도 비용은 실행 전에 확인하는가?
7. **개발 순서:** 먼저 이미지→무기/소품→Unity 흐름을 안정화하고, 같은 구조로 캐릭터·2D·이펙트까지 확장하는가?

전체 목표는 모든 분야를 포함합니다. 개발 순서는 안정적인 연결을 먼저 증명하기 위한 순서이며, 첫 묶음만 만들고 전체가 완성됐다고 선언하지 않습니다.

자세한 처리 규칙은 [전체 기획서](01-전체-기획서.md), 개발 작업에 전달할 문장은 [개발용 프롬프트](03-개발용-프롬프트.md)에 있습니다.
