# 안내형 제작실 · preview28

홈의 `새 오브젝트 만들기`, `이미지·모델로 시작`, `마지막 작업 이어하기`에서 시작한다. 프로젝트 이동은 상단, 오브젝트 이동은 왼쪽, 후보 비교는 중앙, 현재 작업의 설정과 실행은 오른쪽에 둔다. 좁은 창에서는 안내를 미리보기 위로 옮기고 실행 영역을 화면 하단에 유지한다. 기존 수동 기능은 상단 `도구 → 기존 작업실`에서 연다.

## 사용 흐름

1. 대상을 추가하거나 기존 자료를 가져온다. 이 동작은 생성 요청이 아니다.
2. 현재 단계의 주요 조건을 정한다. 기술적인 수치와 상세 설명은 접힌 설정에서 확인한다.
3. `입력·비용 확인`으로 요청을 준비하고, 고정된 입력과 비용을 확인한 후 별도로 실행한다.
4. 후보를 눌러 비교한다. 미리보기만으로 다음 제작의 원본은 바뀌지 않는다.
5. `이 결과 사용 · 다음 설정`을 눌러 확정한다. 다음 설정으로 이동하지만 제작을 자동 실행하지 않는다.
6. 정적 소품은 움직임 단계를 생략할 수 있다. 기존 모델은 재생성 없이 표면·전달 단계에 사용한다.
7. Unity 파일 준비와 실제 가져오기 기록을 구분한다. 현재 입력에 대응하는 가져오기 기록이 있을 때 `Unity에서 확인`을 제공한다. 이 버튼은 연결된 프로젝트를 열며, 이미 열린 프로젝트는 안내한다. Play Mode나 재전달을 실행하지 않는다.

`수정하기`에서 이미지 수정, 형태 보정, 빠진 면 보완, 재질 변경, 크기 설정으로 연결한다. 기존 채택본과 미리보는 수정 원본을 구분하며, 아직 사용할 원본으로 정하지 않은 결과가 필요한 작업은 먼저 원본 선택을 안내한다. UV 결과 확인, 저장된 결과 복구, 좌표·파트 원본 복원은 기존 엔진의 검증과 명령을 유지한다.

## 구현 경계

- `shared/graphics-journey.ts`는 단계·파트·클립, 실제 입력, 준비 조건, 검토·승인·복구 안내를 계산하는 순수 모듈이다. 파일 검사·비용 승인·실행의 최종 권한은 기존 엔진에 남긴다. 새 실행 엔진이나 제작 데이터 이전은 없다.
- 전체 제작 후 분리와 독립 파츠 제작의 입력 범위를 구분한다. UV 작업만 끝난 파트를 텍스처 완료로 표시하지 않으며, 다른 파트의 재질 이력을 섞지 않는다.
- 실행 중에는 현재 설정이 아니라 저장된 요청의 입력을 표시한다. 초안 수정으로 기존 승인 요청을 바꾸지 않는다.
- 프로젝트·오브젝트별 화면 위치와 설정 초안은 별도 로컬 저장소에 보존한다. 복원은 승인·채택·제작을 수행하지 않는다.
- 기본 본문·입력 14px, 설명 13px, 구역 제목 16px, 화면 제목 20px를 사용한다. 선택은 테두리와 문구, 버튼 상태로도 구분한다.

## 남은 검증

실제 신규 사용자에게 설명 없이 제작을 맡기는 사용성 검증은 아직 수행하지 않았다. Windows의 모니터별 OS DPI를 직접 변경하는 검사와 전체 스크린 리더 검증도 별도 항목이다. 이번 작업은 접근성 인증이나 인간형 파츠 접합·Humanoid 품질 완성을 뜻하지 않는다. Unity 열기 동작은 화면 명령 연결과 경로 검증을 구현했으며, 이번 UI 검증에서 새 Unity 제작·Play Mode를 실행하지 않았다.
