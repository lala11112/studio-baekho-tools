# 자동 인간형 리깅 사용과 검증

Partsmith의 리깅 단계에서 설치된 Auto-Rig Pro를 사용해 인간형 전체 모델을 리깅하고, 시험 동작을 확인한 뒤 제한된 웨이트 보정과 Unity 전달을 진행합니다. 운영체제의 마우스·키보드 조작은 사용하지 않습니다. Auto-Rig Pro의 AI 감지는 숨겨진 Blender 프로세스에서 실행하며, 파일 검사·보정·내보내기도 로컬에서 처리합니다.

## 사용하는 순서

1. 이미지·모델 또는 기존 자료로 만든 사람 전체 모델을 사용 결과로 선택합니다. 텍스처를 완료한 전체 재질 버전도 선택할 수 있습니다.
2. **리깅 → 자동 리깅 → 설치 상태 확인**에서 Blender, Auto-Rig Pro, AI 파일 설치를 확인합니다. 유료 애드온과 AI 파일은 사용자의 설치본을 사용하며 앱에 재배포하지 않습니다.
3. 미리보기에서 정확한 전체 모델과 앞 방향을 확인하고 손가락 감지 여부를 선택합니다. **이 모델 자동 리깅**을 누릅니다.
4. 실제 처리 단계가 표시됩니다. 중단은 로컬 프로세스를 중지하며, 재시작은 리깅을 자동 실행하지 않습니다.
5. 새 후보의 재질·단색·메시 선·뼈대를 확인합니다. 중앙 미리보기에서 팔 벌리기·팔꿈치 굽히기·왼쪽 및 오른쪽 무릎 시험 동작을 선택합니다. 이 클립은 검사 전용으로, 게임용 FBX에 포함하지 않습니다.
6. 필요한 경우 **부위·뼈 영향 검사**를 누릅니다. 연결된 부위를 고르면 모델에서 해당 정점이 강조됩니다. 확인된 영역에만 현재 웨이트 정규화, 지정 본 영향 제거, 지정 본 100% 고정 중 하나를 실행합니다. 기존 결과는 유지하고 새 후보를 만듭니다.
7. 결과를 확인하고 **이 리그 사용**을 누릅니다. Unity 설정으로 이동하지만 전달은 자동 실행하지 않습니다.
8. 연결된 Unity 프로젝트에 전달할 결과를 확인하고 별도로 실행합니다. 편집용 BLEND를 보존하면서 검증된 ARP FBX 바이트를 전달합니다.

원본이나 방향을 바꿔 다시 만들 때는 **실행 원본·설치 설정**을 펼치고 **이 설정으로 새 리그 만들기**를 누릅니다. 설정을 바꾸는 것만으로 실행하지 않으며 기존 후보와 사용 중인 리그를 보존합니다. 같은 원본·설정·도구의 완료 결과가 있으면 중복 실행하지 않습니다.

이전 결과를 열면 **지금 미리보는 리그**가 검사·보정·사용 버튼의 대상입니다. 전체 모델 원본을 보고 있을 때 다른 리그가 대신 채택되지 않습니다. 새 리깅 원본을 선택하면 앞 방향을 다시 확인해야 하며, 단순히 원본을 3D로 보는 것은 작성한 실행 설정을 지우지 않습니다. 후보나 검사 기록을 바꾸면 이전 부위·본 선택만 초기화합니다.

## 보정과 지원 범위

- 새 리깅 입력은 기존 리그·웨이트·애니메이션·모프·미적용 변형이 없는 인간형 BLEND 또는 FBX입니다. 앞 방향 확인에는 로컬 GLB 미리보기가 필요합니다.
- 기존 리그 보정은 편집 가능한 Auto-Rig Pro BLEND가 대상입니다. 임의의 다른 리깅 도구가 만든 파일을 같은 방식으로 보정한다고 가정하지 않습니다.
- 부위는 실제로 연결된 메시 정점 집합입니다. 붙어 있는 몸통에서 가슴만 자동으로 분리해 이해하거나, 단일 메시의 머리카락을 임의로 추정하지 않습니다.
- 뼈 영향 제거 뒤 유효한 웨이트가 없으면 차단합니다. 부위 전체 고정은 장식 등 단단한 부위에 적합하며 관절을 가로지르는 몸통·팔다리에는 적합하지 않습니다.
- 무릎의 면 재구성, 자동 해부학 보정, 얼굴·옷 물리, 완성 게임 애니메이션은 이 기능의 범위가 아닙니다. 이전 모델의 개별 보정 절차를 모든 모델에 적용하지 않습니다.
- 현재 ARP 전달은 검증된 FBX를 보존하는 경로입니다. LOD·크기/피벗 변환·별도 클립 합성과 기존 Astra 애니메이션 경로는 별도 검증 전까지 차단합니다. 원본 모델의 크기는 리깅 전에 결정합니다.
- 통짜 인간형 한 종류와 기존 보정본의 실제 동작을 검증했습니다. 여러 파트를 가진 모든 캐릭터의 내보내기 완전성이나 게임에서의 자연스러운 변형까지 검증한 것은 아닙니다.

## 보존과 실행 규칙

원본 버전·파일 SHA·워커 SHA·방향·손가락·선택 부위를 실행에 고정합니다. 동일 요청의 중복 클릭은 한 실행으로 처리합니다. 취소 뒤 늦게 도착한 결과는 채택하지 않습니다. 오류나 재시작 후에는 저장된 완전한 결과만 명시적으로 복구하며 AI를 자동 재실행하지 않습니다.

사용자가 취소한 실행에는 복구 버튼을 표시하지 않습니다. 실패·차단된 실행의 복구는 저장 파일 검사만 수행합니다. 이전 후보를 검사한 뒤 보정본을 만들더라도, 이전 후보의 검사 기록은 그대로 사용할 수 있습니다. 검사 기록과 보정 결과 기록을 구분해 연결합니다.

채택 시 원본·결과·검사 보고서·요청·본 매핑·내보낼 FBX를 다시 검증합니다. 검사 실행은 새 채택 모델로 등록하지 않습니다. 사용자가 결과를 선택하기 전에는 이전 채택본이 유지됩니다.

검사·리깅·선택 웨이트 보정·기본 Unity 전달에는 외부 유료 API와 제작용 GPT 호출을 사용하지 않습니다. 설치된 ARP의 로컬 AI 연산과 Blender 실행 시간은 발생합니다.

## 실제 검증 결과

- 앱 버튼에서 기존 원본 FBX 사본의 몸·손가락 자동 리깅, 원본 형상/UV/재질 보존, FBX 저장과 4개 GLB 시험 클립 생성이 완료됐습니다. 새 결과는 격리 프로젝트의 미채택 후보로 남겼습니다.
- 개발 중 두 실패를 보존했습니다. ARP가 추가한 보조 이미지와 원본 이미지 검사를 구분했고, IK 중립 솔버 오차는 FK 상태로 정리해 해결했습니다. 원본 형상 허용치를 완화하지 않았습니다. 자동 재시도는 없으며 코드 수정 후 명시적으로 다시 시험했습니다.
- 기존 보정본 사본에서 실제 앱으로 연결 부위 검사, 8정점 장식의 지정 본 고정, 검토 후보 생성과 명시적 채택을 수행했습니다. 다른 웨이트와 형상·UV·재질·골격은 독립 검사에서 유지됐습니다.
- 앱 뷰어의 12개 본 영향 계산은 4개 자세에서 Blender와 최대 오차 `2e-5` 원본 단위 이내였습니다. 원본 25정점 선택이 UV 분할된 44개 화면 정점에 정확히 표시됐습니다.
- 실제 Unity 6000.3.21f1에서 Humanoid Avatar valid/human, 52개 명시적 본 매핑, 12,950개 렌더 정점의 유효한 웨이트를 확인했습니다. 정확한 ARP FBX를 가져왔고 재전달 뒤 GUID·사용자 컴포넌트·씬 참조·사용자 프리팹 파일이 유지됐습니다. Play Mode 및 전체 자세의 Unity 변형 동등성은 별도 검증 대상입니다.
- 창 너비 1280/960/800에서 고정 실행·중단·결과 사용 버튼과 실제 Electron 조작을 검사했습니다. 신규 사용자 사용성 검증을 대신하지 않습니다.
- 최종 관련 코드 검사 70개와 실제 Electron 화면 검사 2개를 통과했습니다. 기존 후보에서 새 검사 미리보기를 열고 장식의 원본 8정점을 강조했으며, 채택본과 파일을 바꾸거나 보정을 다시 실행하지 않았습니다.
- 별도 배포본 **0.7.0-preview.31**의 재시작에서 실행 기록·결과·채택·등록 파일 13개 해시가 유지되고 자동 실행이 없었습니다. 운영 프로필로 새 배포본을 열고 창 생성까지 확인했으며, 운영 6작업공간·312등록 파일·8프로젝트 JSON은 이전과 같았습니다. 운영 제작·채택 버튼은 누르지 않았습니다.

증거는 `artifacts/runtime/graphics-auto-rig-start-live.json`, `graphics-auto-rig-app-live.json`, `graphics-auto-rig-app-independent-native.json`, `graphics-auto-rig-app-unity.json`, `graphics-auto-rig-full-skin-check.json`에 저장합니다. 검증 후보와 운영 프로젝트의 결과를 구분합니다.

preview31의 패키지 재시작·운영 보존 증거는 `graphics-auto-rig-packaged-restart.json`, `graphics-auto-rig-production.json`, `graphics-auto-rig-release.json`에 저장합니다. 구매한 Auto-Rig Pro 애드온 및 AI 바이너리는 패키지에 포함하지 않습니다.

## 2026-10-17 · preview32 앱 버튼 완주 확인

앱에서 실제로 보이는 버튼으로 기존 자동 생성 후보 `b005b7d1`을 열고, 4개 시험 동작·재질/단색/메시 표시 → 부위 검사·8정점 강조 → 이 리그 사용 → Unity 프로젝트 검사 → 전달 준비·승인 → 가져오기 완료 표시를 확인했습니다. 검증용 사본에서만 채택했으며 원본 자동 리깅과 유료 제작을 다시 실행하지 않았습니다. 이전에 완료한 8정점 보정 검증은 유지하고, 이번 새 후보에는 보정을 추가 실행하지 않았습니다.

- 수정: 미리보는 이전 후보 대신 최신 후보를 검사·보정·사용하던 대상 불일치, 취소된 실행의 불가능한 복구 안내, 원본 변경 시 이전 앞 방향 재사용, 원본 미리보기 시 실행 설정 초기화, 보정 기록을 검사 기록으로 잘못 선택해 이전 후보의 보정이 잠기는 문제를 해결했습니다.
- 관련 실행기·조정기 43개, 검사 표시 2개, Electron 화면 흐름 2개와 TypeScript·빌드·별도 패키징을 통과했습니다.
- 기존 격리 프로젝트의 실제 이력에서도 원본 후보의 검사 기록이 이후 보정 기록에 가려지지 않았습니다. 구형 검사에 정점 영역 정보가 없으면 보정을 차단하고, 최신 검사에서는 8개 원본 정점 강조와 보정 버튼 활성화를 확인했습니다. 새 검사·보정·채택 없이 작업공간과 등록 파일 13개 해시가 유지됐습니다.
- 별도 Unity 프로젝트에서 정확한 자동 리깅 FBX를 가져왔습니다. Humanoid Avatar valid/human, 명시한 52개 본 매핑, 렌더 정점 12,091개 모두 유효한 웨이트, 잘못된 웨이트 0개를 확인했습니다.
- 최초 전달 준비·승인은 앱 버튼입니다. 이후 재가져오기는 별도 Unity 로컬 회귀 검사로 수행했으며, 앱의 재전달 버튼 검증으로 표현하지 않습니다. 동일 GUID·사용자 컴포넌트·씬 참조·사용자 파일 해시가 유지됐습니다. 앱이 Unity 검사 기록을 자동 수신해 완료 안내를 표시한 것도 확인했습니다.
- 배포본 재시작에서 실행 기록·채택·후보 파일 해시·원본 파일 해시가 유지됐고 자동 리깅 재실행이 없었습니다. 운영 앱은 preview32로 열었으며, 운영 제작·채택 버튼은 누르지 않았습니다.
- 이 검증은 실제 앱 연결과 파일 전달 검증입니다. 원본 자동 리그의 장식 끌림·깊은 관절 접힘 등 외형 문제까지 모두 해결했다는 뜻은 아닙니다. Play Mode와 전체 시험 자세의 Unity 변형 동등성도 이번 검증 범위에 포함하지 않았습니다.
