## 앱에서 사용하는 순서

1. 오브젝트를 추가합니다. 인간·동물·크리처·무기·장비·바위·상자·소품·환경·식물에 맞는 특징을 고릅니다. 없는 특징은 직접 설명합니다.
2. 이미지 단계에서 참조, 시점, 자세, 구도, 배경, 여백과 후보 수를 설정합니다. 멀티뷰는 기본 꺼짐이며 후보 수와 방향 수가 별개입니다. 기존 원본을 가져와 시작해도 됩니다.
3. ‘이 단계 준비 · 비용 확인’으로 설정과 원본을 고정합니다. 비용 카드에서 실행해야 제작이 시작됩니다. 옵션 변경·저장·단계 이동·채택만으로 생성하지 않습니다.
4. 결과를 검토·채택합니다. 모델은 Tripo API, 규칙형 Blender 프리셋, Blender+Astra 중 직접 선택합니다. 기존 모델은 이미지 단계를 생략합니다.
5. 필요한 UV·재질·조립·보정·리깅·동작만 실행합니다. 통짜 정적 모델은 조립·리깅·애니메이션을 생략하고 Unity로 전달할 수 있습니다.
6. Unity 단계에서 파일 내보내기 또는 연결 프로젝트 전달을 선택합니다. 기본은 임포트와 파일 유지입니다. 원본 .blend·FBX·이미지를 덮어쓰지 않습니다.

## 구현한 계약

- `CreationSpec`에 외형·자연어·잠금, 단계별 설정, 파츠 설정, 클립별 설정을 보존합니다. 예전 작업은 읽기 호환을 유지하며 앱을 열었다고 이전 기록을 덮어쓰지 않습니다.
- 이미지·모델·Tripo 텍스처·동작 후보 수는 각각 1–4개입니다. 정확한 수치를 적용하는 로컬 UV·재질 변경은 1개입니다. 인간 기본 3파트는 머리·몸통·머리카락이고 추가 파츠와 각각의 면 예산·후보 수를 관리합니다.
- 처음 만드는 캐릭터 이미지는 전체 디자인입니다. 파츠 이미지 제작을 별도로 선택하면 채택한 전체를 참조해 해당 파츠만 만듭니다. 파츠 슬롯은 `part-<id>`로 분리해 다른 파츠 채택을 덮어쓰지 않습니다.
- M07 분리는 실제 면·UV·재질·웨이트의 분배를 확인하고 파츠별 BLEND/FBX/GLB를 저장합니다. M08은 채택한 각 파츠를 조립합니다. M06 부분 보정은 실제 `partsmith_id` 목록이 있어야 하며 미지정 메시 변경을 거절합니다.
- Humanoid/Generic/기존 리그 보정과 귀·꼬리·머리카락·의상·날개·장비 관절 설정을 연결했습니다. 실제 뼈·웨이트·포즈 변형을 검사합니다. 물리 시뮬레이션을 했다고 표시하지 않습니다.
- 동작은 Runway 영상, 가져온 MP4/WebM, 자연어, 기존 클립 수정으로 입력합니다. 외부 영상은 원본을 보존하고 로컬 ffmpeg로 원해상도 검토 프레임을 추출합니다. 클립 이름·길이·FPS·후보·지시를 별도로 저장합니다. 기존 클립 수정은 원래 장면과 동작 참조를 유지합니다.
- Unity 전달은 원본과 분리된 설정으로 LOD1·충돌체·텍스처 크기·압축을 적용합니다. GUID와 사용자 프리팹 연결을 유지합니다. 리그/스킨 모델의 자동 LOD 등 미지원 조합은 실행 전에 사유를 표시합니다.

## 동시 실행과 사용량

- 이미지 여러 장은 **한 Codex 작업자**에 하나의 고정 요청으로 보냅니다. 제공된 원본은 한 번 읽고 문서화된 묶음 도구 또는 최대 4개의 병렬 네이티브 호출을 사용하도록 지시합니다. 방향별 원본을 시트로 대체하지 않습니다. 도구가 직렬 실행만 지원하면 제한을 보고하도록 합니다. 실제 네이티브 서비스의 동시 실행 여부·4장 소요 시간 단축률은 이번에 실측하지 않았습니다.
- 독립 Blender/Astra 모델·동작 후보는 최대 2개, Runway 후보는 최대 4개 동시 실행합니다. 후보별 폴더·요청 해시·비용 승인을 분리하고 완료 파일을 즉시 등록합니다. 오류 후 아직 시작하지 않은 후보는 자동으로 새 요청하지 않습니다.
- Tripo 후보들은 각각의 요청 ID를 저장한 뒤 원격 생성이 겹쳐 진행됩니다. 이미지 채택→모델, 모델 채택→후처리처럼 선행 결과가 필요한 단계는 병렬로 뛰어넘지 않습니다.
- 텍스처 후보도 합계 비용을 한 번 승인하고 각 원격 작업을 독립 제출합니다. 기존 후처리 1개 제한은 텍스처에만 해제하고, UV 등 수치 처리의 단일 실행 규칙은 유지합니다. 병렬 후보 중 하나라도 유료 제출 여부가 불명확하면 전체 요청을 미확정으로 유지해 새 생성을 막습니다.
- 조회·대기·다운로드·프레임 해독·로컬 프리셋·기본 Unity 전달에는 GPT를 호출하지 않습니다. 모델·추론 강도·참조 해상도는 낮추지 않았습니다.
- Tripo 개발비 승인 300 중 이전 사용 140, 남은 승인 범위 160을 유지합니다. 이번 개발에서 추가 Tripo·fal·Runway 유료 제출은 0입니다. 승인 대기는 저장 상태이며 GPT가 기다리며 추론하지 않습니다.

## 실제 검증 근거

- 최종 전체 회귀 검사 509개 중 501개 통과·8개 제외·실패 0. TypeScript, 프로덕션 빌드, 별도 Electron 패키지 검사 통과. 제외된 검사를 통과로 계산하지 않습니다.
- `scripts/graphics-creation-package-check.ts`: 별도 프로필의 실제 배포 앱 버튼으로 로컬 바위 후보 2개 생성 → 검토 → 1개 채택 → 재시작. 원본/후보 해시·채택 유지, API/GPT 호출 0. 1440×1000·1024×768·800×600 및 100/125/150% 앱 배율에서 실행 버튼 접근 검사.
- `tests/graphics-astra-models.test.ts`: 실제 Blender로 분리·조립, 지정 부분 외 수정 거절, 신규 메시 검증, 보조 관절 변형 검사. 작업자의 결과를 합성 fixture로 공급했으므로 **실제 Astra 창작 품질 검증은 아님**.
- `tests/graphics-motion-import.test.ts`: 실제 ffmpeg로 원본·프레임 해시, 영상 길이(긴 오디오와 구분), 재해독 없는 재사용, 동일 클립 N04 입력 계약 확인.
- `scripts/graphics-optimization-check.ts`: 독립 Unity6000.3.21f1 프로젝트에서 528→264 삼각형 LOD, LODGroup2, Box/Mesh/Convex Collider, 원본1024→Unity256 압축 및 기본설정 복원. Generated GUID 및 User prefab 바이트 유지.
- 후보 병렬 시작·부분 실패·완료 후보 재사용·비용 분리와 UI 저장/실행 경계는 stub 기반 회귀 검사입니다. 외부 서비스 성공으로 표현하지 않습니다.

## 남은 검증과 명시적 제한

- 새 인간·동물·복잡한 장비의 실제 AI 생성부터 Unity까지의 외형·변형 품질은 미검증입니다. 이번에는 기존 실생성 원본과 로컬 검사를 우선했습니다.
- 규칙형 Blender 프리셋은 바위·상자의 지원된 조합입니다. 광맥·수정 덩어리·통/항아리·가동 경첩·임의 자연어·외형 잠금 같은 미지원 요청을 무시하지 않고 거절합니다. 복잡한 형태는 사용자가 Astra 또는 Tripo를 선택합니다.
- 잠금은 메시 구조 등 검사 가능한 계약만 자동 검사합니다. 얼굴·체형 등 외형 일치는 시각 비교가 필요합니다. 원본 이미지가 있다고 로컬 프리셋의 닮음을 보장하지 않습니다.
- 실제 Tripo 부분 재생성과 마스크 UI, Unity Play Mode 검증 버튼, 스킨 LOD, 복잡한 부위별 재질의 전용 편집 UI는 이번에 완성하지 않았습니다. 자연어로 가능한 보정과 전용 기능의 구현 여부를 구분합니다.
- 독립 2D·게임 UI·이펙트·레벨 배치는 후순위 미개발입니다. 기존 116개 작업의 기록은 보존하고 Astra 신규 모델 M15를 별도 추가했으며, 작업 개수를 제품 완성률로 사용하지 않습니다.
