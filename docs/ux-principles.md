# 백호툴 기본 UI·UX 규칙

기준일: 2026-10-08 · 상태: 팀장이 승인한 연결 방향

## 1. 기본 결정

**공통 화면은 도구를 찾고, 현재 작업을 이해하고, 결과로 돌아오는 경험을 책임집니다. 각 도구 담당자는 기존 작업물의 전문 UI와 내부 작업 구조를 유지합니다.**

타격감 찾기는 후보 재생·비교, 모델링은 3D 조작·옵션 편집처럼 서로 다른 작업 방식이 필요할 수 있습니다. 모든 도구에 동일한 단계형 화면이나 좌우 패널 구조를 강제하지 않습니다.

사용성 판단 기준은 다음 질문입니다.

- 지금 어느 프로젝트의 어떤 도구를 쓰고 있는가?
- 다음에 무엇을 해야 하며, 현재 작업은 어떤 상태인가?
- 다른 도구를 보고 돌아와도 작업을 이어갈 수 있는가?
- 결과는 어디에 있고, 사용한 설정을 다시 확인할 수 있는가?

## 2. 공통 영역과 도구 영역

| 영역 | 공통 규칙 | 팀별로 결정할 부분 |
| --- | --- | --- |
| 탐색 | 프로젝트, 도구 이름, 현재 위치, 공통 메뉴 복귀 경로를 제공 | 내부 탭, 전문 기능 분류 |
| 작업 | 작업 식별 정보, 저장 여부, 실행 상태의 의미를 통일 | 입력 폼, 상세 옵션, 내부 단계 |
| 행동 | 실행·취소·재시도·보관·적용 용어와 기본 행동 위치 원칙을 공유 | 편집·재생·회전 등 전문 조작 |
| 결과 | 원래 작업과 연결하고 다시 열 수 있는 경로를 제공 | 미리보기 형식, 비교 방식, 평가 항목 |
| 시각 요소 | 기본 글꼴·버튼·여백·상태 표현을 공통 기준으로 맞춤 | 작업에 필요한 패널 수, 미디어 크기, 도구 전용 조작 |

기존 UI를 연결할 때는 공통 영역과 충돌하는 부분부터 맞춥니다. 내부 편집기를 전부 다시 만드는 것을 연결 조건으로 두지 않습니다. 화면 폭이나 전문 작업 특성 때문에 배치가 달라져야 한다면 이유와 대응 방식을 인계 문서에 남깁니다.

## 3. 도구 선택에서 이어지는 흐름

**도구 선택 → 도구 작업공간 → 결과 확인·보관 → 이어서 작업**

이 흐름은 제품의 큰 이동 경로입니다. 모든 도구가 동일한 횟수의 클릭이나 동일한 입력 단계를 갖는다는 뜻은 아닙니다. 결과 검토도 해당 도구 안에서 수행할 수 있습니다.

| 공통 메뉴 | 사용자가 찾는 것 |
| --- | --- |
| 홈 | 최근 작업, 이어 할 작업, 자주 쓰는 도구 |
| 도구 | 도구 검색, 용도와 입출력 설명, 작업 시작 |
| 실행 | 진행·완료·실패한 실행과 상세 기록 |
| 결과 | 보관한 결과, 원래 작업과 설정, 다시 열기 |
| 설정 | 프로젝트·팀·연결 관련 설정 |

도구가 추가되어도 최상위 메뉴에 도구 이름을 계속 늘리지 않습니다. 프로젝트 선택 위치는 공통 탐색 영역 안에서 유지합니다. 역할별로 홈의 우선순위를 바꿀 수 있지만 메뉴의 의미는 같습니다.

도구 카드에는 이름, 목적 한 문장, 필요한 입력, 얻을 결과, 사용 가능 상태를 우선 보여줍니다. 자세한 옵션은 작업공간에서 다룹니다.

## 4. 작업공간의 공통 행동

### 이동과 이어서 작업

- 다른 메뉴로 이동하거나 돌아와도 입력·선택·진행 상황을 보존하는 경험을 목표로 합니다.
- 프로젝트를 바꿀 때 대상 프로젝트와 현재 작업을 혼동시키지 않습니다.
- 화면 이탈로 실행이 중단되거나 입력이 사라지는 도구는 이탈 전에 실제 영향을 설명합니다. 가능한 경우 초안 보관이나 복귀 경로를 제공합니다.
- 현재 도구가 지원하지 않는 백그라운드 실행·복원을 지원한다고 표시하지 않습니다. 지원 범위와 개선 계획을 [인계 양식](templates/tool-handoff.md)에 기록합니다.
- 긴 작업이 화면 이동과 독립적으로 계속될 수 있는 경우, 공통 실행 목록에서 상태를 확인하고 해당 작업으로 돌아갈 수 있게 합니다.

### 버튼과 주요 행동

한 화면에서는 지금 해야 할 주요 행동 하나를 명확히 강조합니다. 설정 중에는 실행, 결과 검토 중에는 선택·보관이 중심입니다. 실행 버튼은 공통 작업 헤더나 합의한 행동 영역에 두고, 전문 미디어 조작과 구분합니다.

| 용어 | 사용자가 기대할 동작 |
| --- | --- |
| 도구 열기 | 도구의 작업공간으로 이동. 자동 실행하지 않음 |
| 실행 | 현재 입력과 옵션으로 새 실행 시작 |
| 취소 | 실행 중단 요청. 실제 중단 전에는 ‘취소 요청 중’처럼 구분 |
| 다시 실행 | 같은 설정으로 새 실행을 만들고 이전 실행과 연결 |
| 설정 바꿔 실행 | 이전 설정을 불러와 수정한 뒤 새 실행 시작 |
| 선택 | 현재 비교 대상이나 채택 후보를 표시. 보관과 구분 |
| 보관 | 결과를 정해진 위치에 저장하고 다시 열 수 있게 함 |
| 적용 | 원본이나 대상 프로젝트에 변경 반영. 대상과 범위를 먼저 표시 |

취소·재시도·보관을 지원하지 않으면 버튼을 가장한 동작을 제공하지 않습니다. 해당 제한과 가능한 대안을 가까이에서 안내합니다. 실패한 보관을 성공 알림으로 표시하지 않습니다.

## 5. 상태와 오류

실행 상태와 결과 검토 상태를 분리합니다. **실행 완료가 곧 검토 완료나 보관 완료는 아닙니다.**

| 상황 | 표시와 다음 행동 |
| --- | --- |
| 입력 전·초안 | 필요한 입력과 시작 방법. 입력값 유지 여부 표시 |
| 대기 | 실행 대기 이유 또는 순서가 있으면 제공 |
| 실행 중 | 단계 이름·경과 시간. 측정 가능한 경우에만 진행률 표시 |
| 완료 | 생성된 결과와 결과 열기. 검토 필요 여부를 별도 표시 |
| 실패 | 실패 위치·원인·보존된 결과·가능한 다음 행동. 상세 로그는 펼쳐 보기 |
| 취소 요청·취소됨 | 요청 접수와 실제 종료를 구분하고 남은 결과 안내 |
| 검토 전·선택됨·보관됨 | 결과의 검토·선택·보관 상태를 실제 동작과 일치시킴 |
| 빈 화면 | 첫 사용, 검색 결과 없음, 결과 없음의 이유와 다음 행동 구분 |
| 권한 부족 | 행동 가까이에 불가 이유와 실제 지원되는 안내 경로 표시 |

색상과 상태 문구를 함께 사용합니다. 로딩 중에도 화면 구조와 입력값을 유지하고, 임의의 진행률이나 완료 시각을 만들지 않습니다. 입력 오류는 해당 필드와 연결해 수정 방법을 알려줍니다.

## 6. 결과와 기록

결과에서 도구 이름, 대상 프로젝트, 원래 실행, 사용한 조건, 도구 버전, 실행 시점, 보관 위치를 확인할 수 있도록 연결 정보를 전달합니다. 없는 정보는 알 수 없음을 표시합니다.

도구 버전, 결과 후보/버전, 재실행 이력을 같은 의미로 사용하지 않습니다. 결과 보관 성공 후에는 위치나 다시 열기 동작을 제공합니다. 검토 메모나 선택 후보를 지원하는 도구는 해당 정보도 원래 작업에 연결합니다.

타격감의 영상 비교, 모델링의 3D 미리보기·버전 비교는 참고 UX입니다. 지원 미디어와 기능이 확인되면 각 도구의 기존 UI에 맞춰 연결합니다. 미리보기를 제공할 수 없는 형식은 파일 정보와 사용 가능한 열기 방법을 제공합니다.

## 7. 읽기와 조작

- 본문은 14–16px을 기본으로 검토하고, 긴 한국어와 여러 줄 설명이 잘리지 않게 합니다.
- 중요한 버튼과 상태는 키보드로 접근하고 포커스 위치를 알아볼 수 있게 합니다.
- 전용 뷰어의 단축키가 공통 탐색 단축키와 충돌하면 범위와 안내를 조정합니다.
- 작은 화면에서는 패널을 접거나 드로어로 전환해 주요 작업 영역을 확보합니다. 전문 편집기에 최소 화면 폭이 필요하면 명시합니다.
- 실제 기능이 없는 제어 요소, 아무 반응 없는 버튼, 설명 없는 비활성 버튼을 남기지 않습니다.

## 8. 연결 완료의 사용성 기준

담당자가 아닌 팀원이 다음 시나리오를 설명 없이 수행해 봅니다. 이는 제품 구현 후 확인할 기준이며, 현재 통과했다는 뜻은 아닙니다.

1. 프로젝트를 확인하고 원하는 도구를 찾는다.
2. 필요한 입력을 이해하고 작업을 실행한다.
3. 다른 메뉴로 이동한 뒤 실행을 다시 찾는다. 이탈 제한이 있다면 미리 이해한다.
4. 결과를 확인·선택·보관하고 다시 연다.
5. 결과에서 원래 설정을 확인하고, 지원되는 방식으로 수정·재실행한다.
6. 입력 오류나 실행 실패에서 다음 행동을 찾는다.

점검 결과에는 막힌 위치, 예상 행동, 실제 행동, 화면 또는 재현 경로를 남깁니다. 우선순위는 사용자가 작업을 완료할 수 있는지로 정합니다.
