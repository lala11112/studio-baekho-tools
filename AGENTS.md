# Auto-3D-Tool development instructions

## Repository and branch
- This checkout is `https://github.com/lala11112/studio-baekho-tools`.
- Continue this project on branch `Auto-3D-Tool`. Preserve other branches and unrelated work.
- Partsmith is a user-guided asset workbench. Never auto-advance between stages. Flow: GPT (default) or Tripo creates four concept images → user selects one → semantic head/hair/body separation with front/back/left/right images for each part → user reviews/corrects → Tripo Studio Smart Mesh P2 creates ONE model per part from the four views with user polygon target → user accepts each part → Smart UV/textures → user reviews → Blender + Astra assembly with repeated object-scoped instructions, immutable versions and revert → Blender + Astra rig → synchronized multiview 2D animation frames reviewed by user → Astra authors Blender 3D animation → Unity validation. Only initial concept generation offers multiple candidates; later stages produce one result/version and offer prompt-guided reroll of the chosen part/view/object. Preserve unaffected outputs, version history and revert. Existing API tools stay advanced/manual; legacy automatic runs are read-only archives.
- The user's latest animation requirement is multiview 2D animated images/frames, not mandatory video input or a motion-capture service. Use front/side/back frames and explicit timing. Select `gpt-6-astra` for Blender assembly/refinement, rigging and 3D animation as requested; other workers retain the user's configured default. Rigging toggles add object-specific controllable bones/weights for clothing, hair or accessories; OFF still follows the body. Do not add Unity physics unless requested. Never silently replace Astra, reference frames, or authored motion with preset Idle/Walk.
- Treat Smart Mesh P2 in Tripo Studio as the requested default. API P2 Preview support and Studio capabilities are separate. Never silently switch generation models or replay ambiguous submissions. Do not present local demos, task queues, worker-reported checks, or mocked tests as proof of completed high-quality AI production.
- A model reroll uses Tripo Studio Mesh Edit / partial regeneration on the existing model; selecting the entire model gives a full reroll. It is never a new image-to-model generation. Observe the actual edit allowance and cost, preserve prior versions and never fall back to Generate after a quota/selection/tool failure. A requested prompt must be supported and visibly applied or reported unsupported. Do not hardcode free edit counts or credit prices.
- Recover transient errors and repair existing files only within the current user-requested stage, at most three attempts with bounded waits. Preserve successful subphase checkpoints. Recovery of a started phase must not generate new images or submit new Studio charges; untouched subphases may execute their original approved scope. Never auto-advance, auto-resume after cancellation/restart, or replay ambiguous submissions. Use Tripo candidate screenshots for comparison and direct compatible GLB for optional rotation; use Blender conversion only when the downloaded format requires it.
- In separation, known visual quality observations (alignment, scale, alpha edges, appearance) are review warnings, not automatic repair triggers. Preserve failed observations honestly; never turn them into passed checks. Show validated completed part images as non-selectable drafts while remaining views run. New separation requires twelve distinct valid images (three parts × front/back/left/right) and explicit user acceptance before modeling. Viewless legacy part images are front views only; missing views are never fabricated or copied/mirrored as substitutes. Missing-only generation preserves all existing images; explicit targeted reroll creates a new version without changing other images. Keep file integrity/path/hash/role/duplicate checks blocking. Explicit saved-photo inspection must not start a worker or generate missing parts.
- New separation visual observations use the stable `visual_quality` name with a finite `visualCategory` and descriptive `detail`; do not invent new blocking aesthetic check names. Keep the original failed observations. Normalize only local derivatives to a 2048×2048 transparent canvas, using each part's front silhouette as the common height anchor and centered framing across four views. Preserve aspect ratio, asymmetry, raw image bytes, hashes and history. Show/use the validated derivatives for review and Tripo upload. Missing transparency or an unavailable front anchor is an explicit local preparation issue, never a reason to regenerate automatically.
- GPT separation defaults to individual per-view generation because preserving output quality has priority over speed. Offer explicit opt-in `separationStrategy: "part-sheet-v1"`: make one built-in image-generation call per part for a transparent 2×2 multiview sheet (top-left front, top-right back, bottom-left character-left, bottom-right character-right), then split the actual generated pixels locally. An opted-in fresh three-part job uses three generation requests, not twelve sequential view requests. Missing-only batch work groups only the missing views for each part and leaves unrequested cells blank; a single-view correction remains one image call. Preserve the original sheet as registered evidence, each existing view and the frozen batch plan/checkpoint. Recover splitting from a saved sheet without generating again. Jobs without the strategy field keep their original per-view execution plan. Do not claim the current built-in tool has an `n=4` option, silently switch to the paid Image API, or promise a fourfold wall-clock speedup. A 2×2 sheet shares its native resolution across four cells; 2048 derivatives do not invent detail. Do not force batching as a token optimization without the user's explicit selection.
- GPT token optimization must preserve model selection, reasoning effort, all distinct needed reference images at original resolution, and existing semantic/quality checks. Remove redundant context and host-owned file work only. Show native per-view image dimensions separately from normalized 2048 previews; do not describe unmeasured batching as equal-quality or claim a measured token saving without new usage data.
