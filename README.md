# Baekho Enemy Forge

현재 `Four-Tiger-Sword` 프로젝트의 적 구조에 맞춘 Windows용 독립 프리팹 제작 앱입니다. 앱에서 설정하고, 연결된 Unity가 에셋 참조·애니메이션·프리팹 저장을 처리합니다.

## 실행

1. `release/Baekho-Enemy-Forge-1.1.0-Windows.exe`를 실행합니다.
2. Unity 6000.3.10f1에서 프로젝트를 열고 Unity MCP HTTP 서버를 켭니다. 기본 주소는 `http://127.0.0.1:8080/mcp`입니다.
3. 앱의 **Unity 연결**을 누릅니다. 처음 연결하는 프로젝트에서는 **연동 설치**를 누릅니다. 앱이 화면 없는 Editor 어댑터를 설치하고 컴파일을 기다립니다.
4. Drone 설정을 출발점으로 이름·모델·능력치·공격·애니메이션을 지정합니다.
5. **검증 실행** 후 **프리팹 생성**을 누릅니다. 생성 폴더 열기로 결과를 찾을 수 있습니다.

이전 버전을 사용하던 프로젝트도 이번 기능을 사용하기 전에 **연동 설치**를 한 번 눌러 갱신하세요. 방향 파라미터 연결용 Runtime 컴포넌트도 함께 설치됩니다.

프리팹과 전용 데이터는 `Assets/_Project/Generated/Enemies/<이름>/`에 생성됩니다. 이름이 같은 폴더는 덮어쓰지 않습니다. **저장/열기**는 앱 설정 문서인 `*.enemyforge.json`을 저장하고 불러옵니다. 저장하지 않은 변경이 있으면 다른 설계 열기·템플릿 초기화·프로젝트 변경 전에 폐기 여부를 확인합니다. 새 적을 다시 생성할 때는 새 이름을 지정합니다.

앱 창을 닫기 전에는 **저장**을 눌러 설계 문서를 남기세요. 종료 시 설계가 자동 저장되지는 않습니다.

## 제작 기능

- 외형: 프로젝트 모델/프리팹, 위치·회전·크기, 몸체 충돌 크기, 체력바와 피격 효과의 자동·수동 위치.
- 능력치: 체력·공격력·방어력·치명·속성·경직·넉백과 전투 거리.
- 이동과 감지: NavMeshAgent, 시야·근접 감지, 목표 기억과 접근 재시도.
- 기존 공격: 단타, 돌진, 콤보, 점프 내려찍기, HP 조건 자폭. 자폭은 일반 공격과 분리하여 하나만 연결합니다.
- 애니메이션: 클립과 Move 방향 2D 블렌드 트리로 새 컨트롤러를 만들거나, 기존 컨트롤러를 복제합니다. 기존 컨트롤러 모드의 추가 클립 매핑은 없는 상태만 보완합니다.
- AI 몬스터 컨셉: 자연어로 능력치·이동·감지·공격을 함께 재구성하고, 필요한 새 공격은 자동으로 구현합니다.
- 미리보기: 모델 회전·확대, 클립 재생·일시정지·반복 선택·배속·스크럽, 공격 판정 범위. 반복을 끄면 마지막 자세에서 멈추며 다시 재생하면 처음부터 시작합니다. 현재 씬에서 AI나 피해 처리를 실행하지 않습니다.

### 애니메이션과 재질

`Idle`, `Move`, `Groggy` 및 사용하는 공격의 상태명이 필요합니다. `Hit`와 `Die`는 선택 사항입니다. 새 모델 선택 시 이전 클립 연결은 해제됩니다. Generic 클립은 모델의 본 경로가 맞아야 하고, Humanoid 클립에는 Humanoid Avatar가 필요합니다. 모델에 재질이 연결되지 않은 경우에는 재질이 설정된 모델 프리팹을 선택하세요.

원본 Drone에는 전용 Groggy 클립이 없어 초기 매핑은 Idle을 사용하며 안내를 표시합니다. 원본 치명 확률 `50`은 현재 게임 코드에서 100%로 작동하므로 앱은 실제 적용 확률인 100%를 표시합니다. 사용자는 원하는 백분율로 바꿀 수 있고 새 데이터에는 0~1 비율로 저장됩니다. 원본 파일은 수정하지 않습니다. 서로 다른 경직 저항값은 현재 루트 Enemy의 실제 적용값을 기준으로 통일합니다.

Move는 **2D Simple Directional**입니다. 중앙 `(0, 0)`에 정지 클립을 놓고 전후좌우·대각선의 각 방향에 클립 하나씩 배치하세요. 같은 방향에 걷기·달리기를 함께 놓는 방식은 지원하지 않습니다. X/Y 좌표는 로컬 좌우·전후 이동속도(m/s)이며, 클립마다 배속을 지정할 수 있습니다. 원본 Drone의 방향 트리는 전체를 가져옵니다.

X/Y Float 파라미터는 목록에서 선택하거나 새 이름을 입력합니다. 기본값은 `DirX`·`DirY`입니다. 다른 이름을 선택하면 생성 프리팹에 런타임 연결 컴포넌트가 추가되어 실제 이동값을 전달합니다. 파라미터 이름은 서로 달라야 하며 `DirX`와 `DirY`의 축을 뒤바꿀 수 없습니다.

기존 컨트롤러 모드는 원본 Move를 유지합니다. **복제본의 Move 트리 재정의**를 켜면 편집한 트리로 복제본의 Move 모션만 교체하고 전환은 유지합니다. 새로 구성하거나 재정의한 Move는 미리보기의 X/Y 슬라이더와 방향 패드로 실제 블렌딩을 확인할 수 있습니다. 원본 유지 모드의 미리보기는 지정한 보완 클립만 샘플링하며, 원본 상태·전환·트리를 실행하지 않습니다.

### 표시 위치 자동 배치

새 설계의 체력바와 피격 효과는 모델 메시의 실제 크기·회전·배치를 측정해 자동 배치합니다. 체력바는 모델 상단에 최소 0.15m 또는 높이의 8%만큼 여백을 두고, 피격 효과는 모델 중심에 놓습니다. 미리보기의 초록 막대와 하늘색 십자로 위치를 확인하세요. 위치 좌표를 직접 수정하면 해당 항목만 수동으로 전환됩니다. 기존 설계 파일의 좌표는 수동으로 유지됩니다.

### AI 몬스터 컨셉

**AI 몬스터 컨셉**에서 예를 들어 다음처럼 입력합니다.

> 느리지만 단단한 바위 수호자. 좁은 시야를 가지며 가까이 온 적에게 강하게 내려찍고, 멀리 있는 적에게 바위를 던져 공격한다.

템플릿 기본값을 바탕으로 능력치·이동·감지·공격 목록을 다시 구성합니다. 이름·모델·모델 배치·기존 애니메이션 연결·수동 표시 위치는 유지합니다. 자동 표시 위치는 AI가 실측 모델 범위에 맞춰 조정하며 범위를 벗어난 제안은 기본 배치로 보정합니다.

기존 공격으로 표현할 수 있으면 설정을 재사용하고, 적합한 공격이 없거나 일반 공격이 없는 분석 결과라면 자연어 공격 생성 기능으로 보충합니다. 생성 중에는 설계 편집이 잠기며 모든 검증이 끝나면 결과를 한 번에 반영합니다. 실패·취소 시 편집 중 설계는 유지되고, 이미 등록을 마친 공격은 공격 목록에서 다시 사용할 수 있습니다.

이동·감지는 현재 게임의 지상 추적·시야·근접 감지 설정을 사용합니다. 비행·굴파기·새로운 감각기관처럼 새 행동 코드가 필요한 내용은 지원되지 않은 항목으로 표시합니다. 결과의 설정 이유와 안내를 확인하고, 새 공격에 필요한 클립을 연결한 후 **프리팹 생성**을 누르세요.

공격의 `damage`는 고정 피해가 아닌 공격력 배율입니다. 타격 시간은 클립/액션 기준 초이며 공격 속도에 따라 실제 시간이 달라집니다. 현재 게임의 돌진·콤보는 구형 판정만 사용합니다. 점프 및 AI 공격의 궤적은 고정된 전방 목표를 기준으로 한 설명용 미리보기입니다.

## AI 공격 제작

**AI 공격 제작**에서 Codex 연결을 확인하고 만들 공격을 입력합니다. 설치된 Codex의 ChatGPT 로그인을 사용합니다. 실행 파일을 자동으로 찾지 못하면 **실행 파일 선택**을 사용하세요. 별도 API 키를 앱에 저장하지 않습니다. 기본 모델은 사용자 Codex 설정을 따릅니다.

예시:

> 1초 동안 준비한 뒤 플레이어를 향해 탄환 3발을 0.15초 간격으로 발사해줘. 탄환은 벽에 닿으면 사라지고, 패링되거나 공격이 중단되면 모든 탄환을 제거해줘.

기존 공격의 설정으로 가능한 요청은 먼저 해당 공격을 구성합니다. 이 경우 새 코드를 추가하지 않고 검증한 설정값을 적용하며, 자폭 설정은 기존 자폭 슬롯을 갱신합니다. 새 동작이 필요하면 앱이 실제 프로젝트 소스를 제공하여 AI가 공격 SO·실행 클래스·필요한 보조 클래스·설정·미리보기 정보를 생성합니다. 임시 C# 컴파일, 실제 Unity 컴파일, 타입과 설정 검증을 통과한 공격은 자동 등록됩니다. 검증 실패 시 최대 2회 수정하며, 해결되지 않으면 오류와 초안을 남깁니다. AI 제작에는 인터넷과 Codex 사용 가능 상태가 필요합니다.

새 코드는 `Assets/_Project/Scripts/Enemy/Generated/<attackId>/`에 추가됩니다. 기존 Enemy·상태 머신·전투 핵심 클래스는 변경하지 않습니다. 핵심 변경이 필요한 요청은 이유를 안내합니다. 애니메이션·효과 등 아트는 프로젝트 에셋을 선택합니다. 공격이 등록된 뒤 해당 상태에 클립을 연결하세요.

컴파일과 등록 검증은 게임플레이의 모든 경우를 증명하지 않습니다. 새 공격은 실제 게임에서 타격·패링·중단 동작을 확인하세요. 생성 코드의 설정으로 미리보기 메타데이터가 표현하지 못하는 동작은 지원하지 않는다고 표시합니다.

### 오류와 복구

- Unity가 Play Mode·컴파일·에셋 갱신 중이면 작업이 대기하거나 준비 상태를 안내합니다.
- 생성 요청의 응답이 끊기면 요청 ID로 완료 상태를 확인합니다. 같은 프리팹을 자동으로 중복 생성하지 않습니다.
- AI 코드 설치 실패 시 해당 작업이 추가한 파일만 회수합니다. 사용자가 수정한 파일은 보존하고 복구 필요 상태를 알립니다.
- 앱이 수정한 연동 스크립트는 해시로 관리합니다. 사용자가 변경한 연동 파일은 자동 덮어쓰지 않습니다.
- 같은 이름의 Unity 프로젝트가 여러 개 열려 있으면 작업 대상 하나만 열고 다시 연결합니다.
- 앱은 정지한 미리보기에도 15초마다 상태를 갱신합니다. Unity 재시작·연결 끊김으로 세션이 사라지면 이전 이미지를 지우고 **미리보기 시작**을 다시 표시합니다.

프리팹 생성은 씬 배치나 던전 목록 등록을 하지 않습니다. 게임에서 사용할 때는 유효한 NavMesh 위에 배치하고 Player 태그·레이어가 있는 플레이어와 함께 사용하세요.

## 개발 및 검증

Node.js 24에서 실행합니다.

```powershell
npm ci --no-audit --no-fund
npm test
npm run build
npm run test:desktop -- --no-gpu
npm run start
npm run package:win
node scripts/smoke-package.mjs --unity --codex --no-gpu
```

실제 Unity가 열려 있고 연동 설치가 끝난 환경의 검증:

```powershell
npm run test:unity
npx tsx scripts/smoke-preview.ts
npx tsx scripts/smoke-runtime.ts --play
npx tsx scripts/smoke-ai.ts
npx tsx scripts/smoke-features-unity.ts
npx tsx scripts/smoke-concept.ts
```

`test:desktop`은 실제 Electron renderer와 preload에서 필드·배열 편집, 방향 트리 편집, 자동·수동 배치, 컨셉 적용과 편집 잠금, 설계 보존, 재생·반복·연결 복구 및 생성 흐름을 시험하며 Unity·AI 응답은 명시적 모의 데이터입니다. `test:unity`는 실제 Unity에서 임시 프리팹을 생성·검증한 뒤 해당 시험 출력을 정리합니다. `smoke-preview`는 실제 Drone 재질·애니메이션·회전·확대·히트박스와 원본 에셋 보존을 검사하고 연결된 앱 화면을 촬영합니다. `smoke-ai`는 실제 추론을 수행하고 검증된 공격 코드를 샘플로 남깁니다. `smoke-concept`는 실제 추론으로 능력치·이동·감지와 기존 공격을 구성하며 프리팹을 생성하지 않습니다. AI 검사 재실행은 이전 검증 결과를 사용할 수 있으며 `--force`일 때 새 추론을 요청합니다. 결과와 화면은 `artifacts/`에 저장됩니다.

배포 후 `smoke-package`는 실제 패키지 실행 파일·preload·연동 리소스를 확인합니다. `--unity`는 열린 프로젝트의 읽기·미리보기 연결을, `--codex`는 Codex 연결 상태를 확인하며 새 AI 추론은 수행하지 않습니다.

실제로 생성한 탄환 공격의 Play Mode 회귀 검사에서는 1초 준비, 0.15초 간격의 3발 발사, 탄환 이동·3초 수명, 벽 충돌, 몸체 콜라이더 2개에 대한 중복 피해 방지, 총 3회·90 피해, 취소·패링 후 생성 객체 정리를 확인했습니다. Edit Mode와 프리팹 생성 검사도 별도로 실행하며 원본 에셋 해시와 열린 씬 복원 결과를 `artifacts/unity-*-regression.json` 및 `artifacts/unity-scene-restore.json`에 기록합니다.

앱 자체는 다른 백호 앱에 의존하지 않습니다. Unity 어댑터는 현재 프로젝트의 `Assembly-CSharp` 전투 타입에 맞춰져 있으므로 임의의 다른 게임 프로젝트에 대한 범용 지원은 제공하지 않습니다.
