# Auto-3D-Tool / Partsmith — Unity 그래픽 제작

스튜디오 백호 게임개발팀의 업무 자동화 도구. 저장소 `studio-baekho-tools`의 `Auto-3D-Tool` 브랜치에서 개발합니다.

[Notion 개발 기록](https://app.notion.com/p/3f32b4b0fef7818bb2f4e0616387554e): 각 작업 완료 후 문제·원인·수정·검증·남은 작업을 누적합니다.

## 현재 사용 경로 · 0.7.0-preview.42

홈에서 **새 오브젝트 만들기 / 기존 이미지·모델로 시작 / 하던 작업 계속하기**를 선택합니다. 제작실의 오른쪽 안내에서 정확한 원본과 비용을 확인하고 실행한 뒤, 중앙의 결과를 보고 **이 결과 사용**으로 결정합니다. 다음 설정으로 이동해도 다음 제작은 자동으로 시작하지 않습니다.

- 이미지: Codex 네이티브 생성·참고 디자인·수정·변형·장비·방향별 원본. Chrome이 필요하지 않습니다.
- 모델·UV·텍스처: 앱에 저장한 Tripo API 키. Studio 구독과 별도이며 후보 개수만큼 API 비용이 듭니다. 실행 카드와 프로젝트별 누적 승인 한도를 확인합니다.
- 자동 인간형 리깅: 사용자가 설치한 Auto-Rig Pro와 AI 파일로 로컬 실행합니다. 운영체제 화면 조작 없이 처리하며, 설치 확인·원본/방향 선택·실행·결과 사용을 구분합니다. 구매한 애드온과 AI 파일은 배포본에 포함하지 않습니다.
- 파트 조립본의 새 자동 리깅은 조립 당시의 파트 구성을 유지하고 머리카락을 머리 본에 고정합니다. 내보낸 FBX의 파트·UV·재질 할당을 검사하며, 기존 리그를 열었다고 웨이트를 자동 수정하지 않습니다. 실제 다중 파츠 캐릭터의 전체 변형 품질은 별도 확인이 필요합니다.
- 보정·조립·동작: 제한된 로컬 처리와 Blender + Astra 경로가 있습니다. 원본과 클립별 버전을 보존합니다. 측면 영상은 Runway 연결 후 별도 비용 승인으로 생성합니다. ARP 리그의 별도 애니메이션 변환은 검증 전 차단하며, 진단용 자세를 완성 게임 동작으로 표시하지 않습니다.
- 로컬 크기·피벗·FBX 출력·Unity 가져오기: GPT 호출 없이 실행합니다. Unity는 기본적으로 가져오기와 파일 보존만 수행합니다.
- Unity 가져오기 대기 중에는 오른쪽 `Unity 열고 가져오기`로 승인한 프로젝트를 엽니다. 대상 검사 v2는 색공간까지 고정하며 확인된 URP 자동 조명 값 변경을 구분합니다. 이전 대상은 프로젝트를 다시 검사·저장한 뒤 새 전달을 준비합니다.
- 파일 내보내기와 Unity 가져오기 안내를 구분합니다. 자동 리그는 검증된 게임용 FBX를 그대로 내보내고, 함께 제공하는 GLB는 변형 검사용입니다. 자동 리그 이후의 크기·피벗 변경과 GLB만 출력은 현재 지원하지 않습니다.

기존 대검의 생성·재질·Unity 전달, 상자의 선택 평면 복구와 Unity 전달, 인간형 자동 리깅의 검사·제한 보정·명시적 채택과 Unity Humanoid 가져오기를 각각 검증했습니다. Avatar 구조 통과는 모든 관절의 외형 품질이나 애니메이션 리타기팅의 정확한 일치를 보장하지 않습니다.

기존 머리·몸통·머리카락 조립본의 실제 자동 리깅과 Unity 재전달도 앱 버튼으로 확인했습니다. 세 파트·머리카락 Head 연결·원본 UV·크기를 유지했으나 허리 장식의 잘못된 영향과 관절 외형 보정은 남아 있습니다. 진단 GLB와 Unity가 생략하는 미소 웨이트도 별도로 기록하며 원본 웨이트의 완전한 일치로 표시하지 않습니다.

현재 빌드는 전체 기획의 완성본이 아닙니다. 실제 지원 범위와 미검증 항목은 [최신 앱 검증 기록](docs/graphics-studio/12-앱-회귀-검증.md), [평면 복구](docs/graphics-studio/10-정적-평면-복구.md), 앱의 지원 현황에서 확인하세요. 초기 구현 현황 문서의 개수는 현재 완료율로 사용하지 않습니다.

별도 실행 파일: `release/0.7.0-preview.42/win-unpacked/Partsmith.exe` (폴더 전체 필요). 기존 제작 데이터와 키는 기존 프로필에 유지합니다. 실행 중인 작업이 끝난 뒤 앱을 전환하세요. GitHub에는 소스·검증 코드·문서를 저장하며, 로컬 제작 원본·개인 인증 정보·배포 폴더를 올린다는 의미는 아닙니다.

## 기존 제작실 기록 · 0.6.x 이하

아래는 보존된 이전 단계별 제작실의 설명입니다. 새 그래픽 작업 공간의 API/네이티브 경로와 구분합니다.

Windows용 개인 제작 도구 프로토타입. Electron + React + TypeScript + Three.js, SQLite(sql.js), Tripo v3 API, Blender Python, Unity Editor C#으로 구성했습니다.

**단계마다 설정하고 결과를 고르며 수정하는 에셋 제작 도구**입니다. 0.4.0부터 프로젝트 기본 화면은 에셋 제작실입니다. 입력부터 완성까지 자동으로 넘어가지 않으며, 완료된 결과를 사용자가 채택해야 다음 작업을 실행할 수 있습니다. 기존 API 도구는 고급 수동 도구로 유지합니다.

Blender 조립·수정, 리깅, 3D 애니메이션에는 요청한 Codex Astra를 사용합니다. 애니메이션은 **사용자가 확인한 정면·측면·후면 2D 동작 프레임과 타이밍**을 바탕으로 제작합니다. 영상·모션 캡처는 필수가 아니며 프리셋 Idle/Walk로 대신하지 않습니다. 실제 Tripo 유료 생성부터 Unity까지의 전체 캐릭터 품질은 아직 미검증입니다.

## 프로젝트 삭제

0.5.3부터 모든 프로젝트 화면의 각 카드 오른쪽 위 휴지통 버튼으로 삭제할 수 있습니다. 프로젝트 이름을 확인하고 삭제하면 로컬 프로젝트 파일은 Windows 휴지통으로 이동하고 앱 목록과 제작 기록에서 제거됩니다. 실행 중인 작업은 먼저 중지하고 종료를 기다려야 합니다. 외부 원본·백업·Unity 프로젝트·Tripo 웹사이트 모델은 유지됩니다. 휴지통 이동 실패 시 영구 삭제하지 않으며, 앱 내 복원 기능은 제공하지 않습니다.

## 실행

0.6.1은 **이미지 선택 → 전체 모델링**이 기본입니다. 파츠가 필요한 경우에만 분리를 켜고 **정면만 분리** 또는 **멀티뷰 분리**를 선택합니다. 멀티뷰에서는 정면을 기준으로 후면·좌·우를 추가할 수 있습니다. 분리 결과를 확인하고 채택한 다음 모델링을 실행합니다.

컨셉 이미지 수, 분리 이미지의 후보 세트 수, 신규 3D 모델 수를 직접 설정합니다. 분리 1세트는 머리·머리카락·몸통 × 선택 방향 수이며 화면에 총 이미지 수가 표시됩니다. 동작 참조는 기존 키포즈 개수로 조절합니다. 앱의 요청 범위는 1–16개이고 서비스 지원 개수와는 다릅니다. Tripo는 **실제 화면의 생성 개수 옵션**을 사용해 한 번 제출하며, 해당 개수가 없으면 생성 전에 중단합니다. 임의로 개수를 줄이거나 Generate를 여러 번 누르지 않습니다. 기존 모델 리롤은 선택한 모델의 Mesh Edit 결과 1개를 만드는 기존 방식입니다.

앱 내부 도구가 `approval policy is never`로 막히던 문제는 작업자 실행에 한정한 도구별 권한으로 수정했습니다. 전역 Codex 설정·샌드박스·외부 MCP 설정은 바꾸지 않습니다. 호스트의 예산·한 번 제출 기록·로그인 보호는 유지합니다. 이미 ‘제출 확인 필요’로 남은 기록은 자동 생성하지 않습니다. 외부 사이트에서 미제출을 직접 확인했을 때만 해제 버튼으로 새 실행을 허용할 수 있고, 실제 제출 기록이 있으면 해제를 거부합니다.

0.5.4는 파츠마다 한 GPT 작업에서 정면·후면·좌·우의 **독립 원본 네 장**을 받도록 변경했습니다. 잘못 추가했던 ‘4방향 묶음 생성(원본 크기 공유)’ 옵션과 새 2×2 시트 생성은 제거했습니다. 전체 분리는 머리·머리카락·몸통의 세 GPT 작업으로 구성되며 내부 이미지 도구 호출 횟수와는 다릅니다. 중복 문맥·파일 처리·불필요한 도구 연결을 줄이되 GPT 모델·추론·필수 참조 원본·검수 수준은 유지합니다. 없는 방향만 채우거나 한 방향만 수정할 수 있고, 도착한 원본부터 보존합니다. 원본을 자르거나 재인코딩하지 않으며 기존 2048×2048 정렬 사본은 별도로 관리합니다. 과거 시트는 저장 기록과 로컬 검사만 유지하고 자동 재시작하지 않습니다.

0.6.0부터 **새 컨셉·파츠 이미지의 기본 경로는 본인 계정의 ChatGPT 웹 채팅**입니다. 제작실에서 **ChatGPT 연결**을 눌러 앱 전용 브라우저에 로그인하고 **ChatGPT 상태 확인** 후 생성합니다. Codex나 다른 브라우저의 로그인은 자동으로 공유하지 않습니다. 앱이 선택한 참조 원본과 생성 지시를 전달하고 실제 이미지 뷰어에서 원본을 다운로드해 기존 검토·리롤·정렬 흐름으로 가져옵니다. 0.6.1부터 개수·분리·방향은 위 설정을 따릅니다. 다른 생성 경로로 자동 전환하지 않으며, 기존 **GPT · Codex 내장**은 명시적으로 선택할 수 있습니다. 저장된 작업은 원래 연결을 유지합니다. 동작 참조 및 Blender/Astra 단계는 기존 경로를 유지합니다.

0.6.2는 ChatGPT 인증 팝업에서 추가 인증 창을 열 수 있도록 수정했습니다. 부모·인증 창은 같은 앱 세션을 사용하며, 임시 빈 창도 이후 인증 주소를 검사합니다. 제작실에 로딩·로그인 대기·연결 완료·실패를 표시하고 **다시 연결**로 실패한 로딩을 재시도합니다. 로그인 후 상태만 확인하며 생성이나 중단된 작업을 자동 실행하지 않습니다. 차단·실패 진단에서 인증 쿼리와 토큰을 제외합니다. Google이 `disallowed_useragent`로 거부하면 현재 내장 창 방식은 지원되지 않는다고 표시합니다. 브라우저 위장·쿠키 복사로 우회하지 않으며 외부 브라우저 연결은 별도 개발이 필요합니다. 실제 계정의 Google 로그인 성공은 사용자 확인이 필요합니다.

0.6.3은 실제 Google 버튼이 사용하는 `/auth/login_with`가 허용 목록에서 빠져 `BLOCKED_NAVIGATION`으로 멈추던 문제를 수정합니다. 해당 경로만 인증용으로 허용하며 작업자의 조작 가능 범위는 넓히지 않습니다. 실제 페이지 이동은 통과했으나 격리 테스트의 후속 인증 요청은 HTTP 403으로 거부됐습니다. 로그인 시작 요청의 HTTP/네트워크 실패도 앱에 표시하며 자동으로 재시도하지 않습니다. **이 수정은 실제 계정의 로그인 성공을 보장하지 않습니다.**

ChatGPT 웹 모델 설정과 Codex 조작 작업자의 모델·추론 설정을 낮추지 않습니다. 전송 전에 한 번의 요청을 기록하며 불명확한 전송·복구에서는 새 요청을 보내지 않습니다. 중간에 인증이 만료돼 전송하지 못했다면 로그인 후 기존 사진을 기준으로 새 누락 방향 요청을 실행합니다. 로그인·CAPTCHA는 사용자가 직접 처리합니다. 실제 생성 속도·토큰 절감·외형 품질은 새 실생성으로 검증하지 않았습니다. Windows 폴더 빌드 경로는 `release/0.6.3/win-unpacked/Partsmith.exe`입니다. 이전 앱을 닫고 새 파일을 실행하면 기존 사용자 저장소를 사용합니다. 폴더 전체가 필요하며 코드 서명·설치 프로그램은 제공하지 않는 로컬 테스트 빌드입니다. 버전별 실제 검증 범위는 [검증 기록](docs/VERIFICATION.md)을 확인하세요.

```powershell
cd 'C:\Users\김민준\Desktop\3D tool'
npm ci
npm run dev
```

```powershell
npm run build
npm start
npm test
npm run test:ui
node scripts/data-smoke.mjs
npm run package
```

`npm run dev`는 로컬 Vite와 Electron을 함께 실행합니다. Node 24.15.0에서 확인했습니다. `npm start`는 사전 빌드가 필요합니다. 설치한 패키지는 이 작업 폴더에만 있습니다.

## 가장 빠른 로컬 테스트

1. **새 프로젝트 → 로컬 데모 테스트 프로젝트**를 선택합니다.
2. **리깅 · 애니메이션 → 로컬 데모 리깅 실행**을 누릅니다. Blender가 마네킹, 뼈대, Idle·Walk를 실제로 생성하고 GLB·FBX·blend를 내보냅니다.
3. 뷰포트에서 동작을 선택하고 재생합니다. 데모는 절차적 마네킹이며 AI 생성물이 아닙니다.
4. **Unity로 보내기**에서 `C:\Unity\3D Tool Test`를 지정합니다.
5. **Unity 브리지 설치** 후 Unity 창을 활성화하여 스크립트 컴파일을 기다립니다. **Unity에 임포트**하면 실제 결과가 앱에 반환됩니다.
6. 임포트 후 미저장 씬이 없으면 전용 씬으로 잠시 Play Mode에 진입해 각 클립을 자동 검사하고 원래 씬으로 돌아옵니다. 미저장 씬이 있으면 검사를 건너뛰고 앱에 이유를 표시합니다. Unity 메뉴 **Tools → Partsmith → Play latest test scene**으로 변형을 직접 확인할 수도 있습니다.

## 단계별 에셋 제작실

1. **이미지**: 기존 GPT 이미지 생성(기본) 또는 Tripo를 선택하고 프롬프트를 입력합니다. 실제 이미지 후보 네 장 중 하나를 채택하거나 기존 정면 이미지를 가져옵니다.
2. **파츠 모델**: 머리·머리카락·몸통 각각 정면·후면·좌측·우측을 만들고 총 12장을 먼저 검토합니다. 파츠와 방향을 지정해 프롬프트로 수정·리롤하거나 기존 사진은 유지하고 없는 사진만 채울 수 있습니다. 채택한 네 방향을 Tripo Studio Smart Mesh P2에 넣어 파츠 모델 하나를 만들고 검토·채택합니다. 기존 모델은 Tripo의 Mesh Edit(부분 재생성)에서 전체 또는 지정 영역을 리롤합니다. 새 모델 생성으로 대체하지 않으며 이전 버전을 보존합니다. 수정 횟수·비용은 실제 화면에서 확인하고, 지원하지 않는 프롬프트를 적용한 것처럼 진행하지 않습니다. 실제 화면의 멀티뷰·한 개 생성·폴리곤 설정·비용을 확인하며 지원하지 않는 설정으로 몰래 바꾸지 않습니다.
3. **UV · 텍스처**: 채택한 세 파츠에 Smart UV와 텍스처를 적용합니다. 결과를 확인하고 필요한 파츠만 프롬프트로 수정·리롤할 수 있습니다. 설정한 이번 단계 예산 안에서 실행하고 결과를 채택합니다.
4. **조립 · 수정**: Blender + Astra가 원본 이미지 비율에 맞춰 조립합니다. 실제 오브젝트 목록에서 대상 또는 전체를 고르고 자연어로 반복 수정합니다. 이전 버전과 비교하고 되돌릴 수 있습니다.
5. **리깅**: Blender + Astra가 기본 몸체 리그를 만들고, 옷·머리카락·기타 실제 오브젝트에 추가 뼈대 토글을 제공합니다. OFF인 오브젝트도 몸체를 따릅니다. Unity 물리 시뮬레이션을 추가하는 토글은 아닙니다.
6. **애니메이션**: 동작별로 정면·측면·후면의 동기화된 2D 동작 참조 한 세트를 만들고 먼저 검토·채택합니다. 방향별 핵심 프레임은 3~12장으로 설정하며 총 생성 이미지 수를 표시합니다. 이는 모든 FPS 프레임을 렌더한 영상이 아닌 동작 포즈 참조이며, FPS는 이후 3D 애니메이션 타이밍에 사용합니다. 그다음 Astra가 해당 프레임을 보고 Blender 포즈·키프레임을 작성합니다. 결과를 보고 다시 수정할 수 있습니다.
7. **Unity**: 채택한 모델·리그·클립을 내보내고 연결한 Unity 프로젝트에서 검증합니다.

앱을 켜 두어야 작업자가 실행됩니다. 완료 후 다음 단계가 자동 시작되지 않습니다. 상위 입력을 바꾸면 이전 결과 파일은 보존하고 그 입력에 의존하는 선택을 해제합니다. 기존 자동 제작 기록은 조회·복구용으로 남기며 자동 실행을 다시 시작하지 않습니다.

0.4.1은 현재 단계 안에서 일시적인 연결·다운로드 오류와 결과 파일 문제를 2초·5초·10초 간격으로 최대 3회 복구합니다. 직전 오류와 저장된 파일을 전달하며, 시작한 하위 작업의 복구에서는 새 이미지 생성과 새 Studio 과금 제출을 차단합니다. 아직 시작하지 않은 하위 작업만 원래 승인 범위대로 진행합니다. 로그인·CAPTCHA·불명확한 결제·추가 생성이 필요한 품질 문제는 이유를 표시하고 멈춥니다. 취소하거나 앱을 닫은 작업은 자동으로 다시 시작하지 않습니다.

머리·머리카락·몸통 분리는 파츠·방향마다 별도 이미지로 생성하고 성공한 사진부터 저장합니다. 모델 결과는 Tripo 화면 사진을 먼저 보여주고 **3D로 돌려보기**로 실제 모델을 확인합니다. 읽을 수 있는 GLB는 직접 표시하고, FBX·압축 메시 등 변환이 필요한 경우에만 Blender를 사용합니다. 과거 여러 후보로 만든 작업 기록은 남기지만 새 모델 생성 수는 하나입니다.

분리 사진은 준비된 방향부터 표시합니다. 원본 대비 크기·위치·가장자리·외형 차이는 경고로 남기고 자동 복구로 붙잡지 않습니다. 새 작업의 12장이 모두 준비되면 사용자가 사진과 경고를 보고 수정하거나 채택합니다. 파일 누락·손상·경로 이탈·중복 등 실제 파일 검사는 유지합니다. 중지된 작업은 **저장된 사진 보기**로 이미 있는 파츠만 불러올 수 있습니다. 이 버튼은 새 생성 요청을 보내지 않습니다. 과거 버전의 방향 정보 없는 사진은 정면으로만 취급하며, **없는 사진만 채우기**는 기존 사진을 보존하고 부족한 방향을 새로 생성하는 별도 실행입니다.

Codex는 기존 ChatGPT 로그인을 사용하는 로컬 CLI로 실행하며 계정 사용량이 소모됩니다. 앱은 인증 토큰을 읽거나 복사하지 않습니다. Studio는 별도 브라우저에서 직접 로그인합니다. 유료 작업은 이번 단계의 범위·상한을 확인한 뒤 실행하며, 불명확한 제출은 자동 재시도하지 않습니다. 멈춤은 이미 제출된 원격 과금을 취소하지 않습니다.

Windows에서 BOM이 포함된 JSON 보고서 때문에 정상 생성 결과가 거절되던 오류를 수정했습니다. 기존 분리 결과 복구와 새 작업의 결과 재검사는 파일을 재사용하며 생성 요청을 보내지 않습니다. 파일·구조 검사 통과와 사람이 만족하는 외형·동작 품질은 별도로 확인해야 합니다.

## 수동 도구 · 문제 해결

- **연결 설정**: 마스킹 입력, DPAPI 암호화 저장, 키 교체·삭제, 연결·API 잔액 확인. 보안 저장을 사용할 수 없으면 세션 한정으로 처리합니다.
- **Tripo 작업실 → 모델 생성**: Smart Mesh P2 Preview / P1 / HD, 텍스트·이미지·멀티뷰 입력, 삼각면·P2 사각면, 폴리곤 수·UV·텍스처·PBR을 설정해 모델 하나를 만듭니다. P2는 공식 v3 문서 지원이며 이 계정의 실제 생성 권한은 미검증입니다. 다른 모델로 자동 변경하거나 재결제하지 않습니다.
- **Tripo 후처리**: 메시 분할·스마트 분할·분할 부위 보완·리토폴로지·UV 패킹·텍스처·리깅·Idle/Walk·형식 변환을 원격 요청합니다. **Smart UV 영역은 공개 API에서 확인한 UV 패킹 범위**이며 Studio 전체 기능과 동일하지 않습니다.
- **결과 보관함**: 결과 선택·3D 재생·파츠 후보 적용·후속 Tripo 처리·Unity용 출력을 지원합니다. FBX 원본은 보존하고 Blender로 미리보기 GLB를 별도로 만듭니다. ZIP/OBJ/STL/USDZ/3MF 등은 원본 보관까지 지원하며 내장 미리보기나 바로 다음 단계 입력은 제한됩니다.
- **이미지 스튜디오**: 프롬프트, 모델·해상도·후보 수 선택, 유료 요청 검토, 생성 후보 선택, 선택 이미지를 추가 프롬프트로 수정, 이전 후보로 복귀. PNG/JPEG 가져오기도 지원합니다.
- **파츠 준비**: 전체 원본을 유지하고 드래그 crop 또는 클릭 다각형 마스크로 파츠 PNG를 만듭니다. 잘라낸 파츠는 가려진 면 복원 필요 상태로 표시됩니다.
- **조립 작업실**: 파츠별 이미지→3D 요청, 여러 후보 비교·선택·고정, 특정 파츠 재생성, GLB 가져오기, 숨기기·분리 보기, 변환 조작기와 수치 입력, 조합 저장·복원.
- **Blender로 조립**: 현재 표시 파츠를 같은 상대 배치로 가져와 목표 키에 균일 정규화하고 GLB·FBX·blend로 출력합니다. 오브젝트의 표면을 용접하지 않습니다. 변환·후보 변경 시 이전 출력은 오래된 버전으로 처리합니다.
- **리깅**: 최종 조립 GLB에 대한 Tripo 검사 → 리깅 → Idle/Walk 요청을 각각 검토·승인합니다. 모델 선택에서 완료된 결과를 고른 후 **Unity용 FBX로 변환**합니다. `.blend` 수동 보정 후 내보낸 GLB를 새 후보로 가져오는 경로도 제공합니다.
- **Unity**: FBX·텍스처 가져오기, URP 재질, Humanoid Avatar 검사, Animator Controller, 관리 Prefab, 사용자 Prefab Variant, 전용 테스트 씬, 재생 평가와 경고 반환.

## 데이터와 보안

실제 저장 경로는 **연결 설정 → 프로젝트 저장소**에 표시됩니다. 일반 실행은 Electron의 사용자 데이터 폴더를 사용합니다.

```text
userData/
  workbench.db                 SQLite 인덱스·프로젝트·작업·승인 기록
  tripo.key                    Windows DPAPI 암호화 데이터만
  projects/<UUID>/
    project.json               저장 형식 v1; 키 없음
    assets/<UUID>.*            Tripo 원본·수정본·파츠·후보
    previews/<ID>/model.glb    FBX 원본과 분리한 미리보기
    builds/<UUID>/             FBX, GLB, blend, textures, 검사 보고서
    workbench/<UUID>/          단계 설정·선택·버전, 작업별 불변 산출물
    production/<UUID>/         이전 자동 제작 입력·산출물·작업 이력
```

프로젝트 상단 다운로드 버튼은 폴더 전체를 별도 위치에 백업합니다. **프로젝트 열기**로 백업의 `project.json`을 복원할 수 있습니다. 같은 UUID가 이미 열려 있으면 중복 복원 대신 기존 목록을 사용합니다.

자동 제작 이력도 입력 사본·검증된 산출물·해시를 확인해 보관용으로 복원합니다. 가져온 백업의 편집 가능한 JSON을 원격 실행 승인으로 취급하지 않으므로 해당 실행은 중단 상태로 열립니다. 원격 Studio 로그인·비용 장부는 프로젝트 백업에 포함되지 않으며, 백업에서 자동으로 원격 작업을 재개하지 않습니다.

Electron은 `nodeIntegration: false`, `contextIsolation: true`, `sandbox: true`를 사용합니다. preload에 제한된 명령 인터페이스만 노출합니다. 생성 URL·API 키는 renderer에 직접 전달하지 않고 결과를 프로젝트 안에 내려받습니다. 로컬 파일 프로토콜은 등록된 프로젝트 에셋만 제공합니다.

## 개발 디렉터리

```text
src/                         React UI, Three.js 뷰포트, 수동 마스크
shared/                      버전 1 명령·데이터 타입, 문서 기반 모델 목록
engine/                      SQLite, 제작 작업, Tripo, Blender·Unity 로컬 어댑터
electron/                    제한된 IPC, 파일 대화상자, DPAPI 키 저장
integrations/blender/        headless Python 처리
integrations/unity/Editor/   프로젝트에 설치하는 Editor 브리지
tests/                       승인·과금 중복 방지·복구 회귀 테스트
scripts/                     빌드·Electron/데이터/Unity 검증
artifacts/                   검증 보고서와 화면 캡처
```

기본 통합·번들 플러그인 설정은 변경하지 않았고 사용자 추가 blender/fal_ai/notion MCP도 활성화하지 않았습니다. Unity 검증용 CLI 바이너리는 `artifacts/runtime/tools`에 별도로 받아 체크섬을 검증했으며, 테스트 Unity 프로젝트에 `com.unity.pipeline`을 추가했습니다. 앱 자체는 이 CLI나 MCP 없이 Editor 브리지로 작동합니다.
