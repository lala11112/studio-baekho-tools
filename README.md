# Baekho Map Forge

스튜디오 백호의 **Windows 데스크톱 맵 프리팹 제작 앱**입니다. 3인칭 3D 로그라이크에서 서로 이어 붙일 맵 모듈을 만들고, 기존 Unity 프리팹으로 조립합니다. Codex로 입체 설계도와 배치를 생성한 뒤 높이·계단·연결문·사용 에셋을 직접 편집합니다. 각 사용자의 Codex와 ChatGPT 로그인을 사용하며 별도 API 키는 필요 없습니다.

## 0.3.1: 바닥 두께와 오브젝트 높이 맞춤

Unity 가져오기에서 **바닥 윗면을 셀 높이에, 벽·문·소품 아랫면을 같은 높이에** 맞춥니다. 원본 프리팹의 피벗이 중앙에 있어도 바닥과 오브젝트가 겹치지 않도록 실제 경계를 측정합니다. 바닥 두께는 **셀 간격 × 12% × 두께 배율 Y**입니다. 기본 셀 간격 2m와 배율 1에서는 0.24m이며, 바닥 윗면 아래로 두께를 확보합니다. Y 오프셋은 이 기준면을 추가로 이동합니다. 계단의 저단 기준점과 오름폭 계산은 유지합니다.

이미 저장한 맵은 새 앱에서 `.baekho.json`을 열어 **Unity 내보내기**를 다시 실행하세요. 새 ZIP의 두 스크립트와 JSON을 Unity에 업데이트한 뒤 **Build Prefab**으로 프리팹을 다시 생성해야 적용됩니다. 기존 프로젝트의 배율·오프셋 값은 바꾸지 않습니다. 이전 내보내기 JSON은 이전 배치 방식을 유지합니다.

## 서로 연결할 맵 만들기

시작 S와 끝 E가 있는 단일 맵 대신 **여러 개의 외부 연결문을 가진 모듈**을 만듭니다. 연결문 개수는 AI 생성 전에 1~16개로 지정하고, 편집 중에도 추가·삭제할 수 있습니다. 끝방은 연결문 하나만 둘 수도 있습니다.

- **연결문:** 이름, 바깥 방향, 폭, 통과 높이, 연결 종류(kind)를 지정합니다. 연결점의 Y는 해당 셀 바닥 높이입니다.
- **여러 에셋:** 고정 5개 슬롯 대신 사용자가 추가·삭제하는 목록입니다. 바닥·벽·문·소품·계단별로 여러 프리팹을 등록할 수 있고, 전체 최대 256개입니다.
- **셀별 선택:** 같은 종류의 에셋은 등록 순서로 자동 순환합니다. 셀 편집에서 특정 에셋을 지정하면 그 선택이 우선합니다. 에셋 삭제 시 해당 셀 지정은 자동 순환으로 돌아가며 Undo로 복원할 수 있습니다.
- **Unity 연결점:** 프리팹의 Connections/<id>에 BaekhoMapConnection 컴포넌트가 저장됩니다. 위치·외향 회전과 id/label/kind/width/height를 게임의 맵 조립기에 사용할 수 있습니다.

이 도구는 개별 모듈과 연결문을 제작합니다. 모듈 사이 복도 생성이나 여러 맵을 자동 배치하는 런타임 조립기는 포함하지 않습니다.

## 다른 PC에서 실행

배포 파일은 **release/Baekho-Map-Forge-0.3.1-Windows.exe**입니다. Windows x64 PC에 EXE 하나만 전달하면 됩니다. Node.js나 이 저장소는 실행에 필요하지 않습니다.

1. 해당 PC에 이미지 생성을 지원하는 Codex를 설치하고 자기 ChatGPT 계정으로 로그인합니다.
2. 앱 상단 **Codex 연결**에서 상태를 확인합니다. 설치된 Codex 앱을 먼저 찾고, 없으면 PATH와 npm의 native 실행 파일을 찾습니다. 자동으로 찾지 못하면 **실행 파일 선택**으로 codex.exe를 지정합니다.
3. 로그인이나 업데이트가 필요하면 연결 창 안내에 따릅니다. 생성에는 인터넷과 계정의 Codex 이용 권한·사용 한도가 필요합니다.

실행 경로 설정은 각 PC에만 저장합니다. 개발자의 인증 정보와 Codex 실행 파일은 배포에 포함하지 않습니다. Windows 짧은 경로의 ~ 문자 때문에 정상 요청을 차단하던 0.2.0 오류도 수정되어 있습니다. 이전 앱을 닫고 새 EXE를 실행하세요.

## 제작 순서

1. **맵 컨셉**, 가로·세로 셀 수, 셀 간격, 기본 고저차, AI로 만들 연결문 개수를 입력합니다.
2. **AI 설계도 생성**으로 단상·계단·외부 연결문이 보이는 이미지를 생성합니다.
3. **설계도 분석 → 배치 만들기**로 높이와 연결문을 추출합니다. 모든 내부 통행 셀과 연결문의 높이·계단 연결성을 검사합니다. 실패하면 원본 이미지를 유지하여 다시 분석할 수 있습니다.
4. **3D 미리보기** 또는 **배치 편집**에서 셀을 선택합니다. 셀 종류, Y 높이, 계단 상승 방향과 오름폭을 직접 수정합니다. 격자에서는 타일·높이 브러시로 드래그할 수 있습니다.
5. 외곽 셀을 선택하고 **이 셀을 연결문으로**를 누릅니다. **연결문** 탭에서 전체 목록을 선택해 편집할 수도 있습니다. 새 연결문은 D 타일이 되며 문 프리팹이 적용됩니다.
6. **에셋 → Unity 프로젝트 폴더 연결**에서 Assets와 ProjectSettings가 있는 프로젝트를 선택합니다. 원하는 종류와 프리팹을 골라 **에셋 추가**를 누릅니다. 같은 종류를 여러 번 추가할 수 있습니다.
7. 등록한 에셋의 이름·배율·오프셋·Y 회전을 조절합니다. 바닥의 **두께 배율 Y**는 셀 간격의 12%인 기본 두께에 곱해집니다. 바닥 윗면과 벽·문·소품 아랫면은 셀 높이에 자동으로 맞추며 Y 오프셋으로 추가 조정합니다. 계단은 원본의 Y 배율 1에서 측정한 오름폭을 입력하면 셀 오름폭에 맞춰 Y 배율을 자동 계산합니다.
8. 특정 셀에 특정 프리팹을 쓰려면 **셀 편집 → 이 셀의 에셋**에서 선택합니다. 예를 들어 문 셀의 바닥과 문 프리팹을 각각 지정할 수 있습니다.
9. **저장**으로 .baekho.json을 보관하고, **Unity 내보내기**로 ZIP을 만듭니다. Undo/Redo와 Ctrl+Z/Ctrl+Shift+Z는 연결문·셀 지정·에셋 목록 변경도 복원합니다.

Codex에 연결하지 않아도 샘플 편집, 저장, 에셋 연결과 내보내기를 사용할 수 있습니다. 샘플은 AI 생성 결과로 표시하지 않습니다. Unity 원본 에셋 파일은 AI 요청에 보내지 않습니다.

## 연결문 규칙

문 셀의 **바깥쪽 경계 중앙**이 연결점이며, 바닥의 Y 높이를 사용합니다. 로컬 +Z가 맵 바깥을 향합니다. 북/동/남/서 방향은 각각 Y 회전 0/90/180/270도입니다.

- 바깥쪽은 맵 밖 또는 맵 외부까지 이어진 빈 공간이어야 합니다. 방 안에 갇힌 빈 구멍은 외부로 인정하지 않습니다.
- 반대쪽은 방 내부의 통행 가능한 셀이어야 하고, 높이가 허용 단차 이내여야 합니다. 계단 측면으로 연결할 수 없습니다.
- 모든 연결문과 내부 통행 셀은 높이를 고려해 하나로 연결되어야 합니다. 내보내기에는 연결문이 최소 한 개 필요합니다.
- 폭은 0.25m부터 셀 간격까지, 통과 높이는 0.25~20m입니다. 이는 연결 규격입니다. 원본 문 메시의 크기와 충돌체는 에셋 배율 및 Unity에서 맞춥니다.
- 연결점은 문 프리팹 오프셋·추가 회전과 독립적으로 유지합니다. 문 프리팹은 경계 중앙에 사용자의 오프셋과 Y 회전을 더해 배치합니다.

게임의 맵 조립기에서는 호환되는 kind·폭·높이를 고른 뒤 두 연결점의 위치를 일치시키고 바깥 방향이 서로 마주 보도록 모듈을 회전·이동할 수 있습니다. 방끼리 겹치는지 확인하는 처리는 게임 쪽에서 구현해야 합니다.

## Unity에 가져오기

1. ZIP을 풀고 **두 스크립트를 모두** 원본 에셋이 있는 Unity 프로젝트에 복사합니다.
   - Unity/Editor/BaekhoMapImporter.cs → Assets/Baekho/Editor/BaekhoMapImporter.cs
   - Unity/Runtime/BaekhoMapConnection.cs → Assets/Baekho/Runtime/BaekhoMapConnection.cs
2. 기존 설치가 있으면 같은 위치의 파일을 업데이트합니다. 다른 폴더에 중복 설치하지 마세요. Runtime 스크립트는 Editor 폴더에 넣지 않습니다.
3. Map.baekhomap.json을 Assets 아래로 복사하고 컴파일 완료 후 선택합니다.
4. **Assets → Baekho → Build Prefab**을 실행합니다. JSON 옆에 맵 프리팹이 생성되고 Connections 자식에 연결점들이 포함됩니다.

기존 파일을 덮어쓰지 않고 새 이름으로 저장하며 현재 편집 중인 씬은 변경하지 않습니다. 프리팹은 GUID로 참조하고 중첩 프리팹 연결을 유지합니다. 원본 에셋과 .meta를 유지해야 합니다. ZIP에는 원본 에셋의 복사본이 들어 있지 않습니다.

다른 PC에서 .baekho.json을 열면 원본 에셋이 있는 **그 PC의 Unity 프로젝트를 다시 연결**해야 내보낼 수 있습니다. 같은 파일과 .meta를 공유하면 GUID를 유지할 수 있습니다.

상세 내용은 [Unity 가져오기 안내](unity-importer/README.md)를 참고하세요. Unity 6.3 (6000.3.10f1)에서 네이티브 프리팹과 연결점 저장을 검증했습니다.

## 맵 규격과 기존 파일

| 항목 | 규격 |
| --- | --- |
| 격자 | 가로·세로 8~40셀, 셀 간격 0.25~10m |
| 좌표 | 중앙 원점, X 좌우 / Y 높이 / Z 앞뒤. 첫 행은 +Z |
| 높이 | 셀 바닥 −100~100m, 계단 오름폭 0.25~10m |
| 타일 | _ 빈 공간, . 바닥, # 벽, D 문, P 장애 소품, R 계단 |
| 벽 | 한 셀을 차지하는 블록형 벽 |
| 통행 | 상하좌우 높이 연결 검사. 소품 P는 장애물 |
| 계단 | 낮은 쪽과 높은 쪽만 연결. 원본은 낮은 바닥 Y=0에서 +Z로 상승 |
| 자동 에셋 선택 | (row × 맵 가로 + x) % 해당 종류의 에셋 수. 등록 순서 기준 |
| 파일 형식 | 프로젝트 map.version 3, Unity 내보내기 schemaVersion 3 |

한 X/Z 셀에 바닥 높이는 하나입니다. 다리 아래 통로 같은 겹친 층이나 자유형 메시 편집은 지원하지 않습니다. **3D 미리보기는 구조 확인용 블록아웃**이며 실제 Unity 메시·머티리얼·에셋 배율은 Unity 결과에서 확인합니다. 미리보기 받침 기둥은 높이 표현용이며 내보내지 않습니다.

경로 검사는 단차와 계단 방향을 기준으로 하며 캐릭터 충돌·머리 위 여유·실제 계단 경사·NavMesh를 시뮬레이션하지 않습니다. 콜라이더·게임 컴포넌트는 원본 프리팹을 사용합니다.

이전 map.version 1/2 프로젝트를 열면 높이·계단·설계도·프리팹 연결을 보존해 버전 3으로 바꿉니다. **기존 S/E는 바닥으로 전환하고 외부 연결문은 새로 지정**합니다. 방 안에 있던 시작·끝 지점을 임의의 외부 문으로 만들지 않습니다. 이전 API 모델 설정도 Codex 기본 모델 설정으로 옮깁니다. 기존 내보내기 schemaVersion 1/2는 Unity 가져오기 어댑터에서 이전 위치·배율 의미를 그대로 지원합니다. 바닥 두께·높이 맞춤은 새로 내보낸 schemaVersion 3에 적용됩니다.

## 개발 실행과 검증

Node.js 22.12 이상에서 실행합니다.

```powershell
npm install
npm run dev
npm test
npm run build
npm run test:desktop
npm run package:win
npm run test:packaged
npm run test:portable
```

- 단위 테스트: 연결문 외향·높이·외부 빈 공간, 계단 경로, 여러 에셋·셀 지정, 저장·마이그레이션, Codex 통신·실패·취소, GUID·ZIP 검증.
- Electron 테스트: 실제 UI에서 셀·연결문 편집, 다중 에셋 추가·삭제와 Undo, 셀 지정, 저장·재열기, ZIP 내보내기.
- 배포 테스트: 실제 outer EXE를 격리된 임시 경로에서 실행하여 Codex 연결과 앱 버전을 확인합니다. 로그인된 Codex가 필요합니다.
- Unity 테스트: 격리 프로젝트에서 네 방향·높이가 다른 연결점, 런타임 컴포넌트 직렬화, 실제 프리팹 배치, 중첩 참조와 씬 보존을 확인합니다.

일반 자동 테스트는 로그인 변경이나 AI 생성을 하지 않습니다. 2026-10-12에 별도 검증으로 Codex CLI 0.162.0-alpha.17.2에서 0.3의 이미지 생성 1회와 배치 분석 1회를 실행했습니다. 8×8 모듈에서 서쪽 0m·동쪽 2m 외부 연결문 2개와 동쪽 상승 계단 1개를 추출했고 모든 경로 검증을 통과했습니다. 단위 테스트 96개, 실제 Electron 편집·저장·내보내기, JS→ZIP→Unity 프리팹, 실제 0.3.0 배포 EXE의 Codex 연결도 확인했습니다.

0.3.1의 높이·두께 수정은 단위 테스트 96개, Electron의 두께 배율 편집·저장·내보내기, Unity 6.3의 표면 정렬·이전 형식 호환성 검증 137개를 통과했습니다. 실제 앱의 ZIP으로 209개 오브젝트와 연결점 4개를 생성하여 바닥 두께·윗면 높이·계단·원본 프리팹 참조를 1,269개 항목으로 확인했습니다.

연동은 로컬 Codex App Server의 표준 입력·출력 JSON-RPC를 사용합니다. 인증 파일은 Codex가 관리하며 맵 프로젝트나 EXE에 인증 정보를 넣지 않습니다. 참고: [Codex CLI](https://developers.openai.com/codex/cli), [Codex App Server](https://developers.openai.com/codex/app-server).
