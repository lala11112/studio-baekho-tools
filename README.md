# studio-baekho-tools
스튜디오 백호 게임개발팀의 업무 자동화 도구

## AutoHitTimer

애니메이션에서 공격 판정 구간·콤보 전환·공격 종료 시점을 제안하고 사인검의 공격 ScriptableObject에 기록하는 Windows 데스크톱 도구입니다.

**자연어로 비슷한 애니메이션 찾기·파일 드롭 → Unity 두 시점 촬영 → AI 분석(Codex 또는 Claude Code) → 타임라인 검토 → 원본 적용 또는 복사 저장**

### 시스템 문서

저장소의 [시스템 문서](docs/SYSTEMS.md)는 현재 구현의 구조·사용 흐름·AI 분석·Unity 촬영·공격 데이터 매핑·저장 복구를 글과 6개의 다이어그램으로 설명합니다. [그림을 포함한 HTML 문서](docs/SYSTEMS.html)는 브라우저에서 읽거나 인쇄할 수 있습니다. 기준일은 2026년 11월 4일이며 구현된 기능과 남은 검증 범위를 구분했습니다.

### 실행

필요 환경: Windows, Unity **6000.3.10f1**에서 컴파일 가능한 사인검 프로젝트, 로그인한 **Codex CLI 또는 Claude Code CLI** 중 하나. 별도 API 키 입력은 없습니다.

#### AI 엔진 선택

앱 상단 오른쪽의 AI 엔진 목록에서 고릅니다. 선택은 앱 설정에 저장됩니다.

| 선택 | 동작 |
| --- | --- |
| AI 자동 선택 (기본) | 로그인된 Codex를 우선 사용하고, 없으면 로그인된 Claude Code를 사용합니다. |
| Codex | 기존 Codex 인증과 `~/.codex/config.toml`의 최상위 `model`을 사용합니다. |
| Claude Code | 기존 Claude Code 인증(구독 로그인 또는 `ANTHROPIC_API_KEY`)을 사용합니다. 모델은 `ANTHROPIC_MODEL` 또는 `~/.claude/settings.json`의 `model`을 따르며, 없으면 Claude Code 기본 모델입니다. |

Claude Code는 [네이티브 설치](https://docs.claude.com/en/docs/claude-code/setup)로 `claude.exe`가 PATH 또는 `%USERPROFILE%\.local\bin`에 있어야 합니다(npm으로 설치한 `claude.cmd`는 사용하지 않습니다). 로그인은 터미널에서 `claude auth login`으로 합니다.

두 엔진 모두 도구·웹 검색·MCP·사용자 훅 없이 임시 폴더에서 실행하며, 촬영 이미지와 클립 메타데이터만 전달하고 JSON 스키마로 응답을 검증합니다. Claude Code는 `--setting-sources ""`로 사용자·프로젝트 설정을 읽지 않으므로, `settings.json`의 `env`나 `apiKeyHelper`로만 인증하는 환경은 해당 값을 환경 변수로 설정해야 합니다. Claude Code는 촬영 이미지를 요청에 직접 포함하므로 한 번의 요청에 들어가는 이미지 총량이 약 24MB를 넘으면 분석 구간을 줄이라는 오류를 표시합니다.

```powershell
cd Apps/AutoHitTimer
pnpm install
pnpm start
```

배포용 앱 생성:

```powershell
pnpm package:win
```

결과는 `Apps/AutoHitTimer/dist/0.3.0/AutoHitTimer-win32-x64/AutoHitTimer.exe`입니다. **UnityIntegration 폴더를 포함한 전체 배포 폴더**를 복사하세요. 이전 버전이 실행 중이면 종료한 뒤 새 버전을 실행하세요. 0.3.0의 종료 시간 저장에는 연결 모듈 업데이트도 필요합니다. 앱에서 **연결 모듈 설치 / 복구** 후 Unity 컴파일을 마치고 목록을 새로고침하세요.

### Unity 연결

1. 사인검 프로젝트를 Unity에서 열고 컴파일 오류를 해결합니다. 플레이 모드를 종료합니다.
2. 앱에서 프로젝트 루트를 선택하고 **연결 모듈 설치**를 누릅니다. 또는 저장소 루트에서 아래 설치 스크립트를 실행합니다.
3. Unity로 돌아가 파일을 새로고침합니다. 부트스트랩이 Package Manager API로 `com.studiobaekho.auto-hit-timer`와 Newtonsoft JSON 의존성을 설치하고 사인검 어댑터를 복사합니다.
4. 컴파일이 끝나면 앱에서 목록을 새로고침하고, **저장된 열린 장면의 Animator**와 무기를 선택합니다. 캐릭터가 여러 개면 직접 선택합니다.

```powershell
./scripts/Install-AutoHitTimer.ps1 -UnityProject 'C:/path/to/Four-Tiger-Sword'
```

설치 경로는 프로젝트의 `AutoHitTimerIntegration`과 `Assets/StudioBaekho/AutoHitTimer*`입니다. 기존 패키지 의존성은 제거하지 않습니다. 설치 결과는 `Library/AutoHitTimerInstallResult.json`에 기록합니다. 다른 게임에는 별도 어댑터가 필요합니다.

현재 `feature/AutoHitTimer` 브랜치는 다른 자동화 도구를 포함하지 않습니다. 게임 프로젝트가 기존 Combat Lab의 로컬 패키지를 참조한다면 그 패키지가 실제 존재하는 경로를 유지해야 합니다. 이 도구의 설치가 누락된 다른 패키지를 대신 복구하지는 않습니다.

### 사용 방법

- **원하는 동작으로 찾기**에서 “앞으로 돌진하며 검을 두 번 휘두르는 공격”, “검으로 짧게 찌르기, 회전 베기와 활 제외”처럼 설명합니다. 선택한 AI 엔진이 프로젝트의 클립 이름·경로·Animator 상태명·길이를 한국어 설명과 비교하고, 관련 후보를 최대 20개까지 추천 이유와 함께 정렬합니다. 결과에서 선택한 클립을 작업 목록에 추가합니다.
- 자연어 검색은 이름과 메타데이터를 통한 추정입니다. 검색 단계에서 모든 클립의 영상을 분석하지 않으므로 `Take 001`처럼 정보가 부족한 이름은 정확하게 찾기 어렵습니다. 실제 동작은 추가 후 촬영·미리보기로 확인합니다. 검색에는 선택한 엔진(Codex 또는 Claude Code)의 기존 로그인과 사용 한도를 사용하며 위 메타데이터와 검색어가 AI에 전달됩니다.
- 후보가 많으면 목록을 페이지별로 읽고 160개씩 비교한 뒤 추천 후보를 다시 비교합니다. 진행 상태를 표시하며 **검색 취소**로 중단할 수 있습니다. 관련 후보가 없거나 AI 연결·인증에 실패하면 이유를 표시합니다. **이름으로 찾기**는 AI 없이 클립명·상태명·경로를 검색합니다. 기존 연결 모듈의 결과가 잘리면 **Unity 연동 업데이트** 후 Unity 새로고침을 실행하세요.
- `.fbx`/`.anim` 파일을 놓아 가져올 수도 있습니다. 같은 이름과 FBX 안의 여러 클립은 결과 목록에서 선택합니다. 외부 파일은 프로젝트의 도구용 Imports 폴더에 복사하여 가져옵니다.
- 외부 FBX의 Rig가 선택한 캐릭터와 맞지 않으면 이유를 표시합니다. Unity에서 해당 파일의 Rig/Avatar 설정을 맞춘 뒤 다시 검색하세요.
- 여러 클립을 작업 목록에 넣고 순차 분석합니다. 전체 동작은 24fps, 후보 경계는 60fps로 촬영합니다. 긴 클립은 촬영과 AI 입력을 나눠 처리합니다. 클립은 최대 120초, 프로젝트당 작업은 최대 300개입니다.
- 두 시점이 나란히 있는 프레임을 재생·저속 재생하고 타임라인의 시작·종료 경계를 수정합니다. **Space**는 재생, **←/→**는 촬영 프레임 이동입니다. 구간을 직접 추가·삭제할 수 있습니다.
- 히트 분석 뒤 전체 동작에서 **다음 콤보 전환**과 **공격 종료**를 분석합니다. 마지막 타격을 보존하며 자연스럽게 연결·복귀할 시점을 추천하고, 후보 주변을 60fps로 재확인합니다. 현재값과 AI 추천값을 비교한 뒤 **추천값 적용**, 마커 드래그 또는 숫자 입력으로 보정하세요. 콤보 전환은 일반 콤보 공격에서 사용하며, 스킬·궁극기 단계는 공격 종료에 다음 단계로 진행합니다. 원본 클립은 종료 마커 뒤까지 계속 재생해 잘리는 동작을 확인할 수 있습니다.
- 불확실하거나 판단 불가인 추천은 직접 설정합니다. 전환 분석만 실패해도 완료한 히트 분석과 직접 편집한 값은 보존됩니다. 재분석은 추천만 갱신하며 기존 시간 편집을 덮어쓰지 않습니다. 대상 공격·템플릿을 변경하면 시간 편집은 초기화하고 해당 클립의 추천은 다시 적용할 수 있습니다.
- 기존 공격 보정에서는 SO와 공격 단계를 선택하고, 각 후보를 어느 기존 타격에 연결할지 확인합니다. 기존 타격을 연결하면 해당 데미지·피드백을 유지합니다. 새 타격은 공격 기본값을 상속하며, 타수 증가로 총 피해가 늘 수 있습니다.
- **기존 공격 수정**에서는 분석한 클립으로 기존 클립을 교체하거나 빠진 클립을 연결할 수 있습니다. 같은 클립이면 기존 공격 종료 시간을 유지하며, 새 공격·클립 교체에서는 클립 길이를 기본값으로 사용합니다. 직접 편집하거나 채택한 종료 시간이 우선합니다. **히트·전환**에서 콤보·종료를, **공격 시간 설정**에서 이동·타겟 접근/회전·트레일·슬래시 시간을 수정합니다. 종료가 히트를 자르거나 사용 중인 시간 설정보다 빠르면 저장 전에 수정해야 합니다. 마지막 히트보다 이른 수동 콤보 전환은 남은 히트가 생략될 수 있다는 경고를 검토하고 저장할 수 있습니다. 상태 이름·Animator 전환과 타격별 데미지·피드백은 유지합니다. 원본을 수정하려면 **복사본에 저장**을 해제하세요. 클립 변경을 복사 저장하면 SO와 Controller를 함께 복사합니다.
- 새 공격 등록에서는 폼·공격 종류·기존 템플릿을 고릅니다. 길이를 벗어나는 템플릿 시간 설정은 화면에서 수정합니다. Animator 기본 레이어에 고유한 상태와 SO 공격 단계를 함께 만듭니다.
- 검토 완료를 표시하고 변경 내용·타수·피해 변화를 확인한 다음 저장합니다. **복사 저장이 기본값**입니다. 새 공격의 복사 저장에서는 SO와 Controller를 함께 복사하며, 결과 에셋을 게임에 연결하는 작업은 사용자가 수행합니다.

### 지원 범위

| 공격 | 지원 |
| --- | --- |
| 모든 폼 일반 콤보, 공중 착지 마무리, 반격 | 보정·신규 등록 |
| 화·금 폼 스킬 | 보정·신규 등록 |
| 금 폼 궁극기 | 보정·신규 등록 |
| 수 폼 강공격·스킬·궁극기, 목·토 특수 스킬, 버프 궁극기 | 사유 표시, 저장 제외 |

시간은 **공격 속도 배율 적용 전 초**입니다. 단일 클립, 상태 속도 1, 오프셋 0을 지원합니다. Blend Tree, Override Controller, 동적 속도·시간 파라미터, 미러링, 연속 단계의 동일 상태 재사용은 적용하지 않습니다. Humanoid는 유효한 Avatar, Generic은 맞는 바인딩 계층이 필요합니다.

AI는 시각적인 공격 활성 구간을 제안합니다. 실제 충돌 판정이나 게임 플레이를 측정하지 않으며, 60fps 촬영은 정확도 보장이 아닙니다. 가려지거나 애매한 동작·타격 없는 동작은 검토 상태로 남습니다. AI에 실제 촬영 이미지와 클립 정보가 전달됩니다.

### 저장·복구

- 분석 완료가 저장을 의미하지 않습니다. 확인한 결과만 Unity API로 저장합니다.
- 원본 SO·Controller·클립의 변경을 검사하여 오래된 결과 적용을 막습니다. 기존 타격의 데미지와 피드백은 유지하고 신규 타격의 `Damage`와 `PoiseDamage`는 0으로 설정해 기본값을 상속합니다.
- Unity Undo와 변경 전 스냅샷을 제공합니다. 저장 중 중단된 경우 **Tools → Studio Baekho → Auto Hit Timer → Recover Interrupted Save** 메뉴로 복구합니다. 불확실한 저장 요청은 자동 재전송하지 않습니다.
- 앱은 저장 요청 ID를 먼저 기록합니다. 재시작 후 브리지 응답과 어댑터 저장 저널을 조회해 완료·미실행·롤백·복구 필요를 구분하며, 결과가 불확실한 작업은 편집과 재분석을 잠급니다.
- 초안·작업 목록은 `%APPDATA%/StudioBaekho/AutoHitTimer`에 프로젝트별로 보존합니다. 이전 분석은 최대 5개 버전으로 기록합니다. 앱을 다시 열어도 중단된 분석을 자동 재실행하지 않습니다.
- 이펙트 편집 버전에서 만든 초안도 기존 타격 작업과 미확정 저장 기록을 유지하여 읽습니다. 변환 전 원본은 프로젝트 초안 옆의 `.effects-v2-backup` 파일로 보존합니다. 이펙트 편집 기능은 제공하지 않습니다.
- 촬영 파일과 브리지 기록은 프로젝트 `Library/AutoHitTimerBridge`에 있습니다. Library를 삭제하면 촬영 프레임을 다시 만들어야 합니다. 원본 에셋과 최종 저장 결과는 Assets에 남습니다.

### 구조와 검증

- `Apps/AutoHitTimer`: Electron 화면, 프로젝트 연결, 분석 큐, Codex·Claude Code 이미지 분석(`src/ai.cjs`의 `AiRouter`), 초안 보존.
- `Packages/com.studiobaekho.auto-hit-timer`: Editor 전용 브리지, 검색·임포트, 게임 스크립트를 실행하지 않는 렌더 계층 촬영.
- `Integrations/FourTigerSword/AutoHitTimer`: 게임별 SO 매핑·변경 검토·등록·저장 및 회귀 시험.

브리지는 `Library/AutoHitTimerBridge/requests → processing → responses` 파일 mailbox를 사용합니다. 요청 ID, 만료 시간, 처리 영수증을 보존하며 UI에는 파일 시스템 권한을 노출하지 않습니다. 기존 Combat Lab과 실행·설정·통신 경로가 분리되어 있습니다.

```powershell
cd Apps/AutoHitTimer
pnpm test       # 시간 변환, 매핑 검증, 큐·검토·초안·통신 단위 시험
```
