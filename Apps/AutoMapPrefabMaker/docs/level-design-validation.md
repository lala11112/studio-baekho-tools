로그인된 Codex 런타임 `0.162.0-alpha.17.2`의 기본 모델로 **실제 이미지 생성 2회와 이미지 기반 배치 추출 2회**를 실행했습니다. 두 사례 모두 첫 요청에서 통과했습니다. 재시도, 고정된 모의 응답, 수동 지형 수정, 요청 수량 감소는 사용하지 않았습니다.

재현 명령은 `npx tsx scripts/smoke-level-design-ai.ts`입니다. 이 명령은 로그인된 계정으로 실제 AI 요청을 보냅니다. 일반 단위 테스트에는 포함되지 않습니다. 같은 시드는 치수·패턴·로컬 선택을 재현하며 AI 이미지와 지형의 동일성을 보장하지 않습니다.

생성된 PNG를 직접 확인했습니다. 전투방 이미지는 넓은 중앙 평지, 측면 2m 단상과 계단, 두 외부 문, 떨어진 소품을 보여 주며 추출된 격자가 이 공간 구성을 유지합니다. 상점 이미지는 하나의 문과 연속된 평지를 보여 줍니다. 상인은 지형 추출 후 로컬 배치 규칙으로 추가했습니다.

소품 카탈로그는 치수 1×1×1m인 상자·통 두 종류의 **합성 테스트 메타데이터**를 사용했습니다. 실제 Unity 원본 에셋은 AI에 전송하지 않았으며 이 두 생성 결과를 게임의 실제 프리팹과 컨트롤러로 실행한 것은 아닙니다. 전투방의 세 소품은 해당 시드의 가중 선택 결과 모두 통을 선택했습니다. 이미지에 보이는 상자·통의 외형이 최종 프리팹 종류를 고정하지는 않습니다. 최종 선택은 저장된 `bindingId`로 고정됩니다.

## 남긴 실행 증거

검증 파일은 저장소에서 무시되는 `.local/level-design-ai-smoke/run-1791962763162/` 아래에 있습니다.

- `results.json`: 두 사례의 최종 결과와 측정값.
- `small/`, `shop/`의 `request.json`: 확정된 설정과 같은 카탈로그 스냅샷.
- 각 사례의 `blueprint.png`, `raw-layout.json`, `map.baekho.json`, `result.json`: 실제 이미지, 원시 지형 추출, 편집 가능한 결과, 검증 내역.

실행 결과는 사용자 프로젝트를 교체하거나 Unity 씬을 변경하지 않습니다. 연결된 실제 게임에서의 재미, 적 AI, 문틀·가구 메시 충돌, 카메라 시야는 이 실행만으로 확인하지 않았습니다.

## 실제 게임 컨트롤러에서 남은 확인

1. 두 전투방 문에서 각각 진입해 적과 충돌하기 전 시야와 접근 여유를 확인합니다.
2. 표시된 교전 위치에서 네 방향으로 3m 회피를 수행하고 콜라이더·애니메이션 이동량과 비교합니다.
3. 2m 단상까지 계단을 오르고 내려오며 최대 경사와 발판 높이를 확인합니다.
4. 상인 상호작용 거리와 카메라 시야가 통행을 방해하지 않는지 확인합니다.
5. 우회형과 고저차형, 낭떠러지·데드존, 보스방은 별도의 실제 AI 생성 및 플레이테스트가 필요합니다. 관련 규칙과 구조는 단위·Unity 검사 대상이지만 이번 두 AI 사례에는 포함하지 않았습니다.

문헌 근거와 자동 검사 범위는 [레벨디자인 규칙과 검증 근거](level-design-principles.md)를 참고하세요.

## v0.5.1 구조·전술 소품 회귀 확인

`node scripts/smoke-v051.mjs`를 실제 Electron 0.5.1 빌드에서 실행해 **87개 검사와 저장·ZIP 내용 비교를 통과**했습니다. 렌더러 오류는 없었습니다. 40×40셀에 측정된 장애 소품 6개를 배치하는 로컬 연산은 최종 패키지용 빌드에서 **79ms**였습니다. 같은 40×40셀·소품 6개 조건에서 카탈로그를 256개 변형으로 늘린 별도 검사는 95ms였습니다(`.local/v051-catalog-performance.json`). 이는 해당 기기의 합성 사례 측정값이며 최대 부하 전체의 성능 보장은 아닙니다. `--source-only`를 붙이면 Electron을 열지 않고 구조·배치 검사만 실행합니다.

- 12×12셀 지형에서 높이 0·2·4m의 단상, 계단·경사로, 내부 구덩이를 검사했습니다. 단차면과 절벽면의 위쪽은 실제 바닥 아랫면에 닿고 아래쪽은 원래 하단과 해당 구조물의 명시적 보정을 유지합니다. 바닥 Y 배율 2.5와 Y 보정 0.2m인 셀도 포함해, 아랫면 `4 + 0.2 − 2 × 0.12 × 2.5 = 3.6m`를 확인했습니다. 저장된 지형 높이와 구조 원본 범위는 내보내기로 바뀌지 않았습니다.
- 계단·경사로 내보내기는 `surface: bottom`을 사용하며, 하단 Y와 소스 높이 대비 상승 높이 배율을 보존했습니다. 실제 원본 메시의 바닥 중심 정렬은 별도 Unity 검사 대상입니다.
- 18×16셀 전투방의 대칭적인 소품 의도 4개를 비대칭 위치의 소품 4개로 배치했습니다. 상자·가구·바위의 크기와 배율·회전·보정을 적용하고, 라이브러리 순서를 뒤집어도 같은 시드의 결과가 같음을 확인했습니다. 각 소품에는 서로 다른 양쪽 우회 경로와 양수의 추가 이동 거리가 있었으며, 진입·필수 경로·회피 공간 검사 오류는 없었습니다.
- 편집기의 소품 우회 항목을 누르면 해당 인스턴스가 선택되고 경로 표시가 켜졌습니다. 청록색 우회 경로와 회피 공간이 보이는 미리보기를 직접 확인했습니다. 저장과 실제 ZIP 내보내기의 구조 데이터는 사전에 검사한 데이터와 일치했습니다.

이 회귀 스크립트의 소품 치수와 프리팹 파일은 합성 테스트 자료입니다. 실제 프리팹이나 게임 컨트롤러를 실행한 결과로 해석하지 않습니다. 증거는 `.local/v051-smoke/`의 `tactical-evidence.json`, `geometry-preview.png`, `tactics-preview.png`, `tactics-selected-obstacle.png`, 저장 프로젝트와 ZIP입니다. 프리팹의 위치 보정은 명시적인 물리 배치 수정이며, 지형 높이나 다른 물체의 부착 높이를 자동으로 바꾸는 설정은 아닙니다.

별도 실제 Unity 실행에서는 치우친 계단 원점 검사 255개, 앱의 v4 내보내기 검사 1,679개, v5 내보내기 검사 1,739개를 통과했습니다. 바닥 두께와 위치 보정이 있는 원본 에셋에서 지지면과 바닥 아랫면이 실제로 맞닿는지 독립적으로 측정했습니다.

현재 크기 카탈로그에는 비균일 배율의 Sphere/Capsule Collider에 대한 제한이 남아 있습니다. 자식 배율 `(1,2,3)`의 반경 0.5 구체는 카탈로그 크기가 `(1,2,3)`이지만 실제 Unity Collider 경계는 `(3,3,3)`이었습니다. 같은 배율의 Y축 캡슐(반경 0.5, 높이 2)은 카탈로그 `(1,4,3)`, 실제 `(3,4,3)`입니다. 검사 기록은 `.local/bounds-probe-result.txt`입니다. 이런 소스의 실제 물리 경계까지 카탈로그가 보장하지는 않으며, 이번 계단·지지면 수정에서 해당 측정 방식을 변경하지 않았습니다.

### 이전 실제 AI 지형에 새 로컬 배치 규칙 적용

앞서 실제 AI로 생성한 소형 전투방의 지형에 v0.5.1 로컬 생성 처리를 다시 적용했습니다. **새 AI 요청은 보내지 않았습니다.** 이전 결과의 통 3개는 `(4,2)`, `(2,3)`, `(8,7)`에 모두 0°로 놓여 있었습니다. 재처리 결과는 상자 `(3,7)` 0°, 통 `(2,3)` 0°, 상자 `(5,7)` 90°이며 요청 수량 3개를 유지했습니다. 지도·생성 조건·레벨디자인 오류는 없었고, 세 물체 모두 양쪽 우회 경로가 확인됐습니다. 기록은 `.local/v051-ai-reprocess.json`입니다. 이는 이전 AI 지형에 새 생성 규칙을 적용한 검사이며, 기존 저장 맵을 열 때 자동으로 소품을 재배치한다는 의미는 아닙니다.
