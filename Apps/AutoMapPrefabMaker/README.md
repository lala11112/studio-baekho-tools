# Baekho Map Forge

스튜디오 백호의 **Windows 데스크톱 맵 프리팹 제작 앱**입니다. 3인칭 3D 로그라이크의 방 모듈을 만들고 기존 Unity 프리팹으로 조립합니다. 사용자의 Codex와 ChatGPT 로그인을 사용하며 별도 API 키는 필요 없습니다.

## 0.5.1: 바닥 접합·계단 기준점·소품 동선

- 단차 벽과 낭떠러지 벽의 윗끝을 높은 바닥 타일의 **아랫면**까지 내립니다. 바닥의 Y 배율·높이 보정·셀별 에셋을 반영하고 벽면 하단은 유지합니다. 미리보기와 Unity 내보내기가 같은 치수를 사용합니다.
- 새로 내보내는 계단·경사로는 프리팹에서 측정한 **아랫면 중심**을 기준으로 배치합니다. 원본 피벗이 중심이거나 치우쳐 있어도 바닥에 맞추고, 지정한 오름폭과 사용자 위치 보정을 유지합니다.
- 새 소품 자동 배치는 교전 공간 주변에서 장애물 양쪽으로 돌아가는 동선을 평가합니다. 좌우 대칭, 같은 종류·방향 반복을 줄이며 입구·필수 경로·회피 공간과 요청 수량을 보존합니다. 검토 화면에서 소품의 두 우회 경로를 확인할 수 있습니다. 기존 저장된 소품은 다시 배치하지 않습니다.

## 0.5.0: 방 규격·레벨디자인·소품 라이브러리

- 새 생성은 중형 전투방 규격을 기본으로 시작합니다. 소형·중형·대형·보스·시작·보상·상점 규격은 각 축을 2셀 단위로 선택하며 직접 치수를 입력하면 사용자 지정으로 전환합니다. 생성용 셀 간격과 현재 맵의 셀 간격 편집은 별개입니다.
- 이미지와 배치 분석에 동일한 로컬 설계안을 전달합니다. 캐릭터 반경·회피 거리, 모든 입구의 접근 여유, 평지 교전 공간, 우회로와 고지 접근로를 검사합니다. 후보에는 확정된 크기·시드·설계 패턴을 저장하고 실제 통행 면적을 표시합니다.
- 자동 천장은 계단의 높은 끝과 다리 상판을 포함한 **최고 바닥 + 여유 높이**를 따릅니다. 문 위·양옆과 바닥 단차의 틈을 채우며 내부 구덩이에 데드존 또는 마감 바닥을 배치합니다. 수동·잠금 높이는 보존합니다.
- 소품을 역할·종류·프리팹으로 구분하고 테마, 원본 크기, 통행 방해, 배치 위치, 방 용도와 가중치를 설정합니다. Unity의 소품 크기 내보내기를 가져오거나 직접 치수를 입력합니다. 크기 없는 소품은 공간 검사형 자동 배치에서 제외하며 선택된 프리팹은 인스턴스에 고정합니다.

| 규격 | 각 축 범위 | 셀 간격 2m의 외곽 크기 | 기본 구성 | 연결문 |
| --- | --- | --- | --- | --- |
| 소형 전투방 | 10~12셀 | 20~24m | 적 4, 보상 1 | 2 |
| 중형 전투방 | 14~18셀 | 28~36m | 적 6, 보상 2 | 4 |
| 대형 전투방 | 22~26셀 | 44~52m | 적 10, 보상 3 | 4 |
| 보스방 | 22~26셀 | 44~52m | 보스 1, 보상 1 | 1 |
| 시작방 | 8~10셀 | 16~20m | 안전한 준비 공간 | 1 |
| 보상방 | 8~10셀 | 16~20m | 보상 4 | 1 |
| 상점방 | 10~12셀 | 20~24m | 상인 1 | 1 |

규격과 캐릭터 높이 2m·반경 0.4m·회피 거리 3m는 조정 가능한 프로젝트 초기값입니다. 시작·보상·상점방의 위험 요소는 기본으로 꺼집니다. 자동 검사는 플레이 감각을 대신하지 않습니다. 참고한 공개 문헌, 검사 규칙과 실제 게임 확인 항목은 [레벨디자인 규칙과 검증 근거](docs/level-design-principles.md)에 정리했습니다.

## 0.4.1: 후보 비교와 배치 보정

- **여러 후보 생성**: 한 번에 2~8개를 요청하고, 후보 비교 화면에서 구조와 3D를 확인해 선택한 맵만 저장합니다.
- **낭떠러지 위 천장**: 내부 빈 공간 위에도 천장을 이어 만들며, 기존 맵에는 천장 보정 도구를 적용할 수 있습니다.
- **에셋 배율 일괄 조정**: 건축 타일 전체·모든 에셋·종류별로 X/Y/Z를 지정하거나 현재 배율에 곱합니다. 1m 에셋의 X/Z를 현재 셀 간격에 맞추는 버튼도 제공합니다.
- **여러 셀에 걸친 연결문**: 문 폭을 늘리면 실제 개구부 셀이 함께 열리고 넓은 문 프리팹 하나를 내보냅니다.
- **천장 형광등·발광 벽**: 천장용·벽용 프리팹을 따로 지정하고, 한쪽에 몰리지 않도록 공간 전체에 조명을 분산합니다. 기존 맵의 조명만 다시 배치할 수도 있습니다.

## 방 구조와 배치 도구

생성 조건을 고른 뒤 **조건으로 맵 생성**으로 설계도 이미지부터 배치까지 만듭니다. 방 크기·용도 프리셋과 개별 토글을 제공합니다. 맵 사이 통로·복도 생성과 통로 프리셋은 포함하지 않습니다.

| 구분 | 생성·편집 기능 |
| --- | --- |
| 지형 | 높낮이·계단, 경사로, 다리의 개수·상판 높이, 낭떠러지의 개수·크기·깊이 |
| 건축물 | 평천장, 부분 천장 제거, 셀별 벽 높이, 난간·기둥·아치 |
| 조명·장식 | 천장 형광등·발광 벽 패널의 분산 배치, 장애 소품, 장식·식생, 물 |
| 게임 요소 | 적·보상·이벤트 지점, 용암·독늪·함정, 잠금문과 연결 스위치, 비밀문, 휴식처·상인·제단 |
| 영역 편집 | 선택·복사·회전·대칭·붙여넣기, 높이 일괄 편집, 잠금, 전투·보상·휴식 구역, 선택 영역 재생성 |
| 제작 보조 | 내 템플릿, 두 맵 연결 비교, 캐릭터 크기 표시, 자동 복구, 오류 위치 선택, Undo/Redo |

생성 토글은 다음 생성에 적용됩니다. AI가 요청한 다리·높이·낭떠러지 조건을 충족하지 못하면 실패를 표시하고 기존 맵을 유지합니다. 천장과 벽 높이, 조명·게임 지점 등의 추가 배치는 검증된 지형에 로컬 규칙으로 적용합니다. 요청한 개수를 배치할 공간이 부족해도 기존 맵을 유지합니다.

조명은 **사용자가 연결한 조명 프리팹의 설정**을 사용하며 새 Unity Light를 생성하지 않습니다. 게임 지점과 스위치의 연결 정보는 내보내지만 적 생성·피해·보상 지급·문 개폐 등의 게임 동작은 Unity에서 연결합니다. 물과 위험 바닥은 프리팹 배치입니다.

## 다른 PC에서 실행

배포 파일은 **release/Baekho-Map-Forge-0.5.1-Windows.exe**입니다. Windows x64 PC에 EXE 하나를 전달하면 됩니다. Node.js나 이 저장소는 실행에 필요하지 않습니다.

1. 해당 PC에 이미지 생성을 지원하는 Codex를 설치하고 자신의 ChatGPT 계정으로 로그인합니다.
2. 앱 상단 **Codex 연결**에서 상태를 확인합니다. 자동 검색에 실패하면 **실행 파일 선택**으로 codex.exe를 지정합니다.
3. 로그인이나 업데이트가 필요하면 연결 창 안내에 따릅니다. 생성에는 인터넷과 계정의 Codex 이용 권한·사용 한도가 필요합니다.

Codex 실행 경로는 각 PC에만 저장합니다. 인증 정보나 Codex 실행 파일을 배포에 포함하지 않습니다. 이전 앱을 닫고 새 EXE를 실행하세요. AI 연결 없이도 샘플 편집·저장·에셋 연결·내보내기를 사용할 수 있습니다.

## 제작 순서

1. 방 프리셋과 토글을 선택합니다. 맵 설명, 격자 크기·간격, 연결문 수, 높이·개수·밀도를 조정합니다.
2. **조건으로 맵 생성**을 실행합니다. 설계도 생성 → 배치 분석 → 생성 조건·이동 경로 검증을 통과하면 새 맵을 적용합니다. 고급 도구에서 이미지와 배치 분석을 따로 실행할 수도 있습니다.
3. **3D 미리보기**에서 구조를 확인합니다. 천장·배치물·게임 지점·캐릭터 크기 표시를 전환할 수 있습니다. 천장은 실내 편집을 위해 기본적으로 숨깁니다.
4. **배치 편집**에서 셀을 선택하고 타일·높이·계단 상승 방향을 편집합니다. 셀 편집에서 천장과 벽 높이, 다리 방향, 계단/경사로를 지정합니다.
5. **영역·배치**에서 Shift + 셀 선택 또는 가로·세로 입력으로 영역을 정합니다. 복사한 영역은 회전·대칭 후 붙일 수 있습니다. 잠긴 셀은 일괄 수정과 부분 재생성에서 보존됩니다.
6. 조명·구조물·게임 지점을 설치하고 방향·보정값·부착 기준·연결 대상을 편집합니다. 게임 지점은 표시 이름과 게임 연결 키도 지정합니다.
7. **에셋 → Unity 프로젝트 폴더 연결**로 Assets와 ProjectSettings가 있는 프로젝트를 선택합니다. 역할별 기존 프리팹을 추가하고 이름·배율·오프셋·회전을 조절합니다. 같은 역할을 여러 개 등록할 수 있습니다.
8. **저장**으로 .baekho.json을 보관하고 **Unity 내보내기**로 ZIP을 만듭니다. 사용 중인 역할의 프리팹이 없거나 맵 구조에 오류가 있으면 내보내기 전에 수정해야 합니다.

실패한 설계도 초안은 현재 맵과 별도로 저장합니다. 다시 분석하면 이미지를 재생성하지 않습니다. 취소 후 늦게 도착한 응답은 맵에 적용하지 않습니다. 부분 재생성 재시도는 최초 선택 영역을 유지하고 밖의 셀·잠금·외부 연결문을 보존합니다. 구역 용도는 해당 영역의 자동 배치를 유도합니다. 부분 재생성은 큰 지도에서 높이·연결 정보가 요청 길이 한도를 넘으면 실행 전에 안내합니다.

내 템플릿은 조건·에셋 목록과 선택 영역을 이 PC에 보관합니다. 불러온 영역은 직접 붙여넣습니다. 다른 PC에서 사용하려면 프로젝트 파일과 같은 GUID의 Unity 에셋을 전달하세요. 편집 변경은 잠시 후 자동 복구 파일에 저장되며 재실행 시 복구할 수 있습니다. 자동 복구와 별도로 작업 파일을 저장하는 것이 좋습니다.

## 여러 후보를 만들고 골라 저장하기

1. 생성 조건과 에셋을 설정하고 **한 번에 비교할 맵 후보**를 2~8개로 지정합니다. **여러 후보 생성**을 누르면 각 후보의 설계도와 배치를 순서대로 생성합니다. 후보마다 AI 요청을 보내므로 한 개 생성보다 시간과 Codex 사용량이 늘어납니다.
2. **후보 비교**에서 각 배치의 평면도·3D·설계도를 확인합니다. 기존 편집 맵은 후보 생성 중 그대로 유지됩니다. 후보는 생성 시작 당시 조건과 에셋 설정을 보관합니다.
3. 보관할 후보를 체크하고 **선택한 N개 저장**을 누릅니다. ZIP을 풀면 번호가 붙은 `.baekho.json` 파일이 나옵니다. 각 파일을 **프로젝트 열기**로 불러와 편집하고 Unity용으로 내보낼 수 있습니다.
4. **이 맵 편집하기**은 해당 후보를 현재 편집 화면에 적용합니다. 이전 작업은 되돌리기로 복원할 수 있습니다.

후보별로 공간 배치를 다르게 요청하고, 완전히 동일한 지형이 반환되면 중복으로 표시합니다. AI 결과의 차이를 보장하지는 않으며 비슷한 구조가 나올 수 있습니다. 실패한 후보는 이유를 표시하고 나머지를 계속 생성합니다. 취소하면 이미 완성된 후보는 남고, 진행 중이거나 대기 중인 후보는 중단됩니다. 후보 목록은 앱 실행 중에만 유지되므로 보관할 맵은 파일로 저장하세요. 새 후보 묶음을 만들 때 저장하지 않은 후보가 있으면 교체 전에 안내합니다.

## 에셋 크기와 조명 보정

**에셋 → 에셋 배율 일괄 조정**에서 대상·적용 방식·축별 값을 정합니다. 빈 축은 유지합니다. **1m 에셋 X/Z → 셀 맞춤**은 원본 가로·깊이가 1m인 타일을 전제로 X/Z를 셀 간격으로 설정하고 Y는 유지합니다. 예를 들어 2m 셀에는 X=2, Z=2를 적용합니다. 새 건축 타일도 이 배율을 기본값으로 사용합니다. 기존 저장 파일의 배율은 임의로 바꾸지 않습니다. 같은 바인딩을 공유하는 잠긴 셀에도 배율 변경이 적용됩니다.

바닥·천장의 Y는 두께 배율이며 높이를 지정한 벽·계단·절벽·연결문은 해당 높이에 맞춰집니다. 전체 프리팹 크기나 피벗이 1m 기준과 다르면 배율과 오프셋을 추가로 조정하세요.

조명 생성 위치는 **자동 / 천장 / 벽 / 천장+벽**을 선택합니다. 자동은 천장이 있으면 형광등, 없으면 실내를 향하는 벽 패널을 사용합니다. 에셋 카드의 **조명 사용 위치**에서 천장용·벽용 프리팹을 구분합니다. 벽 프리팹은 +Z가 발광면을 향하게 만들고, 실제 광원·Emission 머티리얼은 Unity 프리팹에서 설정합니다. **영역·배치 → 천장과 조명 보정**에서 기존 낭떠러지 위 천장을 채우거나 조명 배치만 다시 계산할 수 있습니다.

## 다리·낭떠러지·천장 규칙

- 한 X/Z 셀에는 통행 높이가 하나입니다. 다리는 상판만 배치하고 아래는 빈 공간입니다. 다리 아래 통행이나 겹친 층을 만들지 않습니다.
- 다리는 직선 축의 양 끝만 이동할 수 있습니다. 양옆은 빈 공간이며 접속 높이가 맞아야 합니다. 여러 다리 셀을 이어 길이를 만듭니다.
- 낭떠러지는 다리 아래까지 이어지는 내부 빈 구역으로 계산합니다. 최저 둘레 바닥에서 설정 깊이를 뺀 동일한 하단까지 절벽면을 연결하고 데드존 또는 마감 바닥을 둡니다. 하부는 추가 통행층이 아닙니다.
- 자동 평천장은 내부 낭떠러지의 빈 셀 위에도 이어지며 외부 빈 공간은 제외합니다. 계단의 높은 끝을 포함한 최고 통행면 위에 여유 높이를 더합니다. 벽은 그 천장까지 맞춥니다. 수동으로 천장을 부분 제거하거나 높이를 바꿀 수 있습니다.
- 천장은 캐릭터 머리 위 여유와 연결문 통과 높이를 검사합니다. 바닥·벽·천장에 붙인 시설은 해당 기준면을 따라갑니다.
- 바닥 윗면은 셀 높이에, 벽·문·소품 아랫면은 기준 높이에 맞춥니다. 바닥 두께는 셀 간격 × 12% × 두께 배율 Y입니다. 사용자 Y 오프셋은 정렬된 기준면을 이동합니다.
- 계단·경사로는 낮은 바닥 Y=0에서 +Z로 상승하는 프리팹을 사용합니다. 원본 오름폭을 입력하면 셀 오름폭에 맞춰 Y 배율을 자동 계산합니다.

## 연결문과 두 맵 비교

연결문은 이름·바깥 방향·폭·통과 높이·연결 종류(kind)를 가집니다. AI 생성에서는 1~16개를 지정하고 편집 중 추가·삭제할 수 있습니다. 연결점은 전체 문 폭의 바깥쪽 경계 중앙이며 문 셀들의 공통 바닥 높이를 사용합니다. 북/동/남/서 방향은 Y 회전 0/90/180/270도입니다.

- 바깥쪽은 맵 밖 또는 외부로 이어지는 빈 공간이어야 합니다. 갇힌 내부 구멍은 외부로 인정하지 않습니다.
- 반대쪽은 높이가 맞는 방 내부 통행 셀이어야 합니다. 계단 측면으로 연결할 수 없습니다.
- 연결문과 모든 통행 셀은 높이·계단·다리 방향을 고려해 연결되어야 합니다. 내보내기에는 연결문이 최소 하나 필요합니다.
- 폭은 0.25~40m 범위에서 맵에 들어가는 크기까지, 통과 높이는 0.25~20m입니다. 폭이 셀 간격을 넘으면 북/남 방향은 오른쪽, 동/서 방향은 아래쪽의 여러 셀을 개방합니다. 잠금·다른 문·지형·천장 높이와 충돌하면 변경하지 않습니다.
- 여러 셀의 문은 프리팹 하나만 내보내며 원본 전체 메시의 가로 경계를 문 폭에 맞춥니다. 프리팹 내부 통과 구멍이나 충돌체의 실제 여유 폭은 Unity에서 확인하세요. 기존 1셀 문은 기존 배율을 유지합니다.
- 연결점은 문 프리팹의 오프셋·추가 회전과 독립적으로 유지합니다.

**두 맵 연결 확인**에서 다른 .baekho.json과 각 연결문을 고르면 비교 맵을 회전·이동해 맞춥니다. 종류·폭·높이와 대략적인 구조 겹침을 확인하며 원본 맵은 변경하지 않습니다. 실제 메시 충돌과 런타임 방 조립은 Unity에서 처리합니다.

## Unity에 가져오기

1. ZIP을 풀고 **네 스크립트를 모두** 원본 에셋이 있는 Unity 프로젝트에 복사합니다.
   - Unity/Editor/BaekhoMapImporter.cs → Assets/Baekho/Editor/BaekhoMapImporter.cs
   - Unity/Runtime/BaekhoMapConnection.cs → Assets/Baekho/Runtime/BaekhoMapConnection.cs
   - Unity/Runtime/BaekhoGameplayMarker.cs → Assets/Baekho/Runtime/BaekhoGameplayMarker.cs
   - Unity/Runtime/BaekhoMapFixture.cs → Assets/Baekho/Runtime/BaekhoMapFixture.cs
2. 기존 설치가 있으면 같은 위치의 파일을 업데이트합니다. 중복 설치하지 말고 Runtime 스크립트를 Editor 폴더 밖에 둡니다. **Window → Package Manager → Unity Registry**에서 **AI Navigation** (`com.unity.ai.navigation`)을 설치합니다.
3. Map.baekhomap.json을 Assets 아래로 복사하고 컴파일 완료 후 선택합니다.
4. **Assets → Baekho → Build Prefab**을 실행합니다. 맵 루트에 `NavMeshSurface`를 추가하고 자동 베이크한 뒤 JSON 옆에 맵 프리팹과 `.NavMesh.asset`을 함께 저장합니다.

기존 파일을 덮어쓰지 않고 새 이름으로 저장하며 현재 씬은 변경하지 않습니다. 원본 프리팹 GUID와 중첩 참조를 유지합니다. ZIP에는 원본 에셋을 넣지 않습니다. 원본 파일과 .meta를 유지하세요.

자동 베이크는 프로젝트의 첫 Agent Type과 생성된 맵 자식의 Render Meshes를 사용합니다. 캐릭터의 Agent Type을 맞추고 생성된 `.NavMesh.asset`을 함께 보관하세요. 원본 조각의 Surface는 생성된 인스턴스에서만 비활성화합니다. 루트 스케일은 1을 유지하며, 여러 방 사이의 NavMesh 연결은 별도로 구성합니다. 패키지가 없으면 설치 안내 후 중단합니다.

연결문은 BaekhoMapConnection, 게임 지점은 BaekhoGameplayMarker, 추가 배치물은 BaekhoMapFixture 컴포넌트로 종류·ID·연결 정보를 제공합니다. 게임 로직을 자동 추가하지 않습니다. 다른 PC에서 프로젝트를 열면 그 PC의 Unity 프로젝트를 다시 연결해야 내보낼 수 있습니다.

이전 맵도 새 앱에서 열어 다시 내보내면 새 가져오기 규격을 사용할 수 있습니다. 상세 내용은 [Unity 가져오기 안내](unity-importer/README.md)를 참고하세요.

## 맵 규격과 호환성

| 항목 | 규격 |
| --- | --- |
| 격자 | 가로·세로 8~40셀, 셀 간격 0.25~10m |
| 좌표 | 중앙 원점, X 좌우 / Y 높이 / Z 앞뒤. 첫 행은 +Z |
| 높이 | 셀 바닥 −100~100m, 계단·경사로 오름폭 0.25~10m |
| 타일 | _ 빈 공간, . 바닥, # 벽, D 문, P 장애 소품, R 계단/경사로, B 다리 |
| 천장·벽 | 천장 아랫면 Y −200~200m, 벽 높이 0.25~300m. 자동 생성 입력은 0.25~20m |
| 에셋 | 최대 256개. 셀별·배치물별 지정, 소품 종류·테마·크기·방 용도·가중치 지원 |
| 자동 에셋 선택 | 기존 타일·시설은 역할별 순환을 유지. 새 소품은 조건과 점유 영역을 검사한 뒤 시드 기반 가중 선택하고 프리팹 ID 고정 |
| 파일 형식 | 새 기능은 프로젝트 map.version 5, Unity 내보내기 schemaVersion 5. 기존 v4도 지원 |

**3D 미리보기는 구조 확인용 블록아웃**입니다. 실제 메시·머티리얼·광원·콜라이더·프리팹 배율은 Unity 결과에서 확인하세요. 이동 검사는 격자 단차와 연결 방향을 기준으로 하며 캐릭터의 실제 충돌, NavMesh, 적 AI를 시뮬레이션하지 않습니다. 추가 구조물의 충돌체도 원본 프리팹을 사용합니다.

이전 map.version 1/2/3은 읽을 때 4로 옮기며 v4 파일도 계속 지원합니다. 원래 높이·배율·에셋 지정은 보존하고 새 천장·배치물을 임의로 추가하지 않습니다. 기존 천장을 자동으로 따라가게 하려면 **최고 바닥 기준으로 맞추기**를 적용합니다. 옛 S/E는 바닥으로 전환하므로 외부 연결문을 직접 지정해야 합니다. Unity 가져오기는 schemaVersion 1~5를 지원합니다.

```powershell
npm run test:variants
npm run test:unity

npm run test:packaged
npm run test:portable
```

- 0.5.1 검증: 단위 테스트 230개, 신규 Electron 구조·소품 검사 87개, 기존 v5 UI 검사 27개와 편집기 회귀 검사를 통과했습니다. 바닥 접합과 치우친 계단 피벗은 실제 Unity에서 검증했습니다. 배포 패키지와 실제 portable EXE의 실행·리소스·Codex 연결 검사도 통과했습니다.
- 단위 테스트: 지형·생성 조건·천장 높이·다리 연결·절벽·배치물·영역 변환·잠금 보존·마이그레이션·Codex 통신·취소·GUID·ZIP을 검사합니다.
- Electron 테스트: 후보 일괄 생성·선택 저장·중복·취소·원본 보존과 실제 UI의 편집·복사·잠금·템플릿·저장·열기·복구·비교·내보내기를 검사합니다. 생성 통합 테스트는 모의 응답으로 성공·실패·재시도·취소를 검증하며 유료 AI 요청을 보내지 않습니다.
- Unity 테스트: 설치된 Unity Editor로 저장소의 격리된 .local/unity-validation 프로젝트에서 실제 프리팹을 만듭니다. UNITY_EDITOR로 실행 파일을 지정할 수 있습니다. Unity 6000.3.10f1에서 가져오기 회귀 검사 255개, 기존 v4 앱 ZIP 검증 1,679개, v5 앱 ZIP의 292개 배치에 대한 1,739개 검사를 통과했습니다. 치우친 계단·소품 피벗, Trigger 영역 정렬과 실제 바닥 아랫면 접합을 확인합니다.
- 자동 NavMesh: `npm run test:unity:navmesh`는 격리된 검증 프로젝트에 AI Navigation을 설치하고 베이크·데이터 저장·실제 경로 탐색·현재 씬 보존·저장 실패 정리를 검사합니다. Unity 6000.3.10f1 / AI Navigation 2.0.16에서 30개 검사와 에디터 재시작 후 프리팹 이동·회전 및 데이터 재사용 검사 10개를 통과했습니다. 패키지가 없는 상태의 안내와 명시적 베이크 생략도 확인했습니다. `npm run test:unity`는 이 검사를 먼저 실행한 뒤 기존 가져오기와 앱 ZIP 검사를 이어갑니다.
- 배포 테스트: 패키지와 실제 portable EXE를 실행해 UI·리소스·Codex 연결을 확인합니다. 로그인된 Codex가 필요하며 AI 생성을 요청하지 않습니다.

2026-10-14에는 소형 전투방과 상점방을 실제 Codex 이미지 생성→배치 추출→로컬 콘텐츠 배치로 검증해 두 사례 모두 첫 요청에서 통과했습니다. 일반 단위·Electron 테스트는 실제 AI를 호출하지 않습니다. `npx tsx scripts/smoke-level-design-ai.ts`로 별도 실행할 수 있으며 요청과 측정값, 실제 게임에서 남은 확인 항목은 [실제 AI 생성 검증](docs/level-design-validation.md)에 기록했습니다. AI 지형 품질은 모델 응답에 따라 달라지며 생성 조건과 이동 검사 실패 시 원본을 유지합니다.

연동은 로컬 Codex App Server의 표준 입출력 JSON-RPC를 사용합니다. 인증 파일은 Codex가 관리하며 맵 프로젝트나 EXE에 넣지 않습니다. Unity 원본 에셋도 AI 요청에 보내지 않습니다. 참고: [Codex CLI](https://developers.openai.com/codex/cli), [Codex App Server](https://developers.openai.com/codex/app-server).
